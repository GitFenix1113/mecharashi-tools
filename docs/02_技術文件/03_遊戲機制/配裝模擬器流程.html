單頁槽位模型、合法性規則、級聯與重量帳（PLAN-052-B 改版後）

v2 — 8 步驟精靈已下線
互動模型
為什麼不再是 Step 1–8
🔄 v2 改版：整檔取代 8 步驟精靈 舊版把配裝拆成 8 個步驟，玩家必須走完 8 步才看得到結果——但配裝是「反覆試」的動作， 每試一次走 8 步，沒有人會用第二次。而且步驟列可無條件跳關，空手直跳 result 會渲染一頁「未選擇」。
v2 的模型只有一句話：一眼看到全部槽位 → 點槽位換裝備 → 即時看重量／出力。 前置關係（機師 → 機甲 → 裝備）不再靠步驟強制，改由分階段載入與 級聯校驗表達：沒選機師時情境欄自動停在機師挑選器，選完自動往下一步。
機師HUD 的機師卡 → 情境欄開機師挑選器。決定執照與（若有）獨立配裝分頁數。
機甲HUD 的機甲卡 → 機甲挑選器。依執照過濾（一對一：重型執照只開得到重型機甲），被擋下的摺疊成「因執照不符隱藏 N」。
武器點槽位圖上任一格 → 該格的武器挑選器（只列 equipSlot 相符者）。
背包背槽或「選擇背包」鈕。背包與背部武器共用同一格，兩邊的挑選器互相有 [改選…] 切換鍵。
元件／改裝／科研本版不渲染（見下方「明確不做的事」）。
合法性規則
單一入口 src/utils/loadoutRules.ts
⚡ 為什麼要單一入口 舊版把「什麼裝得上」拆散在三個 useCallback 裡，於是同時存在三個各自寫錯的判斷。 v2 一律走 canEquipWeapon() / canEquipBackpack() / validateLoadout()， 重量帳一律走 loadoutBudget()。
檢查點規則錯誤碼／tier
機甲選擇licenseAllows(pilot.license, mech.armorType)。執照與裝甲一對一（不是階梯式包含，2026-08-25 修正）。禁止寫 license === '中甲'——執照是輕型／中型／重型，裝甲是輕型／中甲／重型。LICENSE · structural
槽位存在mechSlotCapacity()：單手 ×2、背 ×1；肩 ×2 僅中甲；備用 ×2 由 type === 'BackupEquipment' 的背包給（全庫僅強襲者背包一筆）。NO_SLOT · omitted
槽位相符weapon.equipSlot === ref.slot。雙手武器佔兩格單手，不是第三格。SLOT_MISMATCH · omitted
固定武裝機甲部件的 fixedArmament 佔住的格不可更換；固定武裝本身不是可選裝備。SLOT_OCCUPIED / FIXED_ARMAMENT
形態全鎖form.restrict.kind === 'fixedArmament' 鎖死整套（虛粒子／巡航），不只被 mounts 佔住的那幾格。FORM_LOCKED · blocked
機種限定weapon.mechRestriction。絕不可用 type === '戰術' 代替——實測 medium 49 筆 vs 戰術 44 筆，差 5 筆。MECH_RESTRICTION · structural
形態武器類型form.restrict.allow 白名單（「特殊」不參與過濾）。FORM_WEAPON_TYPE · structural
背包機種backpack.assemblableArmorType 正向邏輯，[] ＝ 無限制。值是英文（Light／Medium／Heavy），必須走 fromAssemblableArmorType()；餵給 toArmorType() 會全部回 null、等於完全不過濾。BACKPACK_ARMOR_TYPE · structural
背槽擇一背包 XOR 背部武器（SlotCapacity.back = 1）。181/181 個背包 slot='back'。BACK_SLOT_TAKEN · situational
負重totalWeight() <= effectiveOutput()，判定的是裝上之後的總重。不阻擋，只提示 ＋ 提供解法。OVERWEIGHT · situational
🎚️ 四個呈現層級（tier） structural 摺疊 ＋ 計數 ＋ [顯示並說明原因]； situational 灰掉 ＋ 原因 ＋ 解法按鈕（型別層強制附上）； omitted 不列入清單； blocked 整個挑選器降級並說明。 新增拒絕原因時 tsc 會逼你選邊並填中文說明。
級聯
單一 reconcile()
🔗 為什麼集中在一支函式 「選完機師才知道要篩選什麼機甲、選完機甲才知道哪個槽被限制住」——每一個動作都可能讓別的地方失效。 散在各 handler 會變成 N×N 條「換 A 時記得檢查 B」，而漏掉的那一條是靜默的。 v2 的規則只有一條：任何動作之後都跑同一支 reconcile()， 動作本身只做結構性的放置／移除，合法性事後統一掃。掃描順序由外而內：機師執照 → 機甲 → 分頁鍵 → 背包 → 各槽武器。
動作處置回饋
換機師（同執照）機甲保留，mounts 逐槽驗證toast 列出被移除項 ＋ [復原]，該格閃橙
換機師（執照容不下）機甲移除 → 連帶 mounts 與背包自動回到機甲挑選
換機甲（中甲 → 輕／重）肩槽整列消失 → 肩部武器移除；medium 限定武器移除toast「移除 2 項：…」
換機甲（有固定武裝）對應槽變 🔒 佔據態，原本裝的移除「右肩已由固定武裝佔用」
換背包（強襲者 → 一般）備用槽消失 → 兩格武器移除toast 兩段：移除項 ＋ 出力變化
裝背部武器背包自動卸下（背槽擇一）toast 提供 [復原]
裝雙手武器同 bank 的左右手都被取代挑選器列上先印「裝上將取代 …」，不灰掉不阻擋
超重不自動卸、不阻擋條轉紅 ＋「超出 N」＋ [自動卸至符合]（須玩家主動按）
↩️ 復原 每次級聯移除推一筆 undo（只留最近 1 筆），toast 上的 [復原] 還原整批。 第二層保險是把整份草稿寫進 localStorage mecharashi_loadout_draft。
數值
重量與出力的口徑
總重機體 ＋ max(Σ主手, Σ備用) ＋ Σ肩 ＋ 背。手部是取較重組，不是相加——備用組不與主手同時上場。寫成加總，海莉絲先鋒形態會算出 2625（官方 1825），誤差 44%，而且是往「裝不下」的方向錯。
機甲固定武裝與形態固定武裝計入（虛粒子 1125 ＝ 825 ＋ 耀星 100 ＋ 隕星 100 ＋ 千星 100）。
可用出力parts.torso.output ＋ 背包加成 ＋ Σ 模組。只有軀幹有出力。背包加成僅四筆已由官方畫面確認；另 15 筆「已知會給出力但數值未建檔」由 hasUnknownBackpackBonus 標成未知，不猜。
順序無關先選背包或先選武器，剩餘出力必須相同——所有挑選器問同一支 loadoutBudget()。舊版選背包時扣武器重、選武器時不扣背包重，跳著選會得到兩份清單。
機甲火力Σ 四部位（chassisFirepower()）。全站禁止讀 mech.firepower：83/90 台的頂層值是單一部位值。
攻擊力DB 值是「全部連擊的總和」，官方顯示的是「每擊值」，且官方值比 DB 高 17.3–18.6% 且逐把不同。→ 顯示 DB 原值並標「本站口徑，含連擊」，不做 ÷hitCount 的官方同格式渲染。差額屬傷害計算範疇。
等級一律滿級／滿品質階。不開武器等級欄位、不給機甲品質階選擇。
數值未建檔mech_090_美杜莎MK2 全欄位為 0，是刻意的佔位（新機甲先建檔再補數值）。挑選器降級並說明「官方數值尚未公布」，不是渲染一台什麼都裝不下的機甲。
