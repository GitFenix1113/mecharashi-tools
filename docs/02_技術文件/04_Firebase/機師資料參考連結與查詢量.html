02 — Reference Graph
機師文件的三種參考連結
機師文件本身只存「指標」，真正的資料在被引用的集合裡。三種連結機制如下圖。
skills[]：文件 ID（PLAN-004） buffIds[]：賦予的 BUFF descriptionRefs [xxx]：型別化引用 反向引用
重點：機師文件存的是指標（ID / refType+refId / buffId），不是資料副本。一個技能（如職業被動「協同作戰1」）由 28 位機師共用同一份 pilotSkills 文件 —— 改一次、全站生效。這正是 PLAN-004「單一資料源」的核心。
03 — refType 對照
descriptionRefs 的 refType → 集合對照
描述文字中的 [xxx] 透過 descriptionRefs["xxx"] = { refType, refId } 解析。每種 refType 對應一個集合（或本地資料）。
refType解析來源查詢成本

🔀 同名消歧鍵（PLAN-039）
map 的 key 就是括號內文字，故同一段正文裡兩個 [駐陣] 必然指向同一筆引用。 需要各指各的時（實例：「可使用指令[駐陣]」＝技能、 「若處於[駐陣]狀態」＝BUFF），在其中一處的括號內加上 消歧後綴：
正文　　可使用指令[駐陣|skill]…若處於[駐陣]狀態
key　　 descriptionRefs["駐陣|skill"] = { refType: 'skill', … }
　　　　descriptionRefs["駐陣"]     = { refType: 'buff',  … }
前台顯示不受影響——RefChip 一律剝除後綴，兩處都顯示 [駐陣]（src/utils/refKey.ts 的 displayKeyword 為唯一解析點）。
不加後綴 = 沿用同一筆引用，是絕大多數情況的正確狀態；舊資料無需任何遷移。
分隔符固定為 |，不可用 #： # 是 maxTriggers 的數值語法糖 sigil， [駐陣#2] 會被 detectLeftoverSugar 誤判、 被 compileSugar 替換成 <refId.maxTriggers>，正文當場改壞。
04 — Loading & Cache
三層快取：為什麼引用不會讓查詢量暴增
所有 useX() hook 與引用浮窗都走同一條 GameDataContext.ensureLoaded(keys)。一個集合在「一個 session」最多只抓一次，且跨 session 由 localStorage 版本快取攤平。
0
同 session 去重（PLAN-016，記憶體）
fetchedRef 記錄已抓過的集合。同一集合在本次造訪只會發一次請求；重複呼叫（切換機師、開多個引用）直接命中記憶體 = 0 讀取。
1
跨 session 版本快取（PLAN-017，localStorage，每集合各一版本號）
每 session 先讀 meta/gameData 的 versions 對照表（1 次讀取）。各集合的有效版本 = versions[集合] ?? version（未被單獨編輯過的集合沿用全域 fallback）。各集合以 {version, data} 存在 localStorage：版本相符 → 直接用快取 = 0 Firestore 讀取；版本不符或無快取 → 進入第 2 層。
2
實際讀取（Firestore）
fetchCollection = getDocs(collection)，一次取回整個集合 = N 筆文件讀取（N = 該集合文件數），讀完寫回 localStorage 快取。Admin 寫入時 bumpDataVersion('集合') 只改該集合版本 → 僅該集合在所有人的快取於下次造訪失效（其餘集合快取存活）。編輯者自己的瀏覽器另以 GameDataContext.patchCollectionItem 就地同步該筆，免重讀。
✅ 萬人瀏覽 ≠ 萬次查詢。每個瀏覽器各自快取；只要版本沒變，回訪只花 1 次讀取（版本文件）。引用詞條再多，也只是「首次開啟某類型時把該集合載入一次」，之後全是記憶體 / localStorage 命中。

06 — Takeaways
結論與優化槓桿
⚠ 誠實揭露：PLAN-004 讓機師頁冷啟動多了 ~512 筆讀取。技能原本嵌在 pilots（已含在 82 筆內），抽離後變成獨立的 pilotSkills(512)。冷啟動由 ~251 → ~763 筆。換得的是：單一資料源、共用技能集中維護、技能可被引用顯示。此成本經三層快取在跨 session 攤平（暖快取回訪僅 1 筆）。
📌 可選優化槓桿（未實作）
· 延後載入 pilotSkills：目前機師頁一掛載就載入；可改為「技能分頁開啟」或「技能引用首次懸停」才載入 → 只看天賦/數值的訪客省下 512 筆。
· 建置期匯出 CDN 靜態 JSON：規模再大時，把參考集合於 build 階段輸出為靜態 JSON，前台 fetch CDN，Firestore 讀取趨近 0。
· 分頁 / 條件查詢：後台已採 getCollectionPage 伺服器端分頁（PLAN：後台分頁查詢），不整包載入。
