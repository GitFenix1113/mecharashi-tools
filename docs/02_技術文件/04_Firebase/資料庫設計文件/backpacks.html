02 — Notes
設計說明
💡 assemblableArmorType 陣列設計 assemblableArmorType 為 string[]（正向邏輯），指定「哪些機甲可以裝備此背包」。 空陣列 [] = 無限制，所有機甲皆可裝備。 允許多值（如 ["Light", "Medium"]），腳本從 API AssemblableAirmenType（斜線分隔）解析。 mechRestriction（舊負向邏輯）已完全移除。
💡 mainSkill 的數值欄位 API 回傳的 SpecificEffects 為 rich text 格式，包含標籤與數值描述。 dmg / crit / critDmg / acc 等數值需管理員從描述中手動解析後填入，供傷害計算器直接使用。
💡 craft.prereqBackpackId — 製作前置（PLAN-036） 背包製作為「低一階前置」關係：SS ← S+（無法由名字反推，後台 BackpackAdmin 手動選擇）、S+ ← S（可由名字乾淨反推，一次性腳本 fill-backpack-craft.mjs 填入，實測 98/98 命中）。 僅存前置這一個 id；種類、圖紙名（name + '設計圖'）、能力軸皆由此 id 查表 derive、不落庫。 存檔走 updateBackpack（自動 bumpDataVersion('backpacks')）；無前置階（S/A/B）不寫 craft，前台未關聯時優雅降級。
💡 分類與能力軸不落庫（PLAN-035 / PLAN-037） 合成階層（素材/基礎/複合/特種 ＝ rarity 粗化）、強化/干擾軸與變體（從 name 字串解析）、能力循前置鏈（backpackAbility 沿 craft 鏈遞迴取祖先能力）皆為前端純函式 derive（src/utils/backpackClassify.ts），零 Firestore 欄位，由 scripts/audit-backpack-classify.mjs 對 live 全 180 名字驗證 unresolved=0 佐證。
