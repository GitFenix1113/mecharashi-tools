01 — Design Principles
設計原則與架構說明
從靜態 JSON 檔案遷移至 Firebase Firestore，集中管理所有遊戲資料，解決複雜關聯性與維護困難的問題。
🔗

關聯管理

模組 ↔ 機甲、技能 ↔ 機師、BUFF ↔ 技能等跨實體關聯，透過 Firestore Document ID 引用，取代 JSON 中的字串 ID 難以驗證的問題。

📐

型別枚舉化

模組槽位、職業、裝甲類型、稀有度等分類欄位，統一定義為 TypeScript Enum，前端與後端共用同一份定義，避免拼寫錯誤與不一致。

🛡️

安全規則分層

遊戲資料 Collections：所有人可讀、僅管理員可寫。用戶 Collection：僅本人可讀寫。Firebase Security Rules 強制執行。

⚡

查詢優化

針對常用篩選場景（依職業篩機師、依槽位篩模組、依機甲篩副模組）預設複合索引，確保大資料量下的查詢效能。

🔄

可擴充設計

BUFF Collection 初始僅含名稱與描述，欄位設計為可向後兼容擴充。技能 Collection 預留 tags、relatedEntities 等泛化欄位。

📋

Admin 管理介面

遊戲資料改由網站管理後台（AdminPage）直接讀寫 Firestore，取代 Google Sheets + GitHub Actions 的間接流程。

型別枚舉定義

PilotClass · ItemRarity · WeaponRarity · ModuleSlot · BackpackType · ConditionType · EffectType 等全部 Enum 定義與 TypeScript 範例

pilots — 機師

機師六維能力 · AP · 天賦 / 技能 / 神經驅動（SkillEntry 嵌入結構）
🤖

mechs — 機甲

部件詳細結構（torso / leftArm / rightArm / legs）· 火力 / 裝甲 / 出力 · 模組引用
🔩

modules — 模組

4模 / 8模 / 通用 / 副模組 · 各等級效果數值（levels[]）· 綁定機甲關聯
🔫

weapons — 武器

武器基礎數值 · 技能（SkillActivation）· 固定 / 浮動改裝方案 · 元件插槽
🎒

backpacks — 背包

背包種類 · 機甲限制（AssemblableArmorType）· 掛載技能 skillIds · 製作前置 craft — PLAN-009 / 036 / 043
✦

backpackSkills — 背包技能庫

背包技能單一資料源 · 可等級化 levels[] · 由 backpacks.skillIds 以 id@N 引用 — PLAN-043
🔀

forms — 機師形態

調構師的形態實體 · 裝備限制 union（類型白名單／武器焊死）· 形態增益連結 · refType:'form' — PLAN-041
⚙️

components — 元件

觸元件（trigger）· 應元件（effect）· 觸發條件（ConditionType）· 效果類型（EffectType）
✨

skills & buffs — 技能與 BUFF

共用技能庫 · BUFF 定義（初始版本，預留 effects[] 擴充欄位）· buffIds[] 跨實體引用
🔬

research — 科研

pilotResearch（機師個別科研選項）· globalResearch（全域加成定義）
🔐

users — 用戶資料

users/{uid}/profile（設定 / 科研選擇）· users/{uid}/builds（配裝紀錄）· 僅本人可讀寫
📜

changeHistory — 變更歷史

後台資料異動稽核 log · append-only（連管理員都改不了）· 刪除快照可還原 · 原生 TTL 兩年
🩺

systemLog — 系統日誌

維護者非預期登出的診斷證據 · 三態哨兵判成因 · 讀取限 OWNER（全站唯一 read 比 write 嚴格）· 原生 TTL 90 天
📰

announcementDrafts / pendingActivities — 公告 staging

台版官方公告抓取與審核暫存（PLAN-048 Phase 2）· 審核最小單位是「一個活動」· 後台專用 · 原生 TTL 六個月
📊

analyticsDaily / analyticsEntity — 使用統計

匿名彙總計數 · 預聚合（看 30 天＝30 reads）· 全站唯一 write: if false（只有 Worker 寫得進）· 不含可識別個人的資料
🛡️

安全規則 · 索引 · 遷移

Firestore Security Rules · 全部複合索引（firestore.indexes.json）· JSON → Firestore 遷移 9 步驟
03 — Collections Overview
Firestore Collections 清單
共 14 個 Collections，分為「遊戲資料」（管理員維護）、「用戶資料」（用戶私有）與「稽核 log」（後台專用、append-only）三類。
pilots
GAME DATA

機師完整資料（六維、技能、天賦、神經驅動、AP）

mechs
GAME DATA

機甲完整資料（部件、火力、出力、模組引用）

modules
GAME DATA

所有模組（4模/8模/通用/副模組，含各等級效果）

weapons
GAME DATA

武器資料（技能、改裝、元件插槽）

backpacks
GAME DATA

背包裝備（機甲類型限制、掛載技能、製作前置）

backpackSkills
GAME DATA

背包技能庫（可等級化，被 backpacks.skillIds 引用）

forms
GAME DATA

機師形態（調構師專屬；裝備限制、形態增益連結）

components
GAME DATA

觸元件 + 應元件（等級、觸發條件、效果）

skills
GAME DATA

技能庫（可跨實體引用的共用技能定義）

buffs
GAME DATA · NEW

BUFF 定義（初始：名稱 + 描述，後續擴充效果欄位）

pilotResearch
GAME DATA

各機師個別科研選項（三種特質 × I/II/III 欄位）

globalResearch
GAME DATA

全域科研定義（機師/機甲/武器 三大類加成）

enemies
GAME DATA

敵方機師+機甲（傷害模擬器用）

users/{uid}/profile
USER DATA

用戶設定（全域科研等級、機師科研選擇、角色：USER / ADMIN / OWNER）

users/{uid}/builds/{id}
USER DATA

用戶配裝紀錄（機師+機甲+武器+背包+模組+元件）

changeHistory
ADMIN LOG

後台資料異動稽核 log（PLAN-030）。append-only：可新增可讀取，但連管理員都改不了刪不掉。不進前台快取層

systemLog
OWNER LOG

維護者非預期登出／寫入被拒的診斷記錄（PLAN-045）。append-only，且讀取限 OWNER（含裝置指紋，ADMIN 不可互看）。不進前台快取層

announcementDrafts / pendingActivities
ADMIN STAGING

台版官方公告的抓取與審核暫存（PLAN-048 Phase 2）。審核最小單位是「一個活動」；必須是獨立集合——做成 PatchVersion.inbox 欄位會被整份 setDoc 無聲洗掉。不進前台快取層

analyticsDaily / analyticsEntity
ANALYTICS

匿名使用統計的預聚合計數（PLAN-046）。全站唯一 write: if false——唯一寫入者是 Cloudflare Worker（service account 繞過規則）。不進前台快取層
