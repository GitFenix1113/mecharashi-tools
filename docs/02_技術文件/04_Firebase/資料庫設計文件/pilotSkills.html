01 — 用途
pilotSkills Collection
📌 用途說明
PLAN-004 技能庫抽離前，技能以嵌入方式存於每個 pilots 文件的 skills[]（同名共用技能各存一份副本）。
抽離後，技能本體集中存於 pilotSkills 集合（單一資料源），Pilot.skills 改為此集合的文件 ID 陣列。
· 共用技能（如職業被動「協同作戰1」）多位機師指向同一文件 → 編輯一次全站生效。
· 技能可被任意描述中的 [xxx] 引用（PLAN-019 refType:'skill'）→ 懸停／點擊顯示 icon、類型與效果。
· 前台讀取走 GameDataContext 一次預載 + PLAN-017 版本快取（回訪 0 讀取）。
⚠ 集合名是誤稱：這是「技能庫」，不是「機師的技能」（PLAN-032 正名）
本集合的真實契約是 「全站技能字典」——收錄所有可被引用的技能定義，成員不限於機師持有。 實測：全庫 89 個 refType:'skill' 引用目標中，75 個（84%）沒有任何機師持有； 集合內另有 83 筆無機師持有的孤兒 doc，其中 SKILL_故障植入、SKILL_態勢優化 根本就是武器技能（維護者早已自行放入）。
PLAN-032 據此裁決不另開 weaponSkills 集合，武器技能直接併入本集合， 以 domain 欄位分類。集合實體改名（pilotSkills → skills） 要做 rename migration 並同步所有 refId，純美觀不值得——故只在文件上正名。

domain'pilot' | 'weapon' ?PLAN-032：技能所屬領域。未填 = 'pilot'（既有 646 筆天然合法，零改動）。
純分類欄位，只影響後台技能庫頁的篩選，不影響解析／引用／任何前台行為。刻意不用 type 表達：實測 170/170 武器技能的 type 全是「被動技能」，零鑑別力。

⚠ 這兩欄刻意放定義側而非武器的掛載側：本欄與上方 descriptionRefs 是一起被消費的（PilotDetailPage 用同一份 refs 解析這段文字的 [xxx]），拆兩份文件會失同步，症狀是「強化後天賦文字裡的引用突然不會亮」。且專武與機師 1:1，天然無跨武器變異——與 activation 的情況正好相反（後者留在掛載側）。
variantsSkillVariant[]?模擬層預留：條件變體（如萬序擬合依形態/武器發動不同子技能）。暫不填
areaSkillArea?模擬層預留：作用範圍/形狀（如龍雷拳 面前3×4格）。暫不填
02 — 維護與遷移
資料維護
🛠️ 後台編輯
機師後台「技能效果」分頁編輯的是 pilotSkills 文件本體（共用技能編輯會同步影響所有持有它的機師）。手動新增技能會建立新文件並把其 ID 附加到該機師的 skills。
🔁 遷移腳本
· scripts/migrate-plan004-skills.mjs（Stage 1）：攤平 pilots.skills、name+description 去重 → 寫入 pilotSkills。
· scripts/migrate-plan004-pilots.mjs（Stage 2）：把 pilots.skills flip 成 ID 陣列。
· scripts/seed-manual-skills.mjs：補爬蟲無法擷取的 form-gated 條件技能（如粒子爆發）。
· scripts/migrate-weapon-skills.mjs（PLAN-032 Stage 1，已進版控）：把 86 把武器內的 183 份內嵌技能以技能名去重，建成 133 筆 domain:'weapon' 的共用文件。去重鍵絕不可用 icon——實測 107 個 icon 中 11 個對到 2–3 個不同技能名（Icon_skill_passive_5136 → 擴容火力／追蹤調律／扞拒），icon 是共用美術素材不是技能 ID。
· scripts/scrape-weapons.js 的 normalizeWeaponSkills()：改版抓到新武器時，以技能名查本集合——有則掛引用、無則建 doc 再掛。⚠ 只保證「新技能會被建 doc」，不保證「既有技能的效果變更會被補丁」（引用化的固有代價，同機師端）；官方文本與本集合不一致時腳本會列清單要求人工核對，不自動覆寫。
· 安全規則：pilotSkills 所有人可讀、管理員可寫（見 security-rules）。
