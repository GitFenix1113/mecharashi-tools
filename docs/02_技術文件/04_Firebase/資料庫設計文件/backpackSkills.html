背包技能單一資料源 · 可等級化（levels[]）· 由 backpacks.skillIds 引用

PLAN-043 — 2026-08-05
01 — 用途
backpackSkills Collection
📌 用途說明
背包技能的單一資料源。背包以 backpacks.skillIds[] 引用本集合，元素可帶 @N 指定等級 （如 bpskill_移動強化@1 ＝ 遊戲內的「移動強化Ⅰ」）。編輯技能會同步影響所有掛載它的背包。
❓ 為什麼不併進 pilotSkills
這與 PLAN-032（武器技能併入 pilotSkills）的裁決相反，且是刻意的：
  • 維護者裁定——背包技能要獨立管理，不與其他實體混在同一份清單。
  • 欄位形狀確實不同：PilotSkillDoc 帶 type／unitType／ap／cd／pp／weapon／variants， 背包技能一個都用不到（遊戲內顯示為「消耗 —／武器 —」）；反過來背包技能需要 levels[]，那是 PilotSkillDoc 沒有的。
  • ID 命名空間獨立：pilotSkills 現存 SKILL_ 大寫 134 筆／skill_ 小寫 512 筆， 後台撞號防呆只查小寫形式。獨立集合的 bpskill_ 前綴直接繞開這個仍未修的洞。
代價（GameDataContext 10 處掛接、RefType／ChangeTargetKind 各一組、複製一份 Admin 分頁） 已於計畫書列成明細並接受。
02 — Schema
backpackSkills Collection 欄位定義
文件 ID 格式：bpskill_<技能名>；同名不同效時加背包 id 後綴。
欄位型別說明
idstring文件 ID（bpskill_移動強化）
namestring技能名稱（族名，不含羅馬階數；階名放在 levels[].name）
skillTypestring技能類型（enums.ts 的 SkillType 字串）。實務上幾乎全為 '被動技能'，但保留欄位——遊戲內技能卡本身標有類型，不該由前端硬編
descriptionstring效果說明。階梯技能時作為各級未填時的回退父層
descriptionRefsDescriptionRefs?描述內 [xxx] 引用側錄（PLAN-019）。可引用 BUFF／詞條／機師技能
iconstring?圖示路徑。慣例存 /images/skills/背包技能/<檔名>（PLAN-043 獨立圖庫資料夾）
effectsSkillEffect[]結構化效果數值（管理員手填），供模擬器計算
buffIdsstring[]賦予的 BUFF → 引用 buffs collection。元素可含 @N
officialIdstring?官方 API 的數字技能 ID（如 62304），由 PLAN-043 遷移自 Backpack.mainSkill.id。純備查、無任何程式讀取——保留的理由是它是回連官方資料的唯一線索，而 Phase E 的 flip 會把 mainSkill 永久刪掉。新建技能不必填
▎levels — 階梯等級（選填；比照 PLAN-024 的 BuffLevel）
 ├ levelnumber等級序號 1,2,3…（對應原羅馬尾碼）
 ├ namestring?該級顯示名（移動強化Ⅱ）。必須手填，刻意不做羅馬數字自動推導——PLAN-024 實測既有資料已知損壞（失穩ⅠⅠⅠ 是三個重複的 U+2160），推導在髒資料上必然失敗。遊戲內無階名的技能族填與 name 相同的原字（明示的編輯決策，而非留空漏填）
 ├ descriptionstring?該級描述；未填時前台回退父層
 ├ descriptionRefsDescriptionRefs?該級專屬引用側錄；未填時回退父層
 ├ effectsSkillEffect[]?該級數值；未填時回退父層
 ├ buffIdsstring[]?該級賦予的 BUFF；未填時回退父層
 └ iconstring?該級專屬圖示；未填時沿用 skill.icon
03 — Notes
設計說明
💡 等級覆寫語意：逐欄位 該級 ?? 父層
解析層在 src/utils/backpackSkills.ts 的 resolveBackpackSkills()，前台／模擬器／後台三處共用。 不是「有 level 就整包換掉」——那會讓只填了階名的等級顯示成空白。 此約定必須與 entityRefs 的 refsFallback 一致，否則會出現 「掃描器認為某處有引用、前台卻顯示父層文字」的錯位。
⚠️ 模擬器只算掛載的那一級
buildBuffPool 刻意不走 runSpec(SPECS.backpackSkills, doc)： 那會把頂層與所有等級的 buffIds 全部倒進池子，讓掛 Lv1 的背包拿到 Lv2 的 buff， 而且不報錯，只是模擬結果偏高。改用解析層先做等級收斂再推。
反方向的 findReferences 則必須掃全部站點——刪 BUFF 時每一級的引用都得清掉。 兩者方向不同，這個不對稱是刻意的。
🗑️ 級聯刪除
ChangeTargetKind: 'backpackSkill'，走 PLAN-030 的兩段式級聯刪除。 唯一的引用來源是 backpacks.skillIds[]；清除時以 arrayRemove 原始元素字串（含 @N）—— 存拆解後的裸 id 會讓移除失敗且靜默無錯。 模擬器整合測試在 tests/emulator/suites/backpack-cascade.test.ts。
🛠️ 後台編輯
後台「背包技能」分頁（BackpackSkillAdmin.tsx）維護技能本體，含折疊式等級編輯區與階名軟驗證 （會逐字印出 code point，讓「ⅠⅠ」與「Ⅱ」的差別看得見）。 背包側的「背包管理」分頁只做掛載：挑選技能、選擇要掛哪一級。
🔁 遷移腳本
