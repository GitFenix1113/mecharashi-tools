01 — 用途
glossaryTerms Collection
📌 用途說明
PLAN-019 引用層把描述文字中的 [xxx] 一般化為型別化引用（EntityRef）。技能有 pilotSkills、BUFF 有 buffs、機體/武器/模組各有集合；
唯獨 固定傷害、啟動、形態增益 這類無專屬集合可放的機制關鍵字沒有歸宿。
glossaryTerms 即為這些關鍵字的單一資料源，作為 refType:'term' 引用的查詢目標。
· 任意 description 中的 [xxx] 可指向此集合（PLAN-019 refType:'term'）→ 懸停／點擊顯示說明，並可逐層 drill。
· 後台「詞條管理」分頁維護；描述欄位旁的 RefPicker 讓任何維護者把 [xxx] 標成可點引用。
· 前台讀取走 GameDataContext 一次預載 + PLAN-017 版本快取（回訪 0 讀取）。
🗃️ glossaryTerms — 詞條文件（GlossaryTerm）
欄位型別說明
idstring文件 ID。格式 term_<名稱>（與 skill_/buff_ 一致）
namestring詞條名稱（= [xxx] 內文字）
categorystring?機制分類（傷害／狀態／資源／通用…）；自由字串，供列表標籤與篩選
descriptionstring詞條解釋文字（可含 [xxx] 標記，再引用其他實體）
descriptionRefsDescriptionRefs?解釋內 [xxx] → 實體引用側錄（PLAN-019 Layer 1）
aliasesstring[]?同義詞：別名 [xxx] 對應同一詞條
iconstring?選填白色字形，選圖器寫入官方檔名 key（如 Icon_buff_4012）；由 gameIconCandidates 解析到 /images/game/icons/buff/，相容既有本機圖片路徑。以色塊底＋米白框呈現，未設圖時顯示中性小點。
iconTone'buff' | 'debuff' | 'special' | 'heal'?選填底色，沿用 BUFF 色系：buff 藍、debuff 紅、special 紫、heal 綠。未設定時維持原本粉紫 #6c45a2，不由 category 推導。選回「預設（粉紫）」會移除此欄位；既有文件無須遷移。
02 — 維護
資料維護
🛠️ 後台編輯
管理後台「詞條管理」分頁新增 / 編輯詞條文件。新增時 ID 採 term_<名稱>。詞條解釋本身也能用 RefPicker 標記內部引用。
圖示沿用 BUFF 的 GameIconField 選圖器（預設 BUFF 字形圖庫），支援選取、清除與即時預覽，底色下拉選單提供 BUFF 的四種色系及預設粉紫；TermGlyph 讓後台列表、編輯預覽及前台引用浮窗／手機詳情使用同一個 iconTone。選圖器「誰在用」與已使用篩選包含詞條。
寫入沿用 updateGlossaryTerm → saveWithHistory('glossaryTerm', term)，圖示與底色存於 glossaryTerms/{id} 的 icon、iconTone，並記錄變更歷史。清除圖示或將底色重設為預設時省略對應欄位，以整份文件寫入移除舊值；無須新增集合或遷移既有詞條。
🔗 RefPicker（引用挑選器）
通用元件 src/components/admin/RefPicker.tsx：自動 tokenize 描述中的 [xxx]，逐 token 指派 refType + 候選實體（讀 GameDataContext in-memory 陣列 + 屬性 stat），寫入 descriptionRefs，並即時 RefText 預覽。
本輪已接進「詞條管理」與機師後台「技能效果（pilotSkills）」；其餘描述面板的 RefPicker retrofit 列於 PLAN-019-E。
PLAN-039：同一段正文出現多個同名 [xxx] 時會顯示消歧提示，並可一鍵把指定一處改寫為 [駐陣|skill]（key 帶消歧後綴、前台顯示仍為 [駐陣]）。分隔符固定 |； # 會與數值語法糖 sigil 衝突，不可使用。
🔒 安全規則
glossaryTerms 的 Firestore 直接讀寫限管理員；前台讀取沿用公開資料 Worker 與 GameDataContext 快取。圖示沿用既有權限，不需修改安全規則。寫入後自動 bumpDataVersion('glossaryTerms') 只使該集合快取失效（每集合各一版本號），編輯者以 patchCollectionItem 同步本機快取。
