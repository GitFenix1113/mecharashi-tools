03 — 後台限定集合
raidDrafts／raidTerms
集合文件內容
raidDraftsraid-21（同期 ID）三個集合的待發布內容（season／stages／bosses）＋逸聞全文與原文雜湊＋待校清單（kind／原文／草稿譯文）＋異常＋與已發布的差異摘要＋解析器版本＋最近一次發布摘要（lastPublished）。一期約 200–260 KB
raidTerms種類名（unit、skill、buff、text、anecdote…）{ kind, entries: { [termHash(原文)]: { cn, tw, status, source, firstSeason?, updatedAt?, updatedBy? } } }。 鍵是原文 sha1 前 16 碼（原文可能含 . / 等欄位路徑字元）。只存人工校對或來源匯入的條目，機轉結果不落地——重新匯入不會洗掉校對（決策八）
04 — 規則、讀取與刻意不做的連動
安全規則與快取
🔒 規則：五個集合都是 read, write: if isAdmin()。前台經 Cloudflare Worker 代理三個公開集合（/api/data/raidSeasons、stages、bosses）； raidDrafts／raidTerms 不代理。LORE_EDITOR 碰不到任何一個（npm run emu:test-rules 有驗）。匯入腳本用 admin SDK，繞過規則。

💾 快取：三個公開集合走版本 gate；stages／bosses 在 NO_LOCAL_CACHE_KEYS（各約 1.3 MB、四個難度都存一次，只有點進某期才用得到）。 列表頁只載 raidSeasons，期詳情頁才載 stages＋bosses。
⚠ 不進 entityRefs SPECS、不走 saveWithHistory（理由同步寫在 src/lib/api/raids.ts 檔頭）： 文件由腳本產生、後台整批覆寫，沒有級聯要跑；進 SPECS 會讓級聯刪除與引用掃描自動連帶讀這些集合，rules 晚一步部署時全站刪除會一起 permission-denied。 說明文字用 ⟦…⟧ 記號＋文件內字典，不寫 descriptionRefs。日後若要引用站上實體，必須先補 SPECS 並部署規則。
⚠ 部署順序：firestore.rules → Worker（ARRAY_COLLECTIONS）→ 匯入 --write → 後台發布 → 網站。 新頂層路由 /raids 還要補 Cloudflare SPA fallback 白名單（CLAUDE.md §3）。三處硬性守衛由 src/lib/collectionKeys.test.ts 斷言。
