01 — 用途
factionEmblems Collection
📌 用途說明
替徽章本身做註記：這顆官方陣營徽章（Icon_logo_<4 碼>_00／_01，圖在 public/images/game/icons/camp/）叫什麼、圖上寫什麼字。
· 故事館編輯台的選圖器顯示名稱、可用名稱／字樣搜尋，並依「對應的陣營文字」把建議排在最前面。
· 故事館卷宗的徽章提示（title／aria）顯示徽章名稱；沒有名稱就退回機師的陣營文字。
· 不是「陣營 → 徽章」字典：每位機師的徽章仍由管理員逐位挑（pilotLore.factionLogos）， 本集合不會自動替任何人選。PLAN-059 決策六原本完全不做對照，2026-10-14 由 PLAN-042-F 決策四修訂成這個形狀。
· 清單以圖庫為準（images/game/icons/index.json 的 camp，37 個編號）：圖庫有、這裡沒有文件的編號＝「未命名」，照樣可選； 這裡有、圖庫沒有的文件會被忽略。
🗃️ factionEmblems — 徽章註記（FactionEmblem）
欄位型別說明
idstring文件 ID＝徽章編號 4 碼，如 0025。單色 _00／彩色 _01 兩個變體共用一份
namestring?陣營中文名稱，如「晨星同盟防衛軍」。沒填＝未命名（只有英文名也算未命名）
nameEnstring?陣營英文名稱，如 DAWNSTAR LEAGUE ARMORED FORCE（站長 2026-10-14：中英文都要留）。與 inscription 分開：圖上的字不一定就是名字（0025 多一行 DEPARTMENT OF THE DEFENCE FORCE；0039 圖上是 AP · TALOS DEFENSE FORCE、中文是「亞太戰區精神力機甲作戰部隊」）
inscriptionstring?圖上字樣（原文照抄），如 DAWNSTAR LEAGUE ARMORED FORCE · DEPARTMENT OF THE DEFENCE FORCE；辨識、搜尋與佐證用
factionsstring[]?對應的陣營文字：機師 pilots.faction 的原字串（可多筆，完全比對、去頭尾空白）。只用來排序建議，不會寫入任何 pilotLore。name 和陣營文字一字不差時不必填（名稱本身也算比對對象）
notestring?給管理員看的備註（例：看字樣推測、待確認）

02 — 刻意不做的連動
不進 SPECS、不走 saveWithHistory
⚠ 理由同步寫在 src/lib/api/factionEmblems.ts 檔頭
  • 不登記進 entityRefs SPECS：註記不引用別人、也不被 EntityRef 引用，沒有級聯要跑。 一旦進 SPECS，級聯刪除與「影響 N 處引用」掃描會自動連帶讀這個集合——rules 晚一步部署的話，全站既有的刪除功能會一起 permission-denied（PLAN-042-A 踩過）。
  • 不走 saveWithHistory：註記是幾個字的短文、寫壞重填即可，所以寫入就是 writeDoc＋bumpDataVersion('factionEmblems')，同 pilots／modules。
    （2026-10-16 修訂）原本還有一條理由：ChangeTargetKind 綁著 SPECS（entityRefs 的 SPEC_COLL_OF 是窮舉 Record），要稽核記錄就得先進 SPECS。 PLAN-042-B 讓 SPEC_COLL_OF 可以填 null（給 mechLore 用），這條已不成立；真要稽核記錄時，加 kind＋填 null 就好，不必進 SPECS。

資料維護
🛠️ 後台編輯
後台 › 機師故事館編輯台 › 「陣營徽章」分頁（/admin/lore?view=emblems；&emblem=<4 碼> 捲到那一顆，選圖器的「未命名・補名稱 ↗」連到這裡）。 每顆一列：名稱、圖上字樣、對應的陣營文字（標籤輸入，候選是現有的陣營寫法）、備註、使用中人數；可篩「未命名」「使用中」。 註記讀不到時不開放編輯（存檔是整份覆寫，不知道既有內容就存會洗掉別人填的字）。
🔒 安全規則與讀取路徑
match /factionEmblems/{docId}：read / create / update 皆 canEditLore() （LORE_EDITOR / ADMIN / OWNER），delete 只給 isAdmin()（PLAN-042-H，2026-10-17；理由同 pilotLore）。 寫入走 writeDoc＋bumpDataVersion，不留 changeHistory；協作編輯的 bump 由 meta/gameData 的 isLoreVersionBump() 放行。 前台經 Cloudflare Worker 代理（/api/data/factionEmblems）。前台只把它當滑鼠提示用：讀不到不擋頁面、不顯示錯誤。
⚠ 部署順序
firestore.rules → Worker（ARRAY_COLLECTIONS）→ 預填腳本＋bump → 網站。 rules 與 Worker 都不在 npm run build / git push 的流程內；漏 Worker 的症狀是正式站 /api/data/factionEmblems 404（本機全綠）。 三處硬性守衛由 src/lib/collectionKeys.test.ts 斷言（Worker、KNOWN_KEYS、rules）。
