01 — skills
skills Collection 欄位定義
📌 用途說明 機師的 talents / skills / neuralDrive 以嵌入方式存於 pilots 文件中（1:1 關係）。
skills collection 存放「可跨實體引用」的共用技能定義，例如：多個武器共享的技能效果模板、或用於 BUFF 系統的觸發技能。
初期可作為技能索引使用，後續依需求擴充引用關係。

namestring技能名稱
typeSkillType技能類型 Enum：被動技能 / 主動技能 / 指令技能 / PP技能
descriptionstring效果描述
iconstring?圖示路徑
dmg / crit / critDmg / accnumber可量化加成數值

02 — buffs
buffs Collection 欄位定義
🆕 v1.0 新增：BUFF Collection（初始版本） 初始版本僅定義 BUFF 名稱與描述，作為佔位設計。後續版本將擴充：持續時間、疊加規則、效果欄位（effects[]）、觸發來源等。 設計原則：任何技能、模組、武器皆可透過 buffIds[] 陣列引用此 Collection 的 BUFF 定義。

📐 PLAN-020：文件 ID 命名規則（新建適用）
  • 新建 ID 由系統生成：維護者只輸入名稱、選分類，ID 一律為 buff_<slug(name)>（前綴固定 buff_，分類只寫入 buffType 欄位、不進 ID）。對話框即時預覽生成的唯讀 ID。
  • slug 規則對齊 scrape-pilots-v3.js 的 safeName （見 src/utils/idSlug.ts 的 makeEntityId）：保留中文 / 英數 / 全形字， 去除半形空白、ASCII 標點、斜線等 Firestore 不合法字元；清理後為空則擋下建立。
  • 前綴防呆：維護者在名稱欄位若誤打 buff_ 前綴 （不分大小寫、可連續重複，如 buff_ / BUFF_ / buff_buff_）， 由 stripIdPrefix 自動消除，ID 與 name 皆不會殘留多餘前綴。
  • 撞名 = 撞 ID（不分大小寫）：建立當下以 docExists('buffs', id)（伺服器）＋ 全集合 in-memory 雙重檢查，命中即擋下並導引「編輯既有項目」，不自動加序號。 in-memory 比對不分大小寫，避免 buff_事不宜遲 與 BUFF_事不宜遲 這類大小寫孿生 （Firestore 文件 ID 區分大小寫，會被視為兩筆不同文件）。
  • 出生即凍結：建立後改 name 只改欄位、不動 ID； 引用以 ID 精準比對（x.id === refId），不受 name 變動影響。
  • 舊資料維持原狀：既有 BUFF_… / buff_… / 無前綴 等歷史風格不遷移 （無程式碼解析 ID 前綴判斷型別，型別存於 buffType）。
  • 本規則由共用 useNewItemCreation 的 deriveId 可選模式提供， 其他集合（pilots / weapons / modules…）日後可逐一 opt-in。
