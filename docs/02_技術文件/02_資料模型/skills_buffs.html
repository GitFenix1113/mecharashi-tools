PLAN-001 v3.0
Shared Interface
共用 Interface
SkillCondition 與 SkillEffect 為跨實體共用的基礎型別，定義於 src/types/index.ts。
🆕 PLAN-001：新增 SkillCondition、SkillEffect、GameBuff interface 取代 PilotSkill / PilotTalent / NeuralDriveLevel / WeaponSkill 原有的平坦數值欄位（dmg / crit / critDmg / acc）。
condition 欄位僅用於顯示說明標籤，計算器不自動判斷觸發。
SkillCondition
技能效果的觸發條件說明，顯示給玩家作為標籤，不驅動計算器自動邏輯。
欄位型別說明
triggerPilotSkillTrigger (Enum)觸發類型（顯示說明用，計算器不自動判斷）：
always 永久被動 / onAttack 攻擊時 / onCounter 反擊時 / onApSkill 使用 AP 技能時
weaponType 使用特定武器類型 / dualWield 雙持 / hpBelow HP 低於門檻
firstAttack 戰鬥首次攻擊 / enemyPhase 敵方回合 / allyHasBuff 隊友持有增益
weaponTypestring?限定武器類型（WeaponType enum，大分類：射擊 / 格鬥 / 突擊 / 戰術）；trigger = weaponType 時填入
舊欄位名 weaponCategory，已更名為 weaponType
weaponKindstring?限定武器種類（WeaponKind enum，細分類：機槍 / 狙擊步槍 / 刀劍…）；比 weaponType 更精確的種類層級篩選
hpThresholdnumber?HP% 門檻（如 50 代表 "HP < 50%"）；trigger = hpBelow 時填入
minApCostnumber?最低 AP 消耗條件
targetClassstring?目標職業限制（PilotClass enum）
hasBuffstring?trigger = hasBuff 時：需持有的 buff / 狀態名稱（如 '強化射擊'、'瞄準'）
SkillEffect
單一可計算效果條目，stat 值與 Module 平坦欄位名稱對齊以確保計算器加總邏輯一致。
欄位型別說明
statstring影響屬性，與 Module 欄位名稱對齊：
'dmg' | 'crit' | 'critDmg' | 'acc'
'dmg_assault' | 'dmg_melee' | 'dmg_shooting' | 'dmg_tactical'
'dmg_blade' | 'dmg_machinegun' | ...（武器種類）
'range' | 'armor_rate' | 'firepower_rate' | ...（其他屬性）
valuenumber數值大小（如 15 代表 15%）
valueType'add' | 'override'?數值計算方式：'add'（預設，加算）/ 'override'（覆蓋原始值，如把係數 0.15 改為 0.2 而非相加）
scopeSkillScope (Enum)受益對象：self（自己）/ ally（其他隊友）/ team（全隊含自己）
conditionSkillCondition | null觸發條件說明；null = 此技能 active 時永遠生效
空陣列語義 effects: [] 代表「技能存在，但數值待管理員填入」，計算器遇到空陣列直接跳過，不影響運作。
不再使用 dmg: 0, crit: 0, critDmg: 0, acc: 0 這種有誤導性的初始值。
SkillType Enum — PilotSkill.type 對應值 被動技能 — 永久生效（passive）
主動技能 — 主動使用，消耗 AP（含武器技能 EquipmentSkill）
指令技能 — 有 CD（冷卻回合），額外欄位 cd?: string，對應 API type = "Order"
PP技能 — 消耗 PP（每次出擊有 PP 上限），額外欄位 pp?: string，如「勇氣」消耗 1PP
設計說明
skills Collection
可跨實體引用的共用技能定義庫。機師技能仍嵌入 pilots 文件（讀取效率優先）。
🆕 v2.0 / PLAN-001：skills Collection 機師的 talents / skills / neuralDrive 仍以嵌入方式存於 pilots 文件中（讀取效率優先）。
skills Collection 存放可被多個實體引用的技能模板（如武器 / 模組共用技能效果）。
PLAN-001 起以 effects: SkillEffect[] 取代舊有的平坦數值欄位。
欄位型別說明
idstring唯一識別碼（如 "skill_001_增傷"）
namestring技能名稱
typestring技能類型（被動技能 / 主動技能）
activationSkillActivation (Enum)?生效方式（武器技能適用）：carry / equip / use
descriptionstring效果描述文字
effectsSkillEffect[]可量化效果列表（取代舊平坦數值欄位）
tags[]string[]分類標籤（如 ["增傷", "被動"]）
buffIds[]string[]此技能觸發的 Buff ID 列表（關聯 buffs Collection）
Schema
buffs Collection — GameBuff
🆕 PLAN-001：GameBuff interface 完整定義 BUFF 定義庫，任何技能、模組、武器均可透過 buffIds[] 陣列引用。
玩家可在計算器中獨立切換 Buff（不依賴技能開關），計算器加總所有 active Buff 的 effects[]。
欄位型別狀態說明
idstring✅ v1.0唯一識別碼（如 "buff_過熱狀態"）
namestring✅ v1.0Buff 名稱（如 "過熱狀態"）
descriptionstring✅ v1.0Buff 效果描述文字
iconstring?✅ v1.0圖示路徑（可留空）
buffTypeBuffType (Enum)✅ PLAN-001Buff 類型：statBoost / resource / state / debuff / control
maxStacknumber?✅ PLAN-001最大疊加層數；resource 類型用，省略表示不可疊加
durationnumber?✅ PLAN-001持續回合數；null = 持續到消耗 / 手動關閉
maxTriggersnumber?🆕生效次數：效果可觸發 N 次後耗盡（與 maxStack 疊加層數、duration 回合數為獨立維度）
mutexGroupstring?🆕 PLAN-019形態互斥群組；同 group 的形態/狀態一次只能存在一個（虛粒子形態 ⟷ 實粒子形態）
descriptionRefsDescriptionRefs?🆕 PLAN-019描述內 [xxx] 引用側錄；buff 也可引用其他 buff
effectsSkillEffect[]✅ PLAN-001Buff active 時提供的效果列表
levelsBuffLevel[]?🆕 PLAN-024階梯 buff 各等級能力；無 = 普通 buff。各級 maxStack/effects 由此提供，同 buff 不同 level 天然互斥（取代 mutexGroup）；引用以 <id.lvN.attr> 指定級、buffIds 以 id@N 賦予級
termRefstring?🆕 PLAN-024掛載 glossaryTerm ID；填了則詳情卡改以該詞條的官方說明為顯示來源（取代本 buff description，單一真相源，為技能庫鋪路）
BuffLevel — 階梯 buff 單一等級（🆕 PLAN-024）
階梯 buff 的 levels[] 各元素。比照 ModuleLevel：結構型（如凝勢）各級 maxStack / effects 不同 → 填滿；數值型（如傷害提升）各級只差數值 → 多半只填 level + effects。level 是「靜態強度階」（來源決定掛哪級），與執行期的 stack（疊加層數）是兩個維度。
欄位型別說明
levelnumber等級序號 1, 2, 3…（對應原羅馬尾碼 I / II / III）
descriptionstring?該級描述（選填；可被滿星 / 算力變體引用）
descriptionRefsDescriptionRefs?該級描述的 [xxx] 引用側錄（PLAN-019）
maxStacknumber?該級最大疊加層數（結構型各級不同，如凝勢 5 / 7 / 7；數值型通常不填）
durationnumber?該級持續回合數
maxTriggersnumber?該級生效次數（效果可觸發 N 次後耗盡）
effectsSkillEffect[]?該級的數值效果（數值型各級的數值差異在此；結構型通常不填）
iconstring?該級專屬圖示（選填；不填沿用 buff.icon）
🆕 PLAN-024：flat XOR leveled — 能力資料單一權威來源 一顆 buff 只能二擇一：flat（無 levels，能力資料來自頂層 maxStack/duration/effects） 或 leveled（有 levels，能力資料一律由各 BuffLevel 提供，頂層三欄停用且應為空）。 buff-wide 欄位（兩態共用）：name/buffType/description/descriptionRefs/icon/mutexGroup/termRef； level-exclusive 欄位（有 levels 只能填在各級）：maxStack/duration/maxTriggers/effects。 後台 BuffAdmin 於有 levels 時停用頂層三欄並在儲存時清空，杜絕「頂層 vs 各級」雙來源衝突。 引用 leveled buff 須帶 level（id@N / <id.lvN.attr> / EntityRef.level）才取得能力數值；不帶 level 僅顯示 buff-wide 資訊。
BuffType 枚舉值說明 statBoost — 純數值增益（最常見）
resource — 可堆疊資源（如彈潮蓄能、連擊層數），搭配 maxStack 使用
state — 特殊狀態（如過熱、強化模式）；形態切換用 state + mutexGroup 表達
debuff — 對敵減益
control — 控制效果
🆕 PLAN-019-F：後台維護 buffs 現可於管理後台「BUFF 管理」分頁新增／編輯（寫入走 updateBuff，安全規則已具備 admin write）， 描述下方掛 RefPicker 可標 [xxx] 引用、effects 複用技能效果編輯器；不再只能靠 seed 腳本或 Firestore console。
PLAN-019
共用引用型別 — EntityRef / DescriptionRefs
🆕 PLAN-019 Layer 1：把描述內 [xxx] 跨實體引用結構化 description 維持遊戲原文字串（[xxx] 標記原樣保留），外掛一份 descriptionRefs 側錄表把每個 [xxx] 對應到目標實體。顯示層的 <RefText> tokenize 後查表，命中渲染為可點擊引用、未命中原樣顯示（優雅降級）。 此型別跨 pilots / weapons / modules / buffs / bosses / stages 共用。
欄位型別說明
EntityRef.refTypeRefTypebuff / skill / pilot / mech / weapon / module / backpack / component / stat / term / neuralDrive（🆕 PLAN-023，指向 neuralDriveAbilities）
EntityRef.refIdstring目標 ID（buffs/{id}、pilots/{id}、glossaryTerms/{id}、neuralDriveAbilities/{id}），或 stat key 如 'dmg'
EntityRef.labelstring?顯示文字；預設取目標 name，可覆寫（原文用別名時）
EntityRef.levelnumber?🆕 PLAN-024：引用階梯 buff 的特定等級。數值代入時自動帶出 <refId.lvN.attr> 形式；未指定 = 不限級（沿用頂層 / base）
DescriptionRefsRecord<string, EntityRef>key = 括號內文字（如 "虛粒子形態"）→ 對應實體
refType 分派原則（混合策略） 增傷/加子彈/加暴傷等既有屬性 → stat；特殊增益/狀態/形態 → buff； [海莉絲] → pilot/mech；無數值歸宿的機制關鍵字（如 固定傷害）→ term（glossaryTerms）。 glossaryTerms 只收「無專屬集合可放」的關鍵字。詳見 PLAN-019 總綱。
PLAN-022
數值引用 — <refId.attr> token
🆕 PLAN-022：把描述內的層數／回合數綁定 BUFF 屬性，根除「正文寫 7、buff.maxStack 是 5」的漂移 繼 [xxx] 實體引用之後的第二種 token。描述正文以 <refId.attr> 內嵌「對某 BUFF 屬性的引用」， 顯示層從 GameDataContext 查 refId 取屬性真值 —— 數字只有 BUFF 一份，正文不再各處手抄。 與 [xxx] 不同：數值 token 自描述、不需 descriptionRefs，且同一 token 可重複出現不限次數。

顯示真值前台 RefText / DiffHighlight 解析；查無（buff 被刪／尚未載入）優雅降級為暗色 ?可疊加5層
屬性註冊表 NUM_ATTRS（src/utils/numRefs.ts，單一資料源；新增可綁屬性 = 加一筆，解析／編譯／降級自動跟上）：
attr語法糖 sigil標籤適用 refType取值
