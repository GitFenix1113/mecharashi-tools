mechs機甲資料 · MECH DATA

部件詳細資料、出力/重量、副模組引用 — 僅儲存滿級（manji）數據

UPDATED v1.5
v1.4 更新
重構說明
🔄 v1.5 更新：天生模組改為逐部位推導（PLAN-052-K） 遊戲裡一顆天生模組的等級是四個部位各自貢獻的等級加總，而本集合只存 module4Id / module8Id / moduleFixedIds 三個 id ——沒有部位、也沒有等級。
矩陣刻意不落盤：90 台 × 4 部位 ≈ 1500 格全是規則的產物，落盤會在官方改版時過期， 而選填欄位不會被填滿（0/5 定律）。通則由 src/utils/innateModules.ts 的 INNATE_LEVEL_RULE 算出（滿階：S ⇒ 特性位 1／8 級 2／副模組 1 每部位；A ⇒ 8 級模組只有軀幹與腿部各 1；B ⇒ 全 0）， 專屬模組則由 (boundPart, levels.length) 推導，零新欄位。
例外的出口是新欄位 parts.{position}.innateModules（見下表）——整格取代、不做部分合併。
對帳：node scripts/check-part-module-drift.mjs（唯讀，逐格比對官方 aircraft_data； 基準線 2026-08-29 全 83 台 × 932 格全中。⚠ 官方停在 v3.2，v3.3 之後的 7 台對不到）。
🔄 v1.4 修正：部件詳細資料獨立 + 模組映射 parts 欄位從耐久數值升級為完整部件物件（含火力、護甲、命中/閃避、移動力、接口、重量、圖示等）。
機甲詳情頁採座艙式排版（3×3 格），中央顯示立繪，四角顯示各部件屬性卡片。
部件圖片路徑：public/images/mechs/{機甲名}/{position}.webp（portrait / half / torso / leftArm / rightArm / legs）。
2026-08 起本層圖檔全面轉為 WebP、原 PNG 已移除；mech_models / mech_badges 因程式中硬編副檔名，仍維持 PNG。
顯示端一律走 utils/assets 的 imageCandidates() + <FallbackImage> 逐層退回，資料殘留舊 .png 路徑仍能自動退到 .webp。
僅儲存 manji（滿級）數據，不再保留初始 base 數據。

 ├ durablenumber耐久值
 ├ armornumber護甲值
 ├ firepowernumber火力值
 ├ weightnumber部件重量
 ├ interfacePartInterface | ''模組接口型別：Ⅰ型接口（32 格）／Ⅱ型接口（288 格）／'' 無接口（40 格）
值由「品質階級 × 部位」決定，不是每台機甲的自由欄位：S ⇒ ⅡⅡⅡⅡ／A ⇒ ⅠⅡⅡⅠ（軀幹與腿部為 Ⅰ）／B ⇒ 無接口。官方 API 83 台 332 格零例外；存的是滿品質階的值（爬蟲取 manji，基礎階與滿階不同：S 級基礎是 ⅠⅠⅠⅠ、A 級基礎完全沒有接口）。規則與 CI 守門在 src/utils/mechInterface.ts。
''（常數 NO_INTERFACE）＝ 這台機甲沒有模組接口，今天只有 B 品質 10 台 40 格；UI 顯示「無模組接口」，不再有「未建檔」這個狀態。
2026-08-27 修正 2 台 8 格：mech_089_星夜女神（人工建檔輸入錯誤，原值 ⅠⅠ型接口 被 D-1 正規化時收成 Ⅰ 型，方向錯了）與 mech_090_美杜莎MK2（依 S 級規則補齊）。後台除下拉選單外另加偏離規則的黃字提示。
 ├ hitnumber?命中值（僅左右臂有）
 ├ dodgenumber?閃避值（僅腿部有）
 ├ movenumber?移動力（僅腿部有）
 ├ outputnumber?出力（僅軀幹有）
 ├ antiRiotnumber?抗暴（僅軀幹有）
 ├ iconstring?部件圖示路徑 /images/mechs/{機甲名}/{position}.webp
 ├ mechaIconstring?遊戲內部資產名（用於官方 CDN waparts/ 路徑）
 ├ fixedArmamentArmamentMount[]?焊死在這個部件上的固定武裝（PLAN-052-A）。{ weaponId, slot, side? }，slot 沿用 WeaponEquipSlot。
左臂 → 左肩、右臂 → 右肩（肩槽附屬於手臂，兩者是巢狀不是正交）。硬不變式：mount.slot === weapons[mount.weaponId].equipSlot，允許 0 例外，由 scripts/validate-mech-slots.mjs 全庫校驗。
用陣列而非選填 scalar：帕斯卡是同一把衝擊炮掛左右兩肩，scalar 表達不了；且 scalar 的三態語意會撞上 stripUndefined（取消勾選寫的 undefined 被整個濾掉 ⇒ 一旦填了就再也取消不掉）——被本欄位取代的三個死槽位就是栽在這裡。
現況（2026-08-24）：帕斯卡／破曉者-01／霸王 各 2 筆，共 6 筆。
渲染時 React key 一律用 slotKey(ref)，不可用 weaponId（兩肩同一把會撞 key）。
 └ innateModulesInnateModuleEntry[]?v1.5 新增。這個部位天生帶哪幾顆模組、各貢獻幾級：{ moduleId, level }[]。
undefined ＝ 照規則推導（絕大多數台走這條，全庫今天 0 台有值）；填了就整格取代，不做部分合併。
[] 與 undefined 語意不同：[] ＝「這個部位沒有任何天生模組」、undefined ＝「照規則算」。後台的「清除」寫回的是 undefined。
level 是這個部位單獨貢獻的級數，不是該模組的最終等級（最終等級 ＝ Σ四部位天生貢獻 ＋ Σ(插槽貢獻 × 部位倍率)，封頂於 levels.length）。
⚠ 它住在部件上，所以混搭時跟著換進來的那一格走——與 fixedArmament 同一條性質。
後台入口：機甲編輯 → 部件分頁 → 各部位卡的「改成人工指定」。
▎副模組引用（指向 modules Collection）
module4Idstring?特性模組 ID（4模組槽位）→ modules Collection；無特性模組的機甲可省略
module8Idstring?8級模組 ID（8模組槽位）→ modules Collection；無8級模組的機甲可省略
moduleFixedIdsstring[]固定副模組 ID 列表（可多個）→ modules Collection；含機甲副模組與機甲專屬模組兩類，靠 module.slot 分流（不要看 id 前綴：A 級的燧石特性模組是 mod_1001、霸王的專屬模組是 mod_2064）
⚠ 這三個欄位只有 id，沒有部位也沒有等級。「哪個部位帶它、各幾級」一律由 resolveInnateModules() 算出（見上方 v1.5 更新），例外才落在 parts.{position}.innateModules。不要在畫面上直接讀這三個欄位當「自帶模組清單」——那正是 PLAN-052-K 修掉的 bug：混搭換掉一個部位後它一顆都不會變。
▎圖片路徑
