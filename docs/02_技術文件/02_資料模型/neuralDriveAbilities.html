neuralDriveAbilities神經驅動能力庫 · NEURAL DRIVE ABILITIES

PLAN-023 · 從各機師 neuralDrive 抽出去重的共用／專屬能力，單一資料源

🆕 PLAN-023：把散在 82 機師 neuralDrive 裡的能力抽成獨立集合 原本同一個能力（如「運動戰2」「AP優化1」）嵌在每位持有機師的 neuralDrive[].levels[] 內、重複維護。 本集合以能力名為鍵去重，Pilot.neuralDrive 的各 level 改以 abilityId 引用本實體， 共用能力維護一份、改一次全機師生效。結構比照 pilotSkills（PLAN-004）：collection + ID 引用 + resolve 雙格式過渡。
規模：1416 個能力實例 → 395 份能力文件（去重 72.3%；共用 65、專屬 327、職業變體拆分 +3）。
Schema
NeuralDriveAbility 欄位定義
欄位型別說明
idstring文件 ID，格式 nd_<能力名 slug>（slug 規則同 idSlug.ts，與 buff_/skill_/term_ 一致）。職業變體加職業後綴，如 nd_AP優化2_戰術家
namestring能力名（= 原 NeuralDriveLevel.skillName，亦為描述內 [xxx] 的指派目標）
descriptionstring能力效果描述（= 原 NeuralDriveLevel.effect）；可含 [xxx] 引用其他能力／詞條／buff
descriptionRefsDescriptionRefs?描述內 [xxx] 引用側錄（PLAN-019 Layer 1）。神驅描述常互引其他能力（[協同作戰1] 等），以 refType 'neuralDrive' 指向本集合
icon / iconLocalstring?圖示（= 原 skillIcon / iconLocal）
effectsSkillEffect[]可量化效果（模擬器用）。建庫時多為空，由後台 NeuralDriveAdmin 長期補填（共用能力填一次全機師受益）
buffIdsstring[]賦予的 buff（id 或 id@N，比照技能／天賦）
Design
設計重點
能力名為鍵 + 職業真變體 去重以「能力名」為主鍵。盤點發現 3 個能力同名卻因職業而效果不同，拆成獨立文件（少數版以職業名為 ID 後綴）：
· AP優化2：戰術家「上限+2」（nd_AP優化2_戰術家）／其他「上限+1」（nd_AP優化2）
· 動力革新2：戰術家「AP回復+1」（nd_動力革新2_戰術家）／其他「擊破回1AP」
· 協同作戰3：機械師「的」版（nd_協同作戰3_機械師）／突擊手版
flip 時各機師依其職業指到對的 abilityId；少量亂碼（編碼壞字）以「該組多數文本」收斂。
雙格式過渡（與 pilots 的關係） Pilot.neuralDrive[].levels[] 加選填 abilityId。填了則內容由本集合提供，未填則用嵌入舊欄位； resolveNeuralDriveLevel(lv, abilityMap) 統一兩種格式（優先 abilityId、查不到回退嵌入，優雅降級）。 已對全 82 機師 flip，嵌入欄位保留為安全網。爬蟲補丁以 ndAreIds 守門：已 flip 的機師跳過 neuralDrive 嵌入式合併，避免 API 值洗回。 zone / minSum / slots（門檻、分區、插槽）仍留在 Pilot，屬「機師如何取得此能力」資訊，與能力本身解耦。
引用與後台 新增 refType 'neuralDrive'：任意 description 的 [xxx] 可指向本集合，前台以實體浮窗呈現（EntityRefView）。 後台「神經驅動」分頁（NeuralDriveAdmin）可列表／編輯能力，RefPicker 支援 neuralDrive 目標，並顯示「此能力被幾位機師引用」（反查推導）； 寫入走 updateNeuralDriveAbility（自動 bump 版本）。
