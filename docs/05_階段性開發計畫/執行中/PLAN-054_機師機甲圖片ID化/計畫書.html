◆ PLAN-054

機師／機甲圖片 ID 化 · gameId · 官方檔名 · 官配

圖片的主鍵從「站上中文名資料夾」換成遊戲 ID：DB 補 gameId／artKey／英文名／官配，陸版擷取的官方原檔以原檔名匯入 public/images/game/，讀取端改由 ID 推路徑，最後清掉與原檔同圖的舊檔。新機師只要填 ID 就有圖。

Problem
問題背景
圖片的主鍵是「站上中文名」，而名字會漂
機師圖在 pilots/<名>/half.webp，pilotArtDir() 再從 portrait 路徑反推資料夾名。 實測已有 5 個資料夾跟顯示名對不上（卡米拉／洛莎審判／淬鋒凱登／裡貝卡，機甲芬裡厄），原稿匯入要靠 import-source-art.mjs 的 NAME_FIXES 7 筆對照硬接；塞拉、珂賽特與雪崩、美杜莎MK2、藍色魔鳥、凜騎士 至今沒有本地圖資料夾。新機師得手動建資料夾、放圖、填路徑。
圖從官方 CDN 來，而且 CDN 排第一順位
爬蟲從官方 CDN 下載裁切圖；PilotIcon、EntityRefView 的候選順序是 portraitUrl（官方 CDN）→ 本地， 每張頭像先打一次第三方網域。2026-09-25 的陸版客戶端全圖擷取已拿到原檔（含 90×90 小頭像、部件圖、2000×1080 機甲大圖）， 但沒有管線把它接上站。
DB 沒有遊戲 ID；英文名與官配只存在筆記裡
機師卡編號（gameId）與立繪主鍵（artKey）在 5 位機師身上不相等、不能互推；nameEn 欄位 PLAN-042-C 開了但沒有資料 （D-5 列為管理員長期作業）；官配 61 組只存在對照檔與站長的記憶中。
v3.0 之後的立繪多是人工去背，品質不一致
官方來源跟不上之後，機師與機甲圖幾乎都是人員手動去背：解析度有落差、圖片置中一直沒有統一，版面只能逐張微調遷就。 站長 2026-10-03 定案：有官方原檔的一律換成官方原檔，不只換「剛好同圖」的那些（決策十一）。
對照已定版（2026-10-03），本計畫不重新盤點、不重新核對
唯一輸入 _local-notes/2026-10/2026-10-03_機師機甲圖片資源mapping_v3_final.json（以下稱 v3）： 91 機師（90 位有 gameId／artKey／英文名；索妮婭此份資料沒有）、92 機甲（wap 編號；凜騎士＝遊騎兵付費塗裝）、 官配 61 組（v1.1 起同版「機師執照＝機甲裝甲」自動配對 47 組＋開服 v1.0 站長指定 14 組）、 每個實體的全部官方素材歸屬（機師 1,865 筆、機甲 2,849 筆）。站長已核對 v1（340 筆）與 v2（159 筆），無未解項目。
Design
設計決策
左線回填 DB、右線匯入檔案；兩線只在讀取端 helper 匯流，互不依賴執行順序以外的任何東西
決策一：v3 是唯一真相，圖片索引.csv 只是檔案定位器
  • v3 決定「誰是誰、哪張圖屬於誰」；v1／v2 與 10-01 盤點檔都不再讀。
  • CSV 只在兩處用：_reserve（v3 只列 ID，要靠命名規則找檔）與新實體模式（決策十）。它不參與任何歸屬判斷。
  • 原始 PNG、CSV、擷取工具一律不進 repo；腳本以 --src 參數讀本機素材夾。
決策二：資料層欄位——全部選填字串，gameId 與 artKey 不互推
集合欄位值例筆數說明
pilotsgameId'10103174'90機師卡 Icon_item_<gameId>A 的編號（只有可抽機師有）
pilotsartKey'Pilot_10103174A'90預設立繪主鍵，與官方檔名逐字相同（_half／_head／_Raw 接在後面）
pilotsnameEn'Yevgeny Ivanovic Goman'90既有欄位（PLAN-042-C D-4），本計畫一次回填
pilotspairedMechId'mech_014_戴亞斯'61官配機甲的文件 ID
mechsgameId'1011'92wap 四碼（Icon_mecha_wap1011）
mechsskinOfId遊騎兵的文件 ID1塗裝本體（只有凜騎士）
  • 字串不是數字：'13037' 與 '10103123' 長度不同，只拿來拼路徑、不做運算。
  • 兩欄不互推：例外 5 位——維娜 10103144／Pilot_13019A、貝爾莎 10103145／Pilot_13010A、阿列娜 13037、珂賽特 11021、瑪阿特 10103180。 artKey 存完整鍵，程式裡不留「主鍵怎麼拼」的規則。
  • 官配只存機師側，機甲側由 pairedPilotOf(mech, pilots) 推導。v3 是 1:1 對稱（61／61 已驗）；兩邊都存就得兩邊同步， 後台改一邊忘一邊是靜默的不一致，推導則不會壞。機甲頁要讀 pilots 集合，但它在版本快取內，不增加 Firestore read。 ⚠ 交接檔原寫雙邊各一欄（pairedPilotId），這裡改為單邊 → ✅ 站長已確認（2026-10-03）。
  • 不存「為什麼沒有官配」：賽文（官方贈送）、帕斯卡／信仰之眼（聯動）、凜騎士（塗裝）、暮色之牙／開拓者（開服未指定）畫面上不顯示官配即可，原因留在 v3 與本計畫書。
  • 不存官方 API ID：它與 gameId 在 81 位相同，但瑪阿特的 API ID 其實是她的造型卡、另有 8 位沒有 API 資料——不是穩定的識別子。

決策四：檔案落點——一個實體一個 ID 資料夾，檔名＝官方資產名
public/images/game/ pilots/<gameId>/<官方檔名>.webp pilots/10103144/Pilot_13019A_half.webp ← 維娜：資料夾是 gameId、檔名照官方 mechs/<wap>/<官方檔名>.webp mechs/1011/Icon_wap1011_1.webp _reserve/npc/<id>/ · enemy-mech/<wap>/ · unknown/<key>/ 站上沒有的實體（NPC 116 · 敵方機甲 10 · 對不到的英文名鍵 4） README.md 來源、命名規則、怎麼重跑匯入
  • 資料夾名＝ID：後台選圖器照資料夾分組，重匯與清檔都以實體為單位。
  • 檔名＝官方資產名逐字（含大小寫）＋.webp：拿官方檔名就 grep 得到，不再需要任何對照表。
  • sharp 轉 WebP q82、原尺寸不縮（最大 2000×1080）、保留透明；同名 Sprite／Texture2D 取 Texture2D；同名但 sha256 不同 → 中止回報，不猜。
  • Windows 不分大小寫、GitHub Pages 分：匯入前以小寫做碰撞檢查（白名單內實測 0 筆）。

決策六：渲染前索引 gameArtIndex.ts——只索引讀取端用得到的 kind
  • 與 hasPilotArt() 同理：版面要在渲染前就知道這個 ID 有沒有某種圖，不能等圖載失敗才換構圖。
  • 由 generate-art-index.mjs 在 build／predev 掃 public/images/game/ 產生；每種 kind 一個 ID 的 Set （機師 half／head／raw／card、機甲 icon／parts／sn），不把 ~2,000 個檔名打進前台 bundle。
  • kind 的命名規則（<artKey>_half、Icon_item_<gameId>A、Icon_mecha_wap<wap>、Icon_wap<wap>_1~4、Icon_mecha_wap<wap>_SN_Raw） 收在一個共用模組，索引、部署剪裁、匯入的新實體模式三處共用同一份。
決策七：讀取端——helper 優先、舊路徑後備（漸進切換）
  • 新增純函式（可 node --test）：pilotGameArt(pilot, kind)、mechGameArt(mech, kind) → 路徑，索引沒有就回 undefined。
  • 呼叫端統一寫 imageCandidates(pilotGameArt(p, 'half'), p.portrait, p.portraitUrl)：本地官方原檔 → 舊本地檔 → 官方 CDN。 主路徑從此不再先打第三方網域。

  • ⚠ 切換期間舊檔不刪：候選鏈的第二順位就是舊檔，任何一處漏切都還有圖可退。刪檔排在 D，且前面有守門測試（C-7）。
決策八：OG 社群預覽跟著切，而且要在刪檔之前
  • generate-og-entity-images.mjs 現在鏡射 pilots/*/half.webp、mechs/*/portrait.webp——D 階段一刪，社群卡片就全退預設圖。 C 階段先改成鏡射 game/pilots/*/*_half.webp、game/mechs/*/Icon_mecha_wap*.webp。
  • Worker 的 buildOgMeta 由 doc 的 gameId／artKey 推 og:image，舊 portrait 當後備；既有的「推出來的 JPEG 不存在就退預設圖」探測保留。
  • Worker 要另外部署；CLAUDE.md 的 OG 補驗指令（現在預期 og/entities/pilots/海莉絲/half.jpg）要改成新路徑。 Transform Rule 不受影響——頁面路徑 /pilots/、/mechs/ 都沒變。
決策九：清舊檔——讀取端與 OG 都切完、驗收過，才刪
  • 有官方原檔的舊圖一律退場（決策十一）：機師 half／full、機甲 portrait／部件四張／art.webp。 刪前的逐張像素比對不再當刪除閘門，改成產出「畫面會變」清單（多半是 v3.0 後的人工去背圖），附切換前後截圖給站長看。沒有官方原檔的（索妮婭）不動。
  • 站上自製圖（機師 art.webp 52 位、官網圖層 8 位×3）一併搬到 ID 資料夾： pilots/<名>/ → pilots/<gameId>/。 pilotArtDir() 改讀 gameId，不再從 portrait 路徑反推；NAME_FIXES 退場；名字資料夾全數消失。✅ 站長 2026-10-03 確認
  • 最後把 DB 的 portrait／parts.*.icon 改寫成 game 路徑、清掉指向不存在檔案的 halfPortrait（筆數以 dry-run 為準）， 連同其他集合裡的路徑快照一起改（決策十二），不留任何指向已刪檔案的值。portraitUrl（官方 CDN）照留，當最後一道後備。
決策十：管線可重跑——新機師填 ID 就有圖；本計畫不碰爬蟲
  • import-game-assets.mjs 兩種模式： --from=v3（本計畫的整批匯入）；--id=<gameId> --art-key=<artKey>／--wap=<####>（新實體：core kind 依命名規則從 CSV 找， 英文名鍵類素材如招募／大廳仍需人工對照，不自動）。預設 dry-run、--apply 才寫、已存在跳過、--force 重轉。
  • 爬蟲已降為備用（站長 2026-10-03 定案，見 CLAUDE.md 6.5：官方 Wiki 更新太慢，遊戲資料改由後台人工建檔，只保留活動擷取）→ 本計畫不改任何爬蟲。 原本排的「爬蟲保留清單」與「爬蟲退出圖片業務」兩項取消；動用備用爬蟲前要注意的兩個隱患（整筆覆寫洗掉新欄位、圖片寫回中文名資料夾）已記在 CLAUDE.md。
  • 新機師流程寫進 data-patch skill：後台建檔 → 填 gameId／artKey → 有新的客戶端擷取就跑 import --id，還沒有就照舊在後台手動指定 portrait → bump。
決策十一：有官方原檔的一律換官方（站長 2026-10-03）
  • v3.0 之後的機師／機甲圖多為人工去背，解析度與置中都不一致 → 機師 half／full、機甲 portrait／部件四張／art.webp 全部改用官方原檔，不分「同圖」與否。
  • 不在此列：機師 art.webp（863×1600 直式完整全身原稿，遊戲檔裡沒有等價物）、官網圖層 official-*（本來就是官方素材）、索妮婭（沒有官方檔）。
  • hasMechArt() 的判準改成「有沒有 _SN_Raw」（91／92；凜騎士沒有 → 走小尺寸版面）。機甲名字資料夾在 D-1 之後就空了，不必搬。
  • 官方圖構圖一致 → 過去為了遷就人工去背圖做的逐張微調（例如 loreArtTuning.ts 的 LORE_ART_TUNING、各處寫死的 object-position）在 C-7 一併檢查，能拿掉就拿掉。
