Problem
問題背景
052-B 交付的是「能用」，不是「好看」
整頁字級擠在 10–12px（text-[10px] / text-[11px] / text-[12px] 幾乎是全部）， 沒有主次階層；卡片一律圓角矩形＋細框線，是工程介面的長相，不是機甲遊戲的長相。 這一頁從頭到尾沒有經過任何美術方向的決策，只有版面邏輯決策——這是刻意的取捨（先把互動模型修對）， 但取捨的帳現在要還。
站上 175 張美術資產，模擬器一張都沒用到
public/images/pilots/ 有 87 位機師的 full.webp（去背立繪，1240×1080）與 half.webp（頭像 340×340）；public/images/mechs/ 有 88 台機甲的 portrait.webp（3/4 特寫 560×340）與四部位圖。 模擬器目前全部以文字清單呈現，玩家在配一台看不見的機甲。
槽位圖不像機甲
LoadoutRig 現在是 2 欄 grid 方格＋文字標籤（手部／肩部／背部／備用各一列）。 功能正確、但沒有任何線索讓玩家意識到自己在對一台機體動手。
配好一套之後沒有產出物
052-B 明確不做匯出圖（html2canvas 已無 import）。玩家配完只能自己截圖， 截出來沒有站名、沒有分享碼、也沒有算力配置——圖被轉發之後找不回來源。
Design
設計決策
決策一：不新造顏色，改的是「階」不是「色」
src/index.css 的 @theme token（--color-accent-*、 --color-text-*、框線三階）全部沿用，一個新色都不加。 要動的是三件事：
① 字級階——拉出 10 / 12 / 15 / 20 / 30px 五階，數值走 JetBrains Mono 放大到 20–30px， 現在全部擠在 10–12px 是「什麼都同樣重要」＝「什麼都不重要」。
② 外框語彙——以 clip-path 斜切角（大區塊 14px、小元件 8px）取代圓角矩形，作為全頁的機甲語彙。
③ 圖示——見決策五。
這條的意義是：改版不會外溢成全站改色，其他頁面一行都不用動。
決策二：立繪常駐，不做入場動畫
機師立繪掛在左欄當常駐身分卡，不做「選角 → 全身照 → 滑動 → 展開配裝」的入場流程。 理由與 052-B 拆掉 8 步驟精靈完全相同：配裝是反覆試的動作，成本不在第一次而在第五次—— 玩家換一把武器想看重量差多少，不該再看一次演出。 「選角感」改掛在三個不擋路的位置：頭像牆＝挑選器本體（決策四）、立繪＝常駐側欄、 左右滑動＝留給形態切換（052-F）與換機甲這種真的有兩個狀態要對比的地方。
決策三：機甲主視覺用 portrait.webp，不拼四部位
實際檢視素材後推翻了「用四部位圖拼出一台機甲」的構想： torso / leftArm / rightArm / legs 是各自獨立的 3/4 視角渲染，視角、光源、比例都不一致，排成人形會很怪。 因此中央主視覺用 portrait.webp（完整機體 3/4 特寫），槽位以 HUD 引線掛在四周； 四部位改成下方一排唯讀部件卡，等 052-G 部件混搭開放後才變成可換的東西。
素材缺口（不阻塞本計畫）：機甲沒有全身像。 portrait.webp 是特寫不是站姿全身。使用者已確認素材庫未來會補齊全身像， 屆時可直接替換中央主視覺、不動版面結構。本計畫按現有素材出貨。
決策四：頭像牆必須有統一卡框
half.webp 不是去背圖，每張帶各自不同的原生背景色（實測有灰、綠、粉）。 直接鋪成網格會花掉整面牆。每格一律：統一卡框 ＋ 底部漸層遮罩（壓住背景、讓名字讀得到） ＋ 左側 3px 職業色條（沿用 CLASS_CONFIG 既有七職業配色）。 87 位必須 lazy load——全載約 2.6MB。
決策五：🔒 與 ▨ 字符換成描邊 SVG
現行 SlotCell 用 emoji 與字符當圖示。字符在不同系統上字形不一致、無法跟著配色走、 也無法調線寬。改為 16/20px 網格的描邊 SVG，六態共用同一組。 六態的差異只走邊框樣式（實線／虛線）、底色、圖示三個維度，外框尺寸與斜切角一致。
決策六：刪掉右欄的「重量帳」表
頂部常駐帳本列的分段條＋圖例已經回答「重量花在哪裡」（機體／手部／肩部／背部各多少）。 右欄再列一張同樣內容的表是重複資訊。表刪掉，只保留它獨有的那一句 ——「備用組較輕、不計入總重」——移到武器列的footer。
決策七：算力面板進模擬器，並在 052-C 定案前落地
算力與配裝是同一件事的兩面，玩家不會想在兩個頁面之間對照。 好消息是引擎與 UI 都已存在： PilotDetailPage 的 NdPowerBar（PLAN-021）已能點選各區 Lv， 規則引擎 src/utils/ndOverrides.ts（ND_RULES γ 區合計上限 23、 zonePower()、defaultNdLevels()）與 PLAN-034 的 BUFF 階覆寫層共用。 本計畫要做的只有三件：把 NdPowerBar 抽成共用元件、 在 LoadoutDraft 加 ndLevels 欄位、把面板放進左欄。
時序是硬的：見下方「跨計畫修訂」——052-C 的分享碼 codec v1 一旦上線， 之後補算力就得升版本。
決策八：匯出圖是另一份設計，不是螢幕版面的截圖
匯出長圖固定 1000px 寬、無互動、無捲動、資訊一次全給——那是印刷品邏輯， 與螢幕版面（響應式、互動、資訊分層）幾乎沒有共用設計，必須各畫一份。
內容只有配裝與算力，不放技能表（使用者裁決）： Key visual（立繪＋機甲）→ 方案名稱 → 四格數值總覽 → 槽位表（含每把武器的元件）→ 算力分區 γ1／γ2 階梯 → 浮水印 footer。
技術上不需新依賴：站上已有三處在用 html-to-image 的 toPng （VersionQuickTable / ComponentDropsPage / RainbowMechPlannerPage， 皆 pixelRatio: 2 ＋ backgroundColor: '#0a0c10'）。
決策九：浮水印分兩層，且要帶得回來源
① footer 主標：mecharashi.wiki ＋「米赫瑪超吉情豹站 — Milkhama PawInfo Station」 ＋ 非官方聲明（與站上 footer 同一套措辭）。
② 底噪 wordmark：大字級低透明度的 MILKHAMA。
右下角印分享碼與產生日期＋遊戲版本——圖被轉發之後，這是唯一能找回原配裝的線索， 也讓過期的圖看得出是哪個版本的數值。
決策十：方案名稱是 draft 欄位，命名需登入
方案名稱顯示在主版面標題列與匯出圖的最大一行。欄位存在 LoadoutDraft（本機草稿也有）， 但命名與雲端保存需要登入（使用者裁決）；未登入者仍可配裝、分享、匯出圖， 只是圖上不帶自訂名稱。登入 gate 的實作掛 052-E。
Scope
實作範圍與不在範圍內
在範圍內：
  • 視覺地基：字級階、斜切角外框、六態共用的描邊 SVG 圖示組
  • 槽位圖重構：LoadoutRig 改為機甲主視覺 ＋ HUD 引線 ＋ 四部位唯讀卡
  • 槽位六態：SlotCell 六態改版（空／已裝／固定武裝／形態鎖定／無槽／預覽）
  • 機師身分卡：立繪常駐左欄（含 lazy load 與載入佔位）
  • 頭像牆挑選器：PickerShell 機師分支改為頭像網格 ＋ 職業／執照／品質篩選
  • 算力面板：NdPowerBar 抽共用元件 ＋ LoadoutDraft.ndLevels 欄位
  • 武器與元件列：右欄改版、每把武器顯示已裝元件與 n/componentLimit；刪除重量帳表
  • 方案名稱：LoadoutDraft 欄位 ＋ 標題列可編輯欄位
  • 匯出配裝長圖：1000px 版面、html-to-image 接線、兩層浮水印
  • 手機版：以上各項的 compact 版本 ＋ 底部固定操作列
不在範圍內：
  • 元件規則引擎（五條規則、componentFamilyKey()、組合特性預覽）→ 052-D。 本計畫只做面板長相；面板上的可裝／不可裝判定要等 052-D 的規則。
  • 雲端存檔與登入 gate 實作 → 052-E
  • 形態獨立配裝（四個分頁、四組數值）→ 052-F
  • 部件混搭與模組槽（四部位卡目前唯讀）→ 052-G
  • 分享碼 codec 本體 → 052-C；本計畫只負責讓它把算力段納入 v1
  • 機甲全身像——素材未齊，待使用者補齊後再議（決策三附註）
  • 入場動畫／選角演出——已評估後否決（決策二）
Amendments
本計畫對其他子計畫的修訂
這三條是本計畫發現、但要由別的子計畫執行的修訂。寫在這裡是為了不讓它們掉在計畫縫隙裡； 各子計畫動工時應先讀這一節。
對象修訂內容為什麼不能拖急迫度
052-C
分享碼與訪客書架		 codec v1 必須新增算力段（§ND）。現行計畫書的分段規格只有 §SETS / §PARTS / §MODULES / 元件段， 完全沒有算力（已逐字確認）。 總綱「MVP 三件絕對不能省的事」第②條就是「codec 是 TLV，且 v1 就含各段」。 v1 上線後補算力＝升版本＋既有分享碼要遷移。 動工前必改
052-D
元件負載與互斥		 元件面板 UI 依本計畫畫板：觸元件（青）／應元件（橙）分區、 候選清單保留裝不上的元件並寫出原因（武器類型不符／條件不成立），不直接濾掉。 「我的元件呢」比多幾列雜訊難處理得多；且總綱已警告不要做一個沒有 componentLimit gate 的面板。 動工時採用
052-E
雲端存檔與配額		 接手方案名稱的登入 gate：未登入可配裝／分享／匯出，但不能命名。 欄位由本計畫先落在 LoadoutDraft，gate 晚一步不影響資料形狀。 可延後
建議排程：本計畫排在 052-C 之前，或至少與 052-C 的 codec 設計同時進行。 兩個理由：① 算力段必須進 v1（上表第一列）； ② 052-C 會在同一頁加上分享列與書架面板，若等它做完再改視覺，等於同一頁改兩次版。
