◆ PLAN-022

數值引用層 · $1/%1 語法糖 · <refId.attr> token

讓描述內的層數／回合數綁定 buff/skill 屬性：維護者打 $1/%1、一鍵代入為 <refId.attr> token，前台解析顯示真值 —— 原文逐字還原、不限顯示次數、數字不再與 buff 屬性漂移。

📐 本計畫為 PLAN-019 實體引用層 的延伸：繼 [xxx] 實體引用之後的第二種 token —— 數值引用。驗收案例銜接 PLAN-021 的凝勢三階層數。

Problem
問題背景
同一個數字存在兩個地方，必然漂移
描述正文寫「可疊加7層」，但 buff_凝勢I.maxStack = 5 —— PLAN-021 驗收時實際抓到的真實 bug。 層數／回合數本質上是 buff 屬性（maxStack / duration）的影子，被以純文字重抄一遍； 兩份資料沒有任何機制保持同步，群友手動維護下漂移只是時間問題。
PLAN-021 的 ndVariants 讓抄寫量倍增
各算力階的改寫正文整段存（凝勢 I/II/III 三段），同一個層數被抄三次，漂移面積 ×3。
已否決的兩條路（演進脈絡）：
① chip 尾綴（[凝勢I] 後自動接「（可疊加5層）」）—— 結構上消滅重複，但使用者回饋希望盡可能還原遊戲原文，數字被搬離原位、且同 buff 多次出現只能標first occurrence，否決。
② token 化模板（PLAN-021 方案 D）—— 維護者要懂模板語法，負擔過高，早已否決。
本計畫是第三條路：原文逐字還原 + 數字自帶機器可讀的歸屬。
Design
設計決策
決策一：三層架構 —— 語法糖（編輯期）→ 正式 token（儲存）→ 解析值（顯示）
輸入：可疊加$1層 　→（按「代入數值」鈕編譯）→　儲存：可疊加<buff_凝勢I.maxStack>層 　→　顯示：可疊加5層 · 語法糖永不落地：$n（可疊加層數）/ %n（持續回合）只存在於編輯當下，按鈕當場編譯成正式 token 才儲存 —— 「編號對齊」的脆弱性被限制在編輯期。
· 正式 token 自描述：<refId.attr> 內含目標實體與屬性，每個 token 獨立解析、不靠出現位置與次數，不限顯示次數。
· 顯示讀真值：前台從 GameDataContext（PLAN-016 已全量預載）查 refId 取屬性值 —— 數字只有 buff 一份，7 vs 5 漂移結構性消失。
決策二：屬性註冊表（registry）承載一切擴展
語法糖符號、屬性標籤、適用實體類型、取值函式全部集中一張表；新增屬性 = 加一筆，挑選器按鈕、解析器、降級邏輯自動跟上。
// src/utils/numRefs.ts —— 單一資料源，所有層都從它驅動
const NUM_ATTRS = {
  maxStack: { sigil: '$', label: '可疊加層數', refTypes: ['buff'],         get: (e) => e.maxStack },
  duration: { sigil: '%', label: '持續回合',   refTypes: ['buff'],         get: (e) => e.duration },
  // 未來：cd: { label:'冷卻回合', refTypes:['skill'], get: e => e.cd } —— 低頻屬性可不配 sigil，走 UI 選單代入
}
語法糖符號是稀缺資源（$、% 之後難記），故僅高頻屬性配 sigil；低頻屬性走「選取數字 → 按鈕 → 下拉選屬性」的純 UI 路徑，registry 兩邊通吃。
決策三：接入點集中 —— 一個 util、三個樞紐，零逐頁實作（減少重複程式碼的核心）
天賦、技能、晶片驅動、武器、模組……全都要用，但不在任何頁面寫任何專屬程式碼。理由：站上描述的渲染與編輯本來就已收斂到少數樞紐 ——
層接入點（改一次）自動受惠範圍
核心邏輯src/utils/numRefs.ts（registry + resolveNumRefs() 純函式 + 語法糖編譯 + 殘留偵測）—— 唯一的真實實作，其他層只是呼叫
前台顯示RefText 解析迴圈加一種 token 分支PilotDetailPage（天賦/技能/神驅）、EntityRefView（引用浮卡）、WeaponSkillCard…所有用 RefText 的地方
差異高亮DiffHighlight base/enhanced 先過 resolveNumRefs 再 tokenize最大強化／專武強化／PLAN-021 神驅強化（5→7 照樣紅字高亮）
後台編輯RefPicker 加「代入數值」按鈕 + 儲存前殘留警告Pilot / Skill / Buff / Glossary / Module / Weapon / Backpack / Component 共 7+ 個後台分頁全部自動獲得
未來新增的任何實體後台，只要照慣例使用 RefPicker + RefText，數值引用天然可用，零新增程式碼。
決策四：編號規則與防呆
· $n/%n 的 n = 該 [xxx] 在描述中首次出現的順序（RefPicker 列表顯示編號供對照）；因語法糖即時編譯、不落地，順序只需在編輯當下成立。
· 「代入數值」按鈕先列出偵測結果與替換預覽再執行（防 %n 與百分比等誤判）。
· 儲存前掃描殘留語法糖，警告「尚有 N 個未代入的數值標記」。
· token 失效（buff 被刪/改 ID）→ 優雅降級：顯示暗色 ? 並 title 提示，比照 [xxx] 查無原樣顯示的慣例。
邊界：不是所有數字都該綁
「可疊加 5 層」是 buff 的 maxStack → 綁；「若攜帶 5 層及以上」「移除 5 層」是天賦的觸發/消耗門檻，不是實體屬性 → 留純文字。 綁定永遠是選用的，後台說明需講清楚這條判斷。
Scope
實作範圍與不在範圍內
在範圍內（第一批 · A+B+D 小步先行）：
  • src/utils/numRefs.ts：registry（maxStack / duration 起步）+ 解析 / 編譯 / 殘留偵測 + 單元測試
  • RefText / DiffHighlight 接入（含 EntityRefView 浮卡內的描述；解析需同時涵蓋 description 與 descriptionMax 兩版正文）
  • 驗收案例：凝勢三階（升級 PLAN-021 已 seed 的層數為 token；token 先由開發者手寫／seed 腳本生成）
  • docs 同步：引用層設計文件補「數值引用」一節
不在範圍內 / 延後：
  • Phase C（RefPicker「代入數值」$n/%n 語法糖 UI）→ 延後：語法糖的受眾是「大量抄寫原文的群友」，目前僅艾達一隻、受眾尚未出現。 PLAN-021 任務 3-1（PilotAdmin ndVariants 編輯器）已於 2026-06-12 提前完成且使用共用 RefPicker —— C 上線時編輯器自動獲得「代入數值」按鈕、無返工； 觸發條件＝群友開始自助維護 / 第二隻 ndVariants 機師出現
  • maxStack / duration 以外的屬性（cd / ap / 百分比類）→ registry 預留，依需求逐筆加
  • 失效 token 的後台稽核頁 → 顯示層先優雅降級，稽核列備選
  • PLAN-021 的基本顯示與驗收 → 不被本計畫阻塞，021 已以純文字數字完成端到端，022 上線後回頭升級
