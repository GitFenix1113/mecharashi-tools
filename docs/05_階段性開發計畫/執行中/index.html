PLAN-033 · 後台編輯視窗加寬

後台編輯彈窗固定 672px（AdminModal 的 max-w-2xl），12 個分頁中有 10 個共用這層殼；維護者只在 PC 上作業，等於為不存在的手機情境留白大半螢幕。高度早已是 max-h-[90vh]，問題純在寬度。但掃描後發現單純加寬是負優化——.input-field 為 width:100%，且 59 處格線有 58 處是固定欄數，多出的寬度會全變成胖輸入框，排數一排都沒少。故加寬（A）與格線改造（B）綁定交付。B 原訂用階梯式容器查詢，開工後改為 CSS auto-fill：階梯解不掉「欄位數本來就少」的區塊（射程頁只有 2 個欄位，再多斷點也排不滿），而 auto-fill 排不滿就留白、不把空間分給現有欄位；且它量的是元素自身寬度，窄版彈窗與巢狀卡片自動得到正確欄數，校準從「35 處各配階梯」簡化為調一個數字。過程中另拆掉一顆雷：容器查詢的 contain:layout 會使彈窗成為 position:fixed 子孫的 containing block，將打壞六個編輯器共用的 IconPicker 全螢幕浮層。寬度經互動示範實測由 80% 上修為 90vw。四個大編輯器的 Tab 版面重構（C）已納入範圍但延後。

PLAN-032 · 武器技能引用化

82 把武器內散落著 170 份技能拷貝，實際上只有 124 個相異技能（重複率 27.1%），而且已經開始漂移——「起爆」在凱旋·改與獵器上是同一個官方技能，文字卻一份補了 PLAN-019 方括號、一份沒有。本計畫沿用 PLAN-004 已驗證的漸進路徑（雙格式 union + 相容層 + 兩階段 flip），把武器技能收進既有技能庫共用。實測發現該集合早已不是「機師的技能」而是全站技能字典（84% 的 skill 引用目標無任何機師持有，維護者甚至已自行放入兩個武器技能），故不另開集合、改用 domain 欄位分類、後台同頁篩選。使用者可見行為完全不變，換來的是「改一處全站生效」。

PLAN-026 · 召喚單位展示

部分機師的特殊召喚單位（如薩普莉婭的咕咕）有自己的技能、型態與裝備，本質是「迷你機兵」。建立獨立 summons 集合並在機師頁以條件式分頁展示；同時新增 summon refType，讓天賦正文的 [咕咕] 接進 PLAN-019 引用層變成可懸停、可點開的實體。資料無外部來源，走後台手動維護。

PLAN-019 · 實體引用與模擬基礎（總綱）
