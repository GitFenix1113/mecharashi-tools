PLAN-042 · 機甲故事館

機甲的逸聞目前只是詳情頁最底下一個 <p>，整段長文擠在數值表格之後；而官方遊戲內的逸聞是分 PART 1 / PART 2 章節、穿插娜塔莉亞等 NPC 頭像旁白的敘事體驗。本計畫另開 /lore 獨立路由做成左文右繪的沉浸式故事館，並復刻官網那招「線稿顯影 → 彩圖疊上」的立繪切換動畫——已實測拆解官網為四層背景圖 + 錯位淡入（線稿領先彩圖 250ms）；本站沒有線稿素材，改以 color-dodge 素描濾鏡即時生成，實測幾乎重現官方質感（邊緣偵測法已驗證不堪用）。順帶補上全站不存在的 manufacturer 欄位，以及撐得起全高面板的全身立繪素材層（現有 portrait 僅 560×340 半身裁切）。
因故事資料需他人協助輸入，另含兩塊：新增 EDITOR 角色（現行規則下所有集合皆 read/write: if isAdmin()，給人 ADMIN 等於交出全站讀寫權；改以 affectedKeys().hasOnly() 把可寫範圍鎖死在故事三欄位，且刻意不給 read、編輯台讀取改走 Worker /api），以及靜態化出口（資料定稿後逐台切成 src/data/lore/ 零查詢，非全站一次切）。機師故事館與陣營勢力不在本期範圍。

PLAN-041 · 機師形態變化

調構師的四個形態（先鋒／突擊／戰術／虛粒子）其實已經有資料——四筆文件躺在 pilotSkills 的 710 筆裡、正文逐字完整，但實測 0 位機師的 skills 陣列引用它們，前台從建立到今天一次都沒顯示過。而 PilotSkill 型別裝不下形態真正需要的東西（武器限制、固定武裝鎖定、顯示順序、增益連結），現況已經在拿 skill.weapon.categories 硬撐。本計畫把四筆遷成獨立的 forms 集合、改掉 12 條 inbound 引用、蓋出條件式第 4 分頁與跨分頁常駐的「特殊能力」列，並順手拆掉 PLAN-019-B 那套 0 筆資料、從未渲染過、卻仍在後台誘導維護者建錯地方的 mutexGroup 引擎。42 筆「形態 × 武器 → 子技能」矩陣列為 N2，可延後。

PLAN-040 · 固定武裝

「無法更換的武器」目前在資料層根本不存在：帕斯卡兩個手臂模組的描述引用了［衝擊炮］，但 weapons 集合 169 筆裡沒有這把武器，引用層不檢查 refId 解不解析得到，於是 chip 照樣可點、點下去顯示「找不到對應資料」——今天就是壞的。彌造者的耀星／隕星／千星同樣 0/169，讓 PLAN-041 機師形態第一天就會卡在「無物可引」。本計畫只做武器層：補 WeaponType「特殊」與 WeaponKind「粒子莢艙／固定武裝」、建那 4 筆手工武器、加 badge 與篩選、並刪掉 0/62 從未被填且形狀錯誤（有肩背無手持）的三個機甲武器槽。武器技能連結刻意留給 PLAN-032，避免造出第二套詞彙。Phase A 另含四項與設計無關的資料衛生，其中一項修好模擬器讀不到彌造者帕姆斯陣列的斷鏈。

PLAN-038 · 社群連結預覽（Open Graph）系統

站長回報網站在 LINE 有連結預覽、Discord 完全沒有。診斷確認根因單一：index.html 沒有放任何 og:* 標籤——Discord 的爬蟲不執行 JS 也沒有 <title> fallback，找不到 og:title／og:image 就完全不顯示卡片；LINE 則退而求其次抓標題撐出陽春卡。分兩層修：Tier 1 補齊全站靜態標籤（可獨立上線）；Tier 2 延伸既有 Cloudflare Worker，用 HTMLRewriter 讓機師／機甲／武器詳情頁分享時顯示對應肖像與名稱。og:image 素材策略刻意重用既有實體圖片欄位，不另開一套美術維護線。

PLAN-032 · 武器技能引用化

82 把武器內散落著 170 份技能拷貝，實際上只有 124 個相異技能（重複率 27.1%），而且已經開始漂移——「起爆」在凱旋·改與獵器上是同一個官方技能，文字卻一份補了 PLAN-019 方括號、一份沒有。本計畫沿用 PLAN-004 已驗證的漸進路徑（雙格式 union + 相容層 + 兩階段 flip），把武器技能收進既有技能庫共用。實測發現該集合早已不是「機師的技能」而是全站技能字典（84% 的 skill 引用目標無任何機師持有，維護者甚至已自行放入兩個武器技能），故不另開集合、改用 domain 欄位分類、後台同頁篩選。使用者可見行為完全不變，換來的是「改一處全站生效」。
▸ 2026-08-07：Phase A 完成（M0 撞號防呆 / M1 型別與相容層 / M3 前台雙格式，另補計畫書漏列的引用掃描層站點）。下一步 M2 建 124 筆技能 doc。
