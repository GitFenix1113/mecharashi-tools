◆ PLAN-068

武器與技能射程範圍 · 官方格型 GridFormType · 選取／作用範圍

武器的射程與技能的範圍改用遊戲本身的「格型」描述：資料庫只存官方格型鍵，格子形狀與台版官方文字放在版控的對照表，前台畫出跟遊戲「當前技能」一樣的小格圖。

Problem
問題背景
一、站上的射程只有三種寫法，遊戲有 160 種
武器現在用 rangeType（manhattan／orthogonal／ring）＋minRange／maxRange 三欄、由管理者手選。 遊戲本身不用「最小／最大」描述攻擊，而是用 160 種格型（GridFormType：菱形、環狀菱形、方形、十字、直線、扇形、只有前方、選方向、全場…）， 每次攻擊都有兩個：選取範圍（能瞄準哪裡）與作用範圍（實際打到哪些格）。
二、站上 200 把武器：184 把對、16 把是「寫法裝不下」
與陸版 11-20 資料包逐把比對（以 gameRef.weaponInfoId 對照）：
武器站上官方
12 把電磁炮菱形 1–5選方向 → 直線 5 格全部命中
千星菱形 1–4選方向 → 扇形 4（遊戲截圖：由近到遠 3／5／7／9 格）
衝擊炮菱形 1–3選方向 → 直線 3 格
13 把火箭菱形 3–6選取對，但作用範圍是方形 1（3×3），站上沒記
嵐質儲能艙、多功能彈倉0–0（naStats）沒有攻擊技能，與現況一致
PLAN-040 決策十當時就判定「扇形」塞不進純量欄位，千星沿用 manhattan 並註明「此值已知不精確」；orthogonal 宣告了但 0 把使用。本計畫是那兩個懸案的正式處理。
三、技能完全沒有範圍資料
pilotSkills 926 份只有描述文字（例「對面前扇形4格範圍內所有目標」），使用者看不到格子圖，模擬器也無從判斷。 而且同一個指令技能，換裝不同種類的武器範圍就不同（例：虛粒子程式＝刀劍方形 1／機槍菱形 4／粒子莢艙扇形 4），描述文字無法表達。
四、射程加成對非菱形格型算不對
天賦的射程加成（EquipStat 的 maxRange）現在是直接加到數字上。官方是查表換格型： SkillRangeInfo.GridFormTypeTransformByAdditionalRange 規定「射程 +1 之後變成哪個格型」，方形、直線、扇形各有自己的鏈。
資料包裡有什麼（盤點結論）
來源內容
GridFormType（enums.json）160 種格型名稱
ConfigDataSkillRangeInfo（160 筆，ID＝格型）最小／最大選取距離、台版官方顯示文字（「3-6格」「環狀菱形3-6格」「直線5*1」「扇形4」）、射程 ±N 的格型轉換鏈
ConfigDataActiveSkillInfo（3,628 筆）GridSelectFormType＋GridEffectFormType；SkillFlag2_SelectFormFix／EffectFormFix＝不吃射程加成
ConfigDataWeaponInfo＋ConfigDataEquipmentTypeInfo武器普攻＝DefaultActiveSkill（502 筆覆寫），否則用武器種類的 DefaultAttackSkill
ConfigDataMainSkillInfo指令技能 → WeaponActiveSkillList[{type: 武器種類遮罩, Id}]，依武器種類對到不同主動技能
程式碼 BattleMapUtility格子實際形狀只在這裡（GetGridOffsetListByFormType＋14 個 Generate*＋靜態建構子），資料表沒有
台陸比對：站上相關的 495 個主動技能中，台版也有的 458 個格型差異 0。
Design
設計決策
決策一：資料庫只存官方格型鍵，形狀與文字放版控對照表
延續 PLAN-055／056「DB 只存官方 key」。鍵用格型英文名去掉前綴（'RingRhombus3to6'），後台與 Firestore 主控台看得懂；數字 ID 只留在對照表。 不擴充 rangeType（160 種開不完，PLAN-040 決策十的理由仍成立），也不把格子座標存進每份文件（格型是遊戲常數，存 DB 只會重複）。
// src/data/gridForms.json —— 腳本從資料包產生、進版控（A-1） { "RingRhombus3to6": { "id": 22, "min": 3, "max": 6, "selectLabel": "3-6格", "effectLabel": "環狀菱形3-6格", "plus": ["RingRhombus3to7", "RingRhombus3to8"], "minus": [...], "labelSource": "tw" } } // src/utils/gridForms.ts —— 由鍵名解析出形狀（A-2） export function gridFormCells(key: GridFormKey, dir?: Dir): [number, number][] | null // 未驗證的格型回 null // src/types/weapon.ts（B-1） attackForm?: { select: GridFormKey; effect: GridFormKey } // 普攻 // src/types/pilot.ts PilotSkill、backpackSkills（B-1） forms?: { kinds?: string[]; select: GridFormKey; effect: GridFormKey }[] // kinds 省略＝不分武器種類
決策二：形狀「名稱推導＋實機截圖驗證」，未驗證的不畫格子
站上實際會用到 31 種格型：23 種照名稱就能確定（菱形、環狀菱形、方形、十字、直線 N、全場、方向）； 8 種要驗證：Sector4（已由 2026-11-23 遊戲截圖驗證：3／5／7／9）、Sector3by5、Line1by3～Line5by3、BoundingSquare1。 還沒驗證的格型，前台只顯示官方文字、不畫格子——畫錯的圖比沒有圖更糟（同 PLAN-040 對 formatter fallback 的判斷）。 反組譯 BattleMapUtility 取得全部 160 種的精確形狀列為選配（A-4），工具鏈在資料包 傷害公式/原生反組譯 已有。
決策三：武器只存普攻一組
站上 200 把武器中，反擊／協力的格型與普攻相同（反擊 150、協力 170）或根本沒有（戰術類不能反擊）， 唯一例外是隕星（普攻菱形 4、反擊與協力菱形 3）。不為一把開欄位，例外寫進 description，匯入報告會再列一次。
決策四：技能依武器種類分列，自動回填只收唯一解
指令技能經 WeaponActiveSkillList 依武器種類（位元遮罩）展開；同格型的種類併成一列。 ⚠ 部分技能的 gameRef.mainSkillIds 是候選清單，會混進不相干的變體（萬序擬合推出 17 種形狀）—— 這類只列進報告的 ⬜ 清單交人工，不自動寫入。武器種類遮罩對站上 WeaponKind 的對照表放在匯入腳本，與 EquipmentTypeInfo 的 25 筆逐一對過。
決策五：舊三欄先保留，加漂移檢查
rangeType／minRange／maxRange 被篩選、模擬器、多支測試使用（18 個檔案、74 處），本計畫不拆。 新增 check-range-drift.mjs 比對 attackForm 與舊三欄，已知裝不下的 16 把列白名單； 前台全面改讀新欄位、穩定一段時間後，再決定舊三欄改由 attackForm 推導或刪除（F-4，記取 PLAN-058 的雙正本教訓）。
決策六：文字用台版官方繁中，形狀用陸版最新資料包
顯示文字取台版 SkillRangeInfo 的 StrKey；台版還沒有的新格型（陸版領先約 5 個月）用簡轉繁 s2t（不用 s2twp），對照表標 labelSource: "cn-s2t"，台版更新後覆蓋。 資料包落點沿用武裝討伐腳本的規則（兩種落點都認、取日期最新）。
決策七：例行流程不靠 AI
比照 PLAN-064：import-attack-forms.mjs 擷取過期會自己呼叫 extract-attack-forms.py，dry-run 報告附 ✅／⬜ 照抄清單； --write 只補空欄、附還原檔、寫完提示 bump。改版後的步驟補進 data-patch skill。
邊界情況
  • 方向型（Dir／EightDir）：選取是「選一個方向」，作用才是實際格子；前台以面朝上畫一個方向，其餘方向淡色。EightDir 的斜向直線會少 1 格（lineDiagRangeMinusOne，SkillFlag_IgnoreDiagRangeMinusOne 可關掉），驗證時要特別看。
  • 只有前方（…InFront）：站上目前沒有武器用到，技能有；按面朝上畫。
  • 不吃射程加成：SelectFormFix／EffectFormFix 的技能，F-1 套加成時要跳過；匯入時一併記在 forms 列上（欄位名 B-1 定）。
  • 沒有 gameRef 的技能：指令 69、主動 33、背包技能 52 份全部沒有——前兩者多是 EX 版等手建技能，交後台人工（E-3）；背包技能先查對照路徑（C-3）。
  • 形態武裝幽弧／夜燼的 type／kind 是空字串（gameRef 有值），匯入照常；種類空白是否刻意不在本計畫處理。

Scope
實作範圍與不在範圍內
在範圍內：
  • 160 種格型的對照表（台版官方文字＋射程加成轉換鏈）與站上用到 31 種的形狀
  • 武器普攻的選取／作用格型：200 把回填（預期 198 把有值）
  • 機師技能（指令、主動、額外打擊）與背包技能的範圍，依武器種類分列
  • 前台格圖元件與武器、技能、模擬器的顯示
  • 後台三個管理頁的格型選單
  • 天賦射程加成改走官方轉換鏈（模擬器顯示）
不在範圍內：
  • 戰場地圖上的實際判定（地形、高低差、飛行目標的 RaycastType）——那是傷害模擬（PLAN-065）的範疇
  • 被動技能、BUFF 本身的範圍（光環範圍 AdditionalAuraRangeAdd 等）；有需要另立案
  • 反擊／協力格型的獨立欄位（決策三）
  • 刪除舊三欄（F-4 只做決定，執行另議）
  • 敵人／首領技能範圍（武裝討伐頁之後若需要，沿用本計畫的元件即可）
