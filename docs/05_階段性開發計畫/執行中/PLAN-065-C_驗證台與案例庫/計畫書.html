◆ PLAN-065-C

驗證台與案例庫 管理者驗證台 · 實測對帳 · 私有案例庫

讓站長貼上配裝、選首領、輸入遊戲內實測，立刻看到引擎預測與誤差；對完帳的案例存進私有 repo，成為引擎每次改動都要通過的回歸測試。

Problem
問題背景
065-B 算得出數字，但還沒有被遊戲證明過
引擎 A 已上線，正確性目前只對過評估階段的原型與站上面板。要標成「已驗證」，必須拿遊戲內的實測逐擊對帳。
對帳現在全靠人工，也存不下來
截圖轉成數字、配裝轉成請求、預測與實測逐項比對，每一步都要開發者手動處理；對完的結果也沒有地方累積，引擎下次改動時無法自動確認沒有改壞。
Design
設計決策
文件政策
本計畫書與進度表公開在 /documents，只寫工作項目、介面與驗收；計算方式、規則、案例內容都在私有 repo mecharashi-sim。
決策一：驗證台放在站上後台，只給管理者
在 /admin 下新增一頁，沿用後台既有的登入與權限。頁面只負責輸入與顯示，計算與完整拆解一律由 Worker 回傳（總綱決策 C1：完整拆解只給管理者）。
決策二：管理者身分由 Worker 驗證
頁面帶上站上的登入憑證，Worker 驗證憑證真偽、再比對管理者允許名單；Worker 不讀資料庫、不持有任何金鑰（總綱決策 C3）。 沒有通過驗證的請求維持一般使用者的待遇。
決策三：公開程式碼不寫死拆解內容
驗證台以通用方式呈現 Worker 回傳的完整拆解，不在公開 repo 定義它的結構，避免從前端程式碼推回計算方式。
決策四：配裝轉請求、模擬 API 用戶端做成共用模組
065-D 的傷害模式會直接沿用，不必重寫。
決策五：案例庫只放私有 repo
驗證台匯出案例檔，放進私有 repo 後成為回歸測試；截圖與錄影不進任何 repo，留在站長本機。
決策六：以「確認攻擊」預覽為主要對帳依據
預覽沒有隨機成分，一張截圖就是一筆確定的樣本；實際跳字與部位分布作為輔助。
Scope
實作範圍與不在範圍內
在範圍內：
  • Worker 的管理者通道：驗證登入憑證、允許名單、管理者可取得完整拆解。
  • 公開 repo 共用模組：契約的公開型別、配裝轉請求、模擬 API 用戶端。
  • 後台驗證台頁：載入配裝與養成假設、選煉獄首領、輸入實測、看預測與誤差、匯出案例。
  • 私有 repo 的案例庫與回歸測試，以及首批實測入庫。
不在範圍內：
  • 對一般玩家開放的傷害模式（065-D）。
  • Buff 與條件效果的計算（065-E、065-F）；驗證台會把它們列為未計入。
  • 截圖自動辨識、錄影自動解析（數字由站長輸入）。
驗收
  • 管理者能在驗證台載入任一配裝、選任一煉獄首領，看到預測與完整拆解；未登入或非管理者拿不到完整拆解。
  • 輸入實測後自動算出逐項誤差；案例可以匯出，並在私有 repo 重跑。
  • 首批實測（第 1 週三關）入庫，單擊誤差達標或差異已歸因（列出未計入的來源）。
