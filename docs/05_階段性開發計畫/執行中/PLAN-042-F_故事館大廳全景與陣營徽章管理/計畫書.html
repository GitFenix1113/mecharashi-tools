Problem
問題背景
陣營徽章選圖器看不懂
編輯台的選圖器（FactionLogoPicker.tsx）每格圖只有 40px、底下只標 4 碼編號，也只能搜編號。全站與 DB 都沒有「徽章 → 陣營名」的資料——PLAN-059 決策六刻意不做陣營字典——唯一的線索是 10-01 素材盤點時看字樣猜的 8 筆（在 _local-notes）。 管理員看一眼也記不住哪顆是哪個陣營；截至 10-13 備份，92 位沒有任何一位選過徽章（PLAN-059 D-5 待開始），正是補上名稱的時機。
外觀的「全身立繪」看不到完整畫面
站上外觀是官方卡面 Raw（1240×1080）：13 套場景外觀四周有官方暈邊（鑑賞版 _Raw_view 只是收窄），其餘去背的造型會被畫布裁掉（卡夏的吊床，腳在右緣被切）。 遊戲大廳是執行時疊出來的——背景半幅 1024²×2、Spine 角色、前景道具，擺位在 Unity prefab 裡、沒有被擷取——擷取裡沒有單張 1920 寬的桌布。 唯一完整單張是造型預覽圖 Img_main_(Skin_)?<英文名>(_08)?_Raw（1056×594，ui_uiimages_uiskindisplay_abs.b），構圖與大廳一致：40 套外觀中 27 套有（13 套場景外觀全有），合計約 2.9 MB。
小 bug：彩色徽章在卷宗被裁成圓形
src/index.css:749 的 .lore-emb__ring img { border-radius:50%; object-fit:cover } 權重高過 Tailwind 的 .object-contain，彩色版 _01 的 <img> 被裁圓。
Design
設計決策
決策一（站長 2026-10-14）：大廳全景先用官方造型預覽圖
1056×594、27 套、約 2.9 MB，立刻可做。高解析版（背景半幅＋Spine 第 0 格＋道具逐套合成到 1920 寬）併入 Spine 計畫，等授權有結果後替換同一個檔位（_lobby），前台不必再改。 卡面去背與否是官方逐套決定的（卡夏去背、阿黛勒帶背景），資料看不出規則。
決策二（站長 2026-10-14，同日修訂）：鑑賞框預設立繪、可切到大廳全景
站長原則：靜態立繪優先，大廳全景只是補充（最初選「預設全景」，補充說明後改判）。有大廳全景的外觀，鑑賞框上方出現「立繪｜大廳全景」切換、預設立繪；沒有的 13 套維持原樣。 起因是阿黛勒這類場景外觀的官方卡面連背景一起畫、站上沒有去背的靜態立繪——真正的解法是 Spine 骨架渲染的去背全身圖（13 套場景外觀都有，卡在 Spine Editor 授權，見 Spine 計畫），大廳全景是過渡。 1056 寬在 1080p 螢幕已放大約 1.65 倍，全景模式要限制最大顯示尺寸（暫定原寸 1.5 倍、實作時目測調整），點擊放大改為上限原寸 2 倍或停用。
決策三（設計）：檔名、對照表、部署層級
預覽圖存 pilots/<gameId>/skins/<artKey>_lobby.webp——衍生檔名，與 _Raw_view 同一套處理（classifyPilotFile 刻意認不得、索引另查）。 外觀 → 預覽圖沒有官方設定表，寫在 scripts/lib/pilotSkinMeta.json 的 lobby 欄（值＝預覽圖官方檔名），--skins 讀取。只看英文名會錯兩處： 奧菲利亞的大廳屬於 Pilot_10103134C（不是 B）；RosaDiaz 屬於 Pilot_10103154C（洛莎·審判外觀 C，不是 10103107 洛莎）； Img_main_Skin_Rosa_08 屬於 Pilot_10103154B（站長 10-14 確認：預覽戴眼罩，154B＝預設 154A 加眼罩、像素差 0.7）。 部署：這 27 張升級為上站（依 10-12「劇透不是顧慮」）；NPC 圖庫的 2 套外觀沒有預覽圖。
決策四（站長 2026-10-14，修訂 PLAN-059 決策六）：替「徽章本身」做註記，不替陣營文字做字典
每個編號存：名稱、圖上字樣、選填對應的陣營文字（機師 faction 的原字串，可多筆）、備註。 對應的陣營文字只用來把建議排到最前面；每位機師的徽章仍由管理員逐位點選，不自動寫入 pilotLore。 決策六擔心的是「替站長決定誰跟誰算同一個陣營」——註記由管理員在後台維護，判斷權仍在管理者手上，只是讓選圖器看得懂。
決策五（站長 2026-10-14）：預填 6 筆字樣可辨識的
0012 黑曜石集團（OBSIDIAN）、0009 電鰻傭兵團（EELS）、0031 盧諾家族（LUNO）、0033 NERV、0034 多瑙河公司（DONAU）、0025 晨星同盟防衛軍（DAWNSTAR LEAGUE ARMORED FORCE）。 0021（多爾集團？D 字）、0038（創界山？雲中塔）名稱留空、只寫進備註當線索。對應的陣營文字不預填。
決策六（設計）：新集合 factionEmblems，不進引用掃描
文件 ID＝4 碼編號（0025），單色／彩色兩個變體共用一份註記。不登記進 entityRefs SPECS（註記不引用別人、也不被 EntityRef 引用）→ 不連動級聯刪除與引用掃描，規則晚部署也不會弄壞既有的刪除功能。 其餘連動照 PLAN-042-A 清單：collectionKeys、GameDataContext、Worker ARRAY_COLLECTIONS、bump-data-version.mjs 的 KNOWN_KEYS、firestore.rules（讀 isAdmin()、前台走 Worker）、api 模組＋barrel、測試 helper。 部署順序：rules → Worker → 網站。
決策七（設計）：選圖器與前台
選圖器：圖 88px、卡片標名稱與字樣、單色／彩色兩顆按鈕；可用名稱／字樣／編號搜尋；排序為「建議（對應文字命中，或同陣營機師已選）→ 已命名 → 未命名」，未命名卡片標「未命名」、照樣可選。 卷宗前台的徽章提示（title／aria）改用徽章名稱，沒有名稱才退回機師陣營文字；順手修裁圓 bug。
Scope
實作範圍與不在範圍內
在範圍內：
  • 27 套大廳全景：對照表、--skins 匯入 _lobby、索引旗標、鑑賞框切換
  • factionEmblems 集合與連動、6 筆預填（data-patch 流程）

  • 高解析大廳合成（併入 Spine 計畫，等授權）
  • 正規化 pilots.faction／正式的陣營集合（日後陣營有機制作用時另議）
  • 館首頁「依陣營」分組（PLAN-059 提案的後續，等多數機師選好徽章）
  • 沒有預覽圖的 13 套外觀（官方沒有）
