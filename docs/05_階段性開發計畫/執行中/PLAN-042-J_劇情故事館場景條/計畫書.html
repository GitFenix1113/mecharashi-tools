Problem
問題背景
只有字、沒有場景
遊戲裡每段過場都有背景畫面：基地、酒店廢墟、夢境，對白就疊在畫面上。站上只留下文字，讀者不知道「現在在哪裡」， 場景切換（從會議室到戰場、從現實到夢境）全靠台詞去猜。PLAN-042-I 解決了「跳關疲勞」，觀賞感則是這一案的目標。
場景資料其實都在，只是沒人接
對白表每一行都記著背景 ID：ConfigDataDialogueInfo.Background → ConfigDataBackgroundInfo.ResPath（例 13_ABS/P001_Raw） → 圖集 ui_uiimages_uidialogpic_13_abs.b 裡的 P001_Raw（1920×592 橫幅）。台版解包 E:\Mecharashi_data_TW 裡 140 張全在。
全館 43 本（2026-11-28 重跑匯入）數值
過場段落有場景的779／787 段（99%）
要插的定場鏡頭1,123 處，用到 130 張不同的 CG

Design
設計決策
決策一：書檔只記「換場景的點」，不逐行存背景
StoryPart.shots: [行索引, key][]，行索引含戰中的 null 分隔，一段過場通常一兩筆。收斂規則寫在匯入腳本：
  • 同一張不重插；過場裡沒有圖的行（黑幕轉場、prefab 背景）沿用前一張。
  • 戰鬥中沒有圖＝回到戰場，下一張 CG 會重新定場；戰鬥段落前後都歸零，所以結尾過場一定重新定場。
  • 沒有戰鬥段落的關，開場與結尾同一張就不重插。
前台照 shots 插圖、不必知道規則；之後要調規則只改腳本、重跑 --write。
決策二：圖片沿用 PLAN-054 的官方檔名慣例，放 public/images/game/story/
官方檔名逐字＋.webp（q82、原尺寸 1920×592），扁平放一層。140 張不同名；哪天兩個圖集出現同名的圖，匯入腳本直接中止、不會默默覆蓋。 只收 1920×592：圖集裡另有 64² 黑底、340² 道具圖、1841×740 與 1024² 各一張，混進來會破壞橫幅比例。 區域地圖是 2048² 的整張世界地圖，前台只露一條，匯入時就裁成 1920×420 的衍生檔 <官方檔名>_strip.webp（取中段偏上）。 這個資料夾不列入後台選圖器的 manifest.json（同 game/icons、game/npc）。gh-pages 約 509 → 528 MB／1 GB。
決策三：插在對白之間的橫幅，不做滿版背景
滿版背景會把圖壓在字底下，正好重演 PLAN-042-I 才解掉的「底圖干擾閱讀」。所以換場景時在那一行前插一張橫幅（定場鏡頭），文字永遠在乾淨的紙面上。 圖片 lazy 載入、固定比例（不會載入完才把文字往下推）、載入失敗整格收掉；淡入動畫在 prefers-reduced-motion 下關掉。 圖後的第一句一律重新報名字（換了場景，該重新交代是誰在說）。圖是裝飾，alt=""＋aria-hidden，不打擾螢幕閱讀器。
決策四：主線的戰鬥段落用區域地圖當底
20 章核對過，每章的節點都落在同一個區域，所以地圖記在書上（StoryBook.map／region），戰鬥段落開頭放一條「戰場 · 帕黎爾沙漠」。 戰鬥段第一行本身就有 CG（戰中過場）時不再疊地圖。活動與機師回憶沒有區域，不放。
決策五：「場景圖」可以關掉，偏好只存本機
想專心讀字、或手機流量吃緊的人可以關掉。開關放在關卡標頭右側（桌機、手機都看得到），偏好存 localStorage 的 mecharashi_story_scenes， 讀寫包 try/catch，讀不到就當預設「開」。
決策六：沒有解包圖片的電腦也能跑匯入
匯入腳本找不到 完整資源_* 時，站上已經有的圖照用、缺的就不插，書檔不會指到不存在的圖；報告列 ⬜ 照抄清單。 storyData.test.ts 另外擋「shots 指到不存在的圖」，萬一手動改壞了 build 前就會知道。
Scope
實作範圍與不在範圍內
在範圍內：
  • import-story.mjs：每行記背景、收斂成 shots；主線書加 map／region；--write 轉檔匯出用到的 CG 與地圖，報告附照抄清單
  • 重跑匯入（43 本），圖片放進 public/images/game/story/；manifest 排除；public/images/game/README.md 記錄
  • 前台：型別、storyScenes.ts（圖片網址與偏好）、StoryLines 插定場鏡頭、戰場地圖、場景圖開關、CSS
  • 測試：shots 合法（索引在範圍內、指到真的對白行、遞增、相鄰不重複）、圖都在
  • 文件：故事館頁面規劃、更新履歷、PLAN-042 總綱子計畫表
不在範圍內：
  • 說話者頭像（方案 C 的另一半）：資料鏈已驗證（Left/RightCharImageId → ConfigDataCharacterPicture.Icon → 站上既有頭像，有名字的台詞 96.8% 對得到）， 但要逐行存頭像鍵（書檔會再大一截）、還要處理缺圖的 5 個角色。站長要做時另開子計畫。
  • 方案 B 選章舞台：章節代表圖可以直接從本案匯入的 CG 挑，評估報告已有自動挑選規則。
  • 活動專屬的 prefab 型背景（PlotActivityAVGUIPrefab_*）：由好幾張介面圖組成，要另外盤點活動美術。
