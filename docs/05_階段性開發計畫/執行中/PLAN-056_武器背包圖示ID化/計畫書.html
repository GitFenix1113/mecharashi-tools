◆ PLAN-056

武器／背包圖示 ID 化官方編號 gameId · 圖庫 · 選圖器 · WebP

武器和背包的圖示早就用官方檔名，但沒有官方 ID 欄位。有 5 筆鍵名是猜的或用中文佔位，12 把武器沒有圖（多半是固定武裝，而且左右肩是兩張鏡像圖），還有 66 張官方圖沒用到，管理者也看不到。本計畫比照機師、機甲，給武器和背包一個官方編號 gameId，把官方圖併進 PLAN-055 的扁平圖庫並轉成 WebP（體積 −83%），選圖器加上武器／背包分頁，讓管理者直接從「未使用」裡挑。

Problem
問題背景

以下數字來自 2026-10-09 盤點：陸版客戶端擷取（E:\Mecharashi_Data 圖片索引）、正式站備份 2026-10-05_db-backup-1559、public/images/{weapons,backpacks} 三方逐張比對。 完整報告在 _local-notes/2026-10/2026-10-09_武器背包圖示盤點/武器圖示全盤點.html。

問題一：沒有官方 ID，而且有 5 筆鍵名是猜的
  • 爬蟲時代下載的 96 張（2026-05-20，PLAN-003）鍵名來自官方 API。站上 101 張裡有 97 張與擷取逐像素一致。
  • 之後手動建檔的 5 把出了問題：影虎嘯、斷湮、輝龍刀用中文佔位檔名；HMG-29C 的 20400502、笑謊者的 10200402 是猜的編號。 圖本身是對的，但官方檔名其實是 20400501、10200501。10200402 是同一造型的灰色版，不是笑謊者。
  • 機師、機甲在 PLAN-054 已經有 gameId。武器、背包沒有，要跟擷取、公告或下一批新擷取對照，只能比名字或路徑字串。
問題二：12 把武器沒有圖示，資料模型也放不下「左右肩兩張圖」
  • 3 把機甲固定武裝：帕斯卡的衝擊炮、破曉者-01 的嵐質儲能艙、霸王的多功能彈倉。
  • 5 把形態武裝：海莉絲虛粒子形態的耀星、隕星、千星，曜巡航形態的幽弧、夜燼。
  • 4 把新專武：征伐、速射格林炮、誓殮、歸零協議。
  • 固定武裝在遊戲裡左右肩是兩張鏡像圖。遊戲截圖比對結果：左肩＝…01、右肩＝…02（霸王、破曉者-01 兩台一致）。但 Weapon.icon 只有一格。
問題三：管理者看不到哪些官方圖還沒用
  • 官方武器圖 163 張、背包 24 張，站上只用了 97＋17 張。沒用到的 66 張武器圖裡，有新專武的圖、形態素材、機甲綁定的肩部。
  • 後台的武器／背包還在用舊 IconPicker：只能挑資料夾、打檔名，看不到哪些沒用過、誰在用，也不能以圖搜圖。 PLAN-055 已經替技能類圖示做好整套選圖器，武器、背包沒有接上。
問題四：PNG 太重
圖示只顯示 32–64px（WeaponIcon 為 w-8～w-16），檔案卻是 340² 的 PNG，平均約 100 KB。 武器 101 張共 9.93 MB、背包 17 張 1.95 MB；轉成 WebP（q82、原尺寸）後分別是 1.66 MB、0.30 MB。背包頁和模擬器的選單一次就列幾十把。

Design
設計決策
和 PLAN-055 同一條管線，只多了兩個分頁。讀取端先切（A），DB 回填（C）只是整理，不是有沒有圖的前提
決策一：武器、背包加 gameId，存官方圖示編號
  • 值是 Icon_weapon_<gameId>／Icon_backpack_<gameId> 的編號部分，例如 '20300501'、'10700301A'、'60350101'。 和機甲的 gameId（取自 Icon_mecha_wap<編號>）同一個來源，都是從官方圖示檔名取號。
  • ⚠ 這是「外觀編號」，不是武器的身分：EX、·改、·LW 和同一機師的二階專武，都跟本體共用同一個號碼（凱旋系 4 把共用 10200301）。 所以不能當主鍵，也不能拿來判斷「是不是同一把」。這和 PLAN-055「圖示不等於技能」是同一個原則。
  • 大小寫例外（Icon_BackPack_ 2 個）照官方檔名逐字存。gameId 換算檔名時，例外由匯入腳本產生的對照表處理，程式裡不寫死。
決策二：圖庫併進 PLAN-055 的 game/icons/，轉 WebP
  • 落點：public/images/game/icons/weapon/、public/images/game/icons/backpack/，官方檔名逐字。 索引、以圖搜圖、反查、ledger 退場都直接沿用 PLAN-055，選圖器只是多兩個分頁。
  • 改判 PLAN-055 決策一的但書（「武器、背包不動」）。當時不動的理由是它們沒有重複問題，這點仍然成立。 但現在需要「未使用」清單、以圖搜圖和官方編號，這三樣只有進圖庫才拿得到。
  • 格式用 WebP q82、原尺寸 340²，不用 PLAN-055 的 lossless：技能圖示是邊緣銳利的符號，武器是 3D 渲染圖，用 lossless 體積會大好幾倍。 實測武器 −83%、背包 −85%。
決策三：收錄範圍，官方圖全收（博物館原則）
  • 武器 163 張、背包 24 張全部入庫，包括外型變化 _b、虛粒子形態左右手素材、空手圖、機甲綁定肩部。這些都是站長確認要「上傳備用」的。
  • 400x 敵方 BOSS 裝備（28 張）也入庫（✅ 2026-10-09 站長定案：「收，資料多只有好處」）：總共不到 1 MB，日後做 BOSS 頁時用得到。 選圖器在「主序列」以外的群組預設收起，平常不會干擾挑圖。
  • 依據 PLAN-055 決策三的前例：圖示不含名字、立繪或文字，所以入庫「台版還沒有的武器圖」不算洩漏未上線內容。
  • 非官方的觀察寫在 註記檔（沿用 scripts/lib/gameIconMeta.json），例如「10601301 空手」「10700501_b 外型變化」，選圖器上會顯示。 資料本身不加分類欄位，因為官方沒有文件。
決策四：DB 以 gameId 為主，icon 只留給自訂圖；固定武裝加左右兩張圖（2026-10-09 實作時改成 gameId 優先，見下）
interface Weapon { /** 官方圖示編號（Icon_weapon_<gameId>）。外觀編號，EX／改 共用，不是武器身分 */ gameId?: string /** 固定武裝左右肩的鏡像圖（官方：左＝…01、右＝…02）。有給 side 時優先用它 */ sideGameIds?: { left?: string; right?: string } /** 自訂圖（站長編輯過、不是官方原檔）的路徑；只在沒有 gameId 時才會用到 */ icon?: string } interface Backpack { gameId?: string; icon?: string }
  • 讀取順序：左右肩圖（有 side 時）→ gameId 圖庫 → icon 原路徑 → icon 檔名對到的圖庫。 gameId 有值就用官方圖，自訂圖只用在沒有官方圖的武器（規劃時寫「自訂圖優先」；實作時改掉，因為過渡期 icon 還存著舊路徑， 分不出哪個是自訂圖、哪個是舊值。笑謊者的舊值 10200402 若排在 gameId 前面，就會顯示成灰色版）。
  • icon 的原路徑排在「檔名對到的圖庫」之前，也是同一個理由：回填 gameId 之前，猜錯的編號要先吃原檔。舊檔退場後原路徑 404，自然退到圖庫。
  • C 階段回填完 gameId 後，官方圖的 icon 舊路徑全部清掉，icon 只剩自訂圖。 這樣兩個欄位不會各存一份同樣的東西、日後各改各的。
  • 左右圖放在武器上，不放在機甲的 MechPart.fixedArmament 掛載點上：鏡像圖是武器本身的屬性，不會因為裝在哪台機甲而改變。 形態武裝的左右手本來就是兩把不同的武器（耀星在右、隕星在左），不需要這個欄位。
決策五：選圖器沿用 GameIconPicker，加武器、背包分頁
  • 篩選：種類（由前綴解析，例如 102 打樁機）× 群組（主序列／機甲綁定肩部／敵方 BOSS／字尾變體）× 使用狀態（未使用／已使用）。
  • 預設只顯示主序列，依編號倒序排列。新專武會落在「既有系列的新變體」，所以挑「未使用＋同種類」就只剩幾張。
  • 反查「誰在用」：純函式掃後台已載入的 weapons／backpacks（gameId、sideGameIds、icon），不增加 Firestore 讀取。
  • 以圖搜圖沿用 PLAN-055 B-4：貼上遊戲截圖就排出最像的官方圖。這次補定風波、笑謊者就是用截圖比對完成的。
  • WeaponAdmin／BackpackAdmin：官方圖改用 GameIconField，寫入 gameId。自訂圖保留舊 IconField，只開 weapons/ 自製圖資料夾。 固定武裝顯示「左肩／右肩」兩格。
決策六：自訂圖放 public/images/weapons/
舊的官方 PNG 退場後，weapons/ 只剩站長自己編輯的圖（目前預計只有耀星、隕星兩張）。 game/ 底下只放官方原檔（PLAN-054 的規則），所以自製圖不能放進圖庫，也不能冒用官方檔名。 檔名用武器文件 ID 之類可讀的名字，由引用掃描器列管。
決策七：社群預覽與舊圖退場沿用既有機制
  • Worker 的 buildOgMeta('weapons') 改成「gameId 推路徑 → icon」。圖庫是 WebP，連結預覽器多半不吃 WebP， 所以 generate-og-entity-images.mjs 的 SOURCES 要加上 game/icons/weapon，產出 JPEG 鏡射（透明背景已有 flatten 處理）。Worker 由站長部署。
  • 退場順序同 PLAN-055 決策九：讀取端先切 → 守門測試通過 → check-image-refs.mjs 回報現役舊路徑引用為 0 → 刪除 repo 內舊 PNG 並部署 → gh-pages ledger 寬限 → Cloudflare Purge。
  • patchVersions／grayOps 存有圖片路徑快照（PLAN-054 的教訓），C 階段要一起改寫。
邊界情況與已知例外
  • 編號前綴不是鐵則：碎狼牙（電鋸）用 50100602、罪棘律典（電磁炮）用 10600402。 放大比對後，前者是 Z15 電鋸的換色版，後者是草莓通心粉電磁炮的換色版。也就是官方檔名本身交叉了，站上的圖是對的，不要「修正」。 選圖器的種類篩選因此只能當縮小範圍用，不能拿來擋選擇。
  • SS 專武的圖示系列不一定跟父武器同系列（42 筆中只有 15 筆相同），不能用 upgrade.fromWeaponId 推圖。
  • 夜魘·改Ⅱ／Ⅲ 用的是馬克的 20100301，夜魘本體卻是 20100401——✅ 站長 2026-10-10 確認沒錯，有些武器本來就長一樣。 v3.0 之後人工建檔的資料全部正確，往後不再檢查老武器的圖；只有站上自行去背的圖可以換成官方原圖。
  • 沒有官方圖的武器留空（資料佔位慣例、PLAN-055 決策八）。前台顯示「武」字佔位，不再做中文截圖佔位。歸零協議在這批擷取裡找不到任何未用的火箭圖，可能就是這種情況。

Scope
實作範圍與不在範圍內
在範圍內：
  • 匯入武器 163、背包 24 張官方圖到 game/icons/{weapon,backpack}/（WebP），命名規則、索引、註記檔、以圖搜圖特徵。
  • 型別：Weapon.gameId／sideGameIds、Backpack.gameId，icon 改為自訂圖；同步 docs 資料模型頁。
  • 讀取 helper 與約 12 個讀圖元件改走候選鏈；固定武裝依左右肩顯示鏡像圖。
  • 選圖器加武器／背包分頁、反查；WeaponAdmin／BackpackAdmin 改用新欄位。
  • 資料：回填 gameId、5 筆修正、固定武裝與千星、站長選的新專武；清掉官方圖的舊路徑；改寫 patchVersions／grayOps 快照；bump。
  • 社群預覽 Worker 與 JPEG 鏡射；舊 PNG 退場。
不在範圍內：
  • 武器技能圖示（weapons.skills[]、pilotSkills）：屬於 PLAN-055。
  • 機甲部件、機師立繪：屬於 PLAN-054。
  • 敵方 BOSS 頁：本計畫只把 400x 圖收進圖庫，不做頁面。
  • 建檔台版還沒有的武器（例如 10100101 對應的 B 級拳套）：等台版上線再由後台人工建檔（CLAUDE.md 6.5）。
  • 不動用備用爬蟲補資料（CLAUDE.md 6.5）。
