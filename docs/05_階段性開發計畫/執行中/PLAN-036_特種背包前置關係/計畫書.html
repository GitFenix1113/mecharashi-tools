◆ PLAN-036

特種背包前置關係 · SS 前置主背包 · 依前置種類篩選 · 後台手輸

SS 特種背包由「圖紙＋前置主背包＋複合背包/專武＋任意 3 個 S」製作。記錄無法 derive 的「前置主背包」，讓背包圖鑑能依前置背包種類篩選，並在後台手動輸入。啟用 PLAN-035 決策六（背包合成關係鏈）的第一步。

立案背景（2026-07-25，站長於背包製作頁提出）：SS 特種背包（如征服者背包）在遊戲【特種背包製作】台是由一份固定配方合成的，其中有一顆「前置主背包」。站長希望背包圖鑑能依前置背包的種類篩選、後台能手動輸入這份關聯，查不到前置就先不顯示。本計畫是 PLAN-035 決策六（背包合成關係鏈）明確分流出來的第一步。
Problem
問題背景
問題：SS 的「前置主背包」無法 derive，目前完全沒有資料
PLAN-035 的階層/軸都能從 rarity＋名字 derive，但 SS 特種背包的前置主背包是製作台的配方事實（征服者背包 ← 某顆前置背包），名字裡沒有這個關聯（「征服者」不含前置背包的任何字樣）。Backpack 型別目前也沒有承載它的欄位，因此無從篩選、無從呈現。
【站長確認】特種背包製作配方是固定的，只有兩種形態：
// 形態一：特種背包（產物是 SS 背包，存 backpacks）← 本計畫範圍 圖紙 + 前置主背包 + 複合背包(S+) + 任意 3 個 S 級背包 // 形態二：特種背包武器（產物是武器，如裁決者，存 weapons）← PLAN-031 已涵蓋 圖紙 + 前置主背包 + 專武(SS) + 任意 3 個 S 級背包
· 圖紙來源是武裝討伐；圖紙的製作材料本計畫先跳過，統一顯示為「{背包名}設計圖」（如「征服者背包設計圖」），未來另做武裝討伐資料庫時再補。
· 任意 3 個 S 級背包是萬用材料，非特定，不需存（顯示為固定文案）。
· 形態二的產物是武器（裁決者等），已由 PLAN-031 的 weapon.upgrade 涵蓋，不在本計畫。
Design
設計決策
決策一：只存「前置主背包 id」一個變動事實，其餘全 derive/固定文案
沿用 PLAN-031「只存事實、不存可推導值」哲學。新增 Backpack.craft?，僅一個必填欄位：
// src/types/backpack.ts export interface BackpackCraft { /** 前置主背包 doc id（specific，後台手輸）。種類/線/變體皆由此 id 查表 derive，不存冗餘。 */ prereqBackpackId: string } // Backpack 增 craft?: BackpackCraft（僅 SS 特種背包會有值）
圖紙＝derive（name + '設計圖'）；前置背包的「種類」＝查 prereqBackpackId 取其 type；任意 3 個 S＝固定文案。複合背包(S+) 核心材料本階段先不存（見不在範圍）。
決策二：背包圖鑑新增「前置背包種類」篩選，未設關聯者在此 facet 下隱藏
在 BackpacksPage 加一個 facet：依前置主背包的 type（出力/移動/誘導…）篩 SS 特種背包。 優雅降級此 facet 啟用時，只顯示有 craft.prereqBackpackId 且能查到前置背包的 SS 條目；查不到關聯的 SS（尚未輸入）先不顯示（站長明確要求）。與 PLAN-035 階層/軸、PLAN-031 特種背包製作 facet 正交共存。
決策三：後台 BackpackEditPanel 對 SS 加「前置主背包」下拉
僅 rarity === 'SS' 時顯示此欄；選項＝ useGameData().backpacks 全清單（ensureLoaded(['backpacks'])），排除自己與其他 SS（前置主背包是較低階背包）。存檔走既有 updateBackpack（自動 bumpDataVersion('backpacks')）＋ patchCollectionItem 就地同步。手輸即生效，不需 migrate 腳本。
決策四（邊界）：craft 是選填、非破壞；stripUndefined 相容
非 SS 背包不寫 craft；未輸入的 SS 也維持無 craft。updateBackpack 走 stripUndefined + 整份 setDoc，編輯既有 SS 時務必保留其它欄位（現有 admin 已是整份 form 存回，安全）。前台對無 craft 的 SS 一律當「未關聯」處理，不報錯。
決策五（延伸，本計畫不做）：完整配方呈現與形態二
完整配方顯示（設計圖＋前置主背包＋複合背包(S+) 核心材料＋任意 3 個 S）需要背包詳情頁或更豐富的浮窗，且要存 S+ 核心材料 id；形態二（特種背包武器的前置主背包）與 PLAN-031 重疊；圖紙材料來源需武裝討伐資料庫。三者皆列後續，待本計畫的前置主背包上線、確認需求後再評估。
Scope
實作範圍與不在範圍內
在範圍內：
  • Backpack.craft?: { prereqBackpackId } 型別（僅 SS 用）
  • 後台 BackpackEditPanel：SS 專屬「前置主背包」下拉（挑非 SS 背包）
  • 背包圖鑑「前置背包種類」facet：依前置 type 篩 SS、未關聯者隱藏（優雅降級）
  • backpackClassify：加 prereqBackpackType(bp, byId) 純函式（查表 derive）
  • 浮窗/卡片顯示「{名}設計圖」與「衍生自 前置主背包」（純文字/連結，視前置有無）
  • docs 資料模型同步 + siteChangelog（手輸即 bump，無 migrate 腳本）
不在範圍內：
  • 完整配方呈現與存 複合背包(S+) 核心材料 id（決策五，另評估）
  • 形態二（特種背包武器的前置主背包）——產物是武器，與 PLAN-031 重疊
  • 圖紙材料來源（武裝討伐資料庫）——站長明確先跳過
  • 批次回填腳本——資料由後台逐筆手輸（updateBackpack 自動 bump）
