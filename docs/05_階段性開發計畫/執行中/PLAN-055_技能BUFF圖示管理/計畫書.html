◆ PLAN-055

技能／BUFF 圖示管理扁平圖庫 · 選圖器改版 · DB 只存 key · BUFF 字形

官方把圖示的分類全寫在檔名裡，站上卻又按「用在哪」分了一次資料夾。結果同一張圖存了好幾份，選圖器又只能用數字檔名找。本計畫照官方的放法，建一個一張圖只存一份的圖庫，選圖器改成用形狀、色系、名字來找，DB 只存官方檔名。BUFF 第一次有圖示。

Problem
問題背景
問題一：選圖器只認數字檔名，圖示找不到
後台的 IconPicker（src/components/admin/IconPicker.tsx）只能先挑資料夾、再打檔名子字串。 但檔名是 Icon_skill_passive_5227 這種純數字，沒人記得住。「全部資料夾」模式要先打字，結果上限 500 筆，縮圖只有 48px。 也不能用技能名或機師名找，看不到「這張圖誰在用」。新角色建檔時，只能在上千張裡用肉眼找。
問題二：同一張圖存了好幾份
站上按「用在哪」分資料夾：skills/ 底下 6 個中文子夾、modules/、components/、backpacks_skills/， 另外 pilot_forms/ 也有一份。這幾個夾共 1,674 個檔，實際只有 1,219 種圖。 其中 391 個檔名跨資料夾重複，用 cmp 比對全部位元組相同，有 5 張在四個資料夾裡都有。 根本原因是「用途」本來就是多對多：同一張被動圖可以同時是技能、模組、元件、背包技能和形態的圖，用資料夾表達用途一定會重複。
問題三：DB 寫法不一，還有副本（2026-10-03 正式站備份實測）
  • 圖示值有 4 種寫法：裸 key、扁平路徑、子資料夾路徑、完整路徑。內嵌的 WeaponSkill 還存了官方 CDN 的遠端 URL。
  • pilotSkills 同時存 icon（裸 key）和 iconLocal（路徑），其中 197 筆只有路徑。104 個 key 在 DB 裡被 2～5 種不同的資料夾路徑引用。
  • 3,239 個扁平路徑要靠 normalizeSkillPath() 推回子資料夾才解析得到（src/utils/assets.ts）。
  • pilots.neuralDrive.levels[] 裡嵌了 1,578 份 skillIcon／iconLocal 副本，其中 9 位手建機師共 115 份是空值。 不過 PilotDetailPage.tsx:829 早就改成優先讀 neuralDriveAbilities 字典，這些副本實際上沒人在用。
  • 還有 37 個中文佔位 key（例如 Icon_skill_passive_凱登01）。10-01 盤點已經逐張目視，全部對到官方鍵名。
問題四：BUFF 沒有圖示
型別已經預留欄位：GameBuff.icon、BuffLevel.icon（src/types/buff.ts:94,104）。但 233 筆裡沒有一筆有值，也沒有 BUFF 圖庫。 BuffAdmin 的選圖器預設開的是技能夾，各等級的 BuffLevel.icon 也沒有編輯欄位。 前台唯一預留的顯示點是引用浮窗（EntityRefView.tsx:145），但目前什麼都顯示不出來。
其實官方有一套很整齊的分類，全部寫在檔名裡（陸版擷取＋正式站備份交叉驗證，2026-10-04）
Icon_skill_前綴passive種類 → 外框形狀_5色系3批次／世代02流水號
  • 種類決定外框形狀：main 主動▲、order 指令■、passive 被動●、talent 天賦◆；pp 是青綠色水滴，右下有 P。
  • 首位數決定色系： 1 紅（攻擊） 2 藍（防禦） 3 綠（修理） 4 金（暴擊／AP） 5 紫（機制）。 主色相吻合 802／806 張。括號裡的功能是對照技能描述歸納出來的，官方沒有文件。
  • 9xxx 是聯動：第 2～3 碼代表角色，95 虎王、96 戰部渡、97 零、98 真嗣、99 明日香。
  • 流水號照建檔順序往後加：天賦紫系從洛莎 5110（v1.0）一路排到貝爾莎 5163（v3.2），v3.3～3.4 的四位新機師是 5164～5167 連號。 所以新角色的圖一定落在各序列的尾端。
  • 官方把技能、模組詞條（Icon_entry_*）、研發（Icon_RnD_*）全部放在同一個資料夾 uiicons/skilltype_abs，只靠檔名區分。 BUFF 是另一套：127 個白色單色字形，打包成一張圖集（bufftype_abs），顏色是遊戲執行時才套上去的。
  • ⚠ 圖示不等於技能：同一張圖常被多個技能共用，例如 main_1106 同時是乘勝追擊、崩山、拘敵猛襲的圖。這和 PLAN-032 的實測結論一致，所以圖示只代表外觀，不能拿來當主鍵或推導技能。
Design
設計決策
檔案線與資料線在讀取端匯流。讀取端以檔名解析，所以 DB 遷移（C）只是整理，不是有沒有圖的前提
決策一：官方檔名就是分類，圖庫扁平，一張圖只存一份
  • 落點分兩個資料夾：
    • public/images/game/icons/skill/<官方檔名>.webp：收官方 skilltype_abs 整夾，包含技能、模組詞條、研發、指揮官技能。
    • public/images/game/icons/buff/<官方檔名>.webp：收 Icon_buff_*、Icon_debuff_*。
    和 PLAN-054 的 game/ 放在一起，匯入、索引、ledger 退場三套機制都直接沿用。
  • 不再按用途分資料夾。「這張圖誰在用」改由反查回答（決策五）。反查是從資料算出來的，比資料夾更精確，也不會跟資料脫節。
  • 改判 PLAN-043 決策五（背包技能圖獨立成 skills/背包技能/，當初「維護者明示接受重複，換取分得清來源」）。 實測那 19 張與被動夾的檔案位元組完全相同，獨立資料夾並沒有保存任何不同的東西，「分得清來源」改由反查提供。 站長 2026-10-05 立案時同意改採扁平圖庫的管理方式。
  • 武器 Icon_weapon_* 和背包 Icon_backpack_* 不動：它們已經是一夾一份、官方檔名，沒有重複問題。
    ⟶ 2026-10-09 由 PLAN-056 改判：「沒有重複」仍成立，但「未使用」清單、以圖搜圖、官方編號 gameId 都只有進圖庫才拿得到，所以武器、背包也收進 game/icons/{weapon,backpack}/。
決策二：來源取聯集，以官方擷取為準，舊圖不丟（博物館原則）
來源數量處理
陸版擷取 skilltype_abs（Texture2D）1,137 個檔名全收
陸版擷取 bufftype_abs（Sprite）127全收。同一張圖集裡另有 9 個職業小圖示，不在本計畫範圍
站上舊夾有、擷取裡沒有的官方檔名254全收，索引標 legacy。多半是官方 CDN 的舊版圖示，其中 26 個仍被 DB 引用
兩邊都有925918 張像素相同、4 張近似、3 張不同（passive_1180／5302／5304，站上那 3 張是 .webp）。以擷取為準，A-3 報告附前後對照給站長看
站上中文檔名40不收。DB 裡的 37 個中文 key 在 C-1 換成官方 key
  • 同名且內容相同就去重。擷取內同名但 sha256 不同時，中止並回報，不猜（沿用 PLAN-054 決策四）。
  • 格式用 WebP。圖示最大 128px、邊緣銳利，預設用 lossless；體積在 A-3 實測，預估全庫小於 5 MB。舊夾退場後，總量會比現在小。
  • Windows 不分大小寫、GitHub Pages 分大小寫，所以匯入前先以小寫做碰撞檢查。
決策三：擷取裡有、站上沒有的 212 張要不要部署（✅ 2026-10-06 站長定案：全部上線）
  • 建議全部部署。選圖器就是它們的使用者：新角色建檔時最需要的，正是各序列尾端還沒用過的圖。 圖示是抽象符號，不含名字、立繪或文字，跟 PLAN-054 擋下的 NPC 立繪、造型不是同一個等級的劇透。
  • 風險：其中被動 53xx 有 25 張站上還沒用到，可能屬於台版尚未上線的角色。別人看得出「有新東西」，但看不出是誰。
  • 替代方案：只部署站上已經有的那些，其餘放 repo 外的封存夾，需要時用 --key 單張升級。代價是新角色上線時得先跑腳本，才選得到圖。
決策四：讀取端以「檔名即 key」解析，舊路徑立刻對到新圖庫
  • 新增 helper gameIconCandidates(value)。不管傳進來的是裸 key、扁平路徑、子夾路徑、完整路徑還是遠端 URL，都取檔名當 key： 第一候選是新圖庫路徑，第二候選是原值（經過 normalizeSkillPath）。交給 FallbackImage 逐張試。
  • 效果：讀取端一切換（A-6），全站圖示就改讀新圖庫，不必先改 DB。DB 遷移（C）因此只是整理，不影響有沒有圖。 刻意永久保留的爬蟲原始資料也不必改寫，靠檔名照樣解析得到：weapons.skills[] 的內嵌 WeaponSkill（PLAN-032）、pilots.biometicComputer 快照。
  • SkillIcon 現在只吃單一路徑，載不到就直接顯示「?」。改成走候選鏈；全部失敗時仍顯示「?」方塊，維持整排文字對齊。
  • 命名規則只寫一份：scripts/lib/gameIconKinds.mjs 給 Node 腳本用，src/utils/gameIcons.ts 給前台用，兩份由測試交叉比對（照 gameAssetKinds 的慣例）。
決策五：選圖器改版：用官方文法篩、用名字找、最新的排前面
  • 新元件 GameIconPicker／GameIconField（src/components/admin/）只負責圖示。舊 IconPicker 留給立繪、武器、背包、機甲這些其他圖。
  • 篩選：種類（形狀）× 色系 × 使用狀態（未使用／已使用）。搜尋：編號、技能名、持有者名稱。
  • 預設依流水號倒序：新角色的圖一定在序列尾端，所以會排在最前面。新版本建檔時，候選會從約 1,400 張縮到十幾張。
  • 反查「誰在用」：用純函式掃後台已經載入的遊戲資料（GameDataContext 快取），不增加 Firestore 讀取。滑鼠移到圖上時顯示「已被 N 處使用：○○・○○、模組・○○」。
  • 同一張圖只出現一次；縮圖 80～96px，滑過放大到 128px。寫回的值是裸 key，不是路徑。
  • 索引：public/images/game/icons/index.json 在 build／predev 時產生，選圖器開啟時才 lazy fetch，不進前台 bundle。 前台顯示不需要它，因為 key 推路徑是確定的。manifest.json 排除 game/icons/，免得舊選圖器又多列一千多張。
  • 色系的功能說明只是介面標籤：放在一份常數裡，不寫進資料當分類欄位，因為官方沒有文件。

  • 37 個中文 key 換成官方 key，對照表用 10-01 盤點 §7.1（43 張已逐張目視，1 張改採次佳候選）。
  • 流程走 data-patch skill：備份 → dry-run → --apply → 寫在腳本裡的 bump。型別變動依 CLAUDE.md 規則 2 同步 docs。
  • 要記住的是 key 只代表外觀。技能之間的關聯仍然靠文件 ID 與名稱，不靠圖示（PLAN-032、PLAN-043 的結論）。
決策七：BUFF 圖示用官方白色字形＋CSS 上色
  • 官方的 127 個字形：
    • 通用增益 8 個（buff_attack／avoid／critical／defence／hit／link／move／recover）。
    • 通用減益 10 個（同一個字形加一道斜線，debuff_*）。
    • 資源與屬性 1xxx、控制與異常 2xxx、修理 3xxx。
    • 角色或機制專屬徽記 4001～4064。
    • 層數數字 5000～5009。
  • 新增 <BuffGlyph>：用 CSS mask-image 套字形，顏色走主題 token。極性由 buffType 推：statBoost 是增益、debuff 是減益、state 是狀態、resource 是資源。 一張字形可以同時服務增益和減益兩種顏色，和遊戲的做法相同。
  • 233 筆要做一次對照，因為官方沒有對照表：
    1. 腳本依 buffType 與描述關鍵字給建議（例如命中→hit、暴擊→critical）。
    2. 產出 _local-notes/ 審核表。
    3. 站長確認後寫入。
    角色專屬狀態從 4xxx 一對一指定。拿不準的就留空，補值等於編造（資料佔位慣例）。
  • 層數數字 5000～5009 不用，層數改用 CSS 文字顯示。
  • 顯示點：引用浮窗（EntityRefView 已預留 lv?.icon || b.icon）與 BuffAdmin 列表。
決策八：沒有新擷取時，新角色的圖示怎麼辦（✅ 2026-10-06 站長定案：留空，沒有的圖就沒有）
  • 有新擷取：跑 import-game-assets.mjs --icons，只加新 key、既有的跳過，再更新索引。新圖會自然出現在選圖器「未使用・最新」的最前面。
  • 沒有新擷取時，建議留空：前台顯示「?」方塊，掃描器列出「缺圖示」清單，等下次擷取再補。這也符合資料佔位慣例：拿不到官方圖就不要自己生一個。 不再做中文截圖佔位，那 37 個中文 key 就是這樣來的。
  • 替代方案：允許暫代截圖，放在 game/icons/interim/，key 加 Interim_ 前綴，由掃描器列管；拿到擷取後用以圖搜圖（B-4）換掉。
  • 不主動動用 scrape-skill-icons.mjs，CLAUDE.md 6.5 已把它列為備用爬蟲。要動用時注意它會把圖寫回舊資料夾，這條會寫進 6.5 的隱患清單（E-3）。
決策九：舊資料夾退場：讀取端先切、掃描器守門、ledger 寬限
  • 退場對象：
    • skills/ 的 6 個子夾（1,088 檔）。
    • modules/ 裡的 Icon_skill_*／Icon_entry_*（530）。
    • components/ 根目錄的 Icon_*（55；OuterFrame/ 與 Stage*_Boss/ 不動）。
    • backpacks_skills/、pilot_forms/。
    • normalizeSkillPath() 與 SKILL_PREFIX_FOLDERS。
  • 刪除條件，依序：
    1. 讀取端切換完成，守門測試通過（A-7）。
    2. check-image-refs.mjs 回報的現役舊夾引用為 0。爬蟲原始快照靠檔名解析，列為允許。
    3. 刪除 repo 裡的檔案並部署。
    4. ledger 寬限 14 天後，從 gh-pages 移除。
  • 快取：新檔名不需要 Purge。DB 改寫後要 bump 該集合的版本。
Scope
