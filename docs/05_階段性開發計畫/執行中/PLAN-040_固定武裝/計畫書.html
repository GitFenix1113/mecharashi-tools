◆ PLAN-040

固定武裝 · Fixed Armament · 資料衛生 · 死槽位清除

把「無法更換的武器」建成真正的武器文件，修好帕斯卡今天就壞著的引用，並清掉三個從未被填過的機甲武器槽。同時作為 PLAN-041 機師形態的前置。

本計畫的定位
這是「機師形態變化」拆出來的第一塊。形態設計（forms 集合、條件式分頁）留給 PLAN-041； 本計畫只處理武器層——因為固定武裝這個概念在沒有形態的情況下也必須成立（帕斯卡沒有形態、沒有調構師、也沒有綁定機師，但它有固定武裝）。
刻意先做的理由：PLAN-041 的 Form.restrict.fixedArmament.weaponIds 要指的耀星／隕星／千星，今天在 weapons 集合是 0/169，形態計畫第一天就會卡在「無物可引」。 而本計畫無爭議、無阻塞，且順手修好帕斯卡今天就壞著的懸空引用。
Problem
問題背景
問題一：帕斯卡的 [衝擊炮] 引用今天就是壞的
mod_帕斯卡_fixed_2（彙編矩陣）與 mod_帕斯卡_fixed_3（深採模型）的描述逐字為 「固定裝備[衝擊炮]，可使用[退敵激波]；同時攜帶兩門[衝擊炮]時，可使用[浪潮來襲]」， 但 weapons 集合 169 筆裡沒有衝擊炮。
而懸空引用不會靜默降級成純文字：引用層只檢查 token 在不在 refs、不檢查 refId 解不解析得到 → chip 照樣渲染成可點擊的彩色底線，點下去顯示「找不到對應資料」。
問題二：彌造者的三把固定武裝完全不存在，擋住 PLAN-041
耀星／隕星／千星在 weapons 集合 0/169。 這三把是海莉絲［虛粒子形態］唯一能使用的武裝（官方形態卡逐字：「無法變更武裝和技能」）， PLAN-041 的 fixedArmament 分支沒有它們就建不出來。
問題三：Mech 的三個武器槽是形狀錯誤的死欄位
leftShoulderSlot / rightShoulderSlot / backSlot（src/types/mech.ts:56-62） 實測 0/62 台機甲有填，唯一消費端是 MechAdmin.tsx:552-554 的 SlotEditor（前台從不讀）。
而且它的形狀本身就錯：只有肩、背，沒有手持 → 帕斯卡的衝擊炮（肩部）勉強塞得下， 但彌造者的耀星／隕星（手持）一個都表達不了。留著它等於留一個會誘導人填錯的空殼。
問題四：moduleFixedIds 有 6 筆斷鏈，其中一筆讓模擬器讀不到帕姆斯陣列
mech_052_彌造者 的 moduleFixedIds 只有 ["sub_mod_火力模組"]， 漏收了 mod_彌造者_fixed_1（帕姆斯陣列）——那是海莉絲唯一的形態強化模組，圖鑑看得到、模擬器看不到。 另有復仇女神 fixed_1..4、星夜女神 fixed_1 同樣漏收，以及 3 筆 boundPart 存成純字串 "torso" 而非 ["torso"]。
校驗腳本必須 slot-scoped（實測數字）
naive 全掃「每個有 boundMechId 的模組是否都在該機甲的 moduleFixedIds 裡」會跑出 115 筆， 其中 109 筆是誤報——主模組（mod_2xxx）與通用模組（mod_3xxx）本來就不屬於固定模組槽。 真正的斷鏈只有 *_fixed_* 那 6 筆。
Design
設計決策
決策一：Weapon 只加兩個選填欄位，不動既有語意
// src/types/weapon.ts export interface Weapon { // …既有欄位 /** * [固定武裝]：無法更換的武器（帕斯卡的衝擊炮、彌造者的耀星/隕星/千星）。 * 純粹供 badge 渲染 + 篩選，不編碼「來源」。 * * ⚠ 命名刻意避開既有的 fixedMod（:96「固定改裝」）—— * 同一個 interface 上同時有 fixed(固定武裝) 與 fixedMod(固定改裝) 是維護地雷。 * ⚠ 【不要】複用 isExclusive(:90) / exclusiveFor(:91)：那是「機師專武、可選裝、SS、強化天賦」， * 與固定武裝「強制、鎖死、無法更換」語意相反；且 exclusiveFor 被 useFirestore.ts 與 * PilotsPage.tsx 當「機師→專武」索引消費，塞進去會被渲染成金框專武， * 並破壞 isExclusive ⇔ rarity === 'SS' 的既有不變式。 */ isFixedArmament?: boolean /** * 手建文件保護旗標。官方 API/WIKI 無這四筆資料、100% 手動維護。 * weapon.ts 是唯一缺此旗標的主要型別（對照 mech.ts:75 / pilot.ts:40）。 */ manual?: boolean }
決策二：enum 要補三個值（依遊戲內截圖）
現行 WeaponType 只有 4 值、WeaponKind 17 值，四把固定武裝有兩把落在外面：
武器官方 type / kind裝配位置現況
耀星格鬥 / 刀劍手持 → singleHandenum 已有
隕星突擊 / 機槍手持 → singleHandenum 已有
千星戰術 / 粒子莢艙背部 → backkind 要新增
衝擊炮特殊 / 固定武裝肩部 → shouldertype + kind 都要新增
WeaponEquipSlot 現有四值（singleHand / dualHand / shoulder / back）完全夠用，不動。
決策二的連帶效應（必須寫進 PLAN-041，否則三個月後會被推翻）
PLAN-041 的核心論證之一是「三個戰鬥形態的『只能裝備 X 武器』把 WeaponType 做成無重疊無遺漏的 partition （先鋒=格鬥+射擊 / 突擊=突擊 / 戰術=戰術）」。
一旦 WeaponType 多了「特殊」，這個 partition 就不再完整。 正確的表述是：「特殊／固定武裝不參與形態的武器過濾——因為固定武裝本來就無法更換，過濾器對它沒有意義」。 這句話必須逐字寫進 PLAN-041 的設計決策，不能只留在這裡。
決策三：武器不認識任何人——箭頭永遠是 來源 → weapon
固定武裝在遊戲裡有兩種完全不同的來源，本計畫刻意都不編碼在武器身上：
案例來源DB 表達
帕斯卡 · 衝擊炮 部件（手臂）：裝上帕斯卡的手臂，肩上就一定有衝擊炮 已可表達：mod_帕斯卡_fixed_2/_3 的 boundPart: ["rightArm"]/["leftArm"] + 描述引用 → 本計畫只補 descriptionRefs
彌造者 · 耀星/隕星/千星 機師形態：來自海莉絲的［虛粒子形態］，不是機甲底盤屬性 今天無法表達 → 留給 PLAN-041 的 Form.restrict.fixedArmament.weaponIds
因此「由模組 derive 掉 fixedArmament」的構想證偽：彌造者除了帕姆斯陣列（boundPart: torso）之外沒有任何固定模組， 那三把武器沒有模組來源。兩案確實是不同機制，形態端仍必須自己存 weaponIds。
副作用（刻意）：武器完全不認識形態 → PLAN-040 可以在 PLAN-041 還在設計時就先上線。這條箭頭是兩案解耦的唯一機制。
決策四：明確不做的三件事，各附理由
  • 不加 Weapon.fixedFor：「哪台機甲 × 哪個部位」已由 Module.boundMechId + boundPart 正確編碼，再存一次就是第三套真相源。且 scalar 表達不了帕斯卡「同一把 × 左右兩臂」。
  • 不加 Mech.fixedWeapons[]：(a) 幫不到彌造者——虛粒子形態是機師天賦狀態，不是底盤屬性；(b) 第三次重複編碼 boundMechId/boundPart；(c) 彌造者 lore 逐字寫「通用武裝接口使得該機不僅可以兼容多型常規武裝」，底盤明講可換常規武裝。
  • 不做武器技能連結：見決策五。
決策五：固定武裝自帶的技能留給 PLAN-032，本計畫不碰
截圖顯示固定武裝有自己的技能卡：千星 →［虛粒子矩陣］（指令 · 4AP · 冷卻 0）、衝擊炮 →［退敵激波］（指令 · 1AP · 冷卻 0）。 這正是執行中的 PLAN-032「武器技能引用化」的用例，而 PLAN-032 目前 0/8 全待開始。
本計畫不在 Weapon 上開任何技能欄位——避免造出第二套詞彙、之後被 PLAN-032 收編時重做。 代價（誠實）：固定武裝的卡片初期沒有技能區塊。這是可接受的，因為技能本身（skill_虛粒子矩陣 等）已存在於 pilotSkills，只是還沒掛到武器上。
決策六：三個死武器槽刪除而不是保留
Mech.leftShoulderSlot / rightShoulderSlot / backSlot 實測 0/62、前台零消費端、且形狀表達不了手持武器。 保留它會讓「機甲有固定武器」出現第二套表達方式，與 Module.boundPart 直接衝突。
一併刪除 MechAdmin.tsx 的武器槽分頁與 SlotEditor 元件。
建檔的資料誠實性：截圖數值不能照抄
遊戲內武器卡的「命中 / 暴擊」是套用機師屬性後的結果（三把彌造者武器的暴擊都是 4603，明顯來自機師）， 「攻擊」也是滿級強化後的觀測值。
→ 建檔時只填能確定為武器固有的欄位：type / kind / equipSlot / hitCount（×6、×10、×1）/ 射程 / 彈量 / 重量 / 描述 / 圖示。 攻擊力等成長數值標註為「滿級觀測值，待官方資料校正」，不要假裝它是基礎值。
Scope
實作範圍與不在範圍內
在範圍內：
  • Phase A 資料衛生：修 6 筆 moduleFixedIds 斷鏈、3 筆 boundPart 型別違規、寫 slot-scoped 校驗腳本、修全庫僅存的 3 條懸空引用
  • Phase B 型別：Weapon +2 欄、WeaponType +「特殊」、WeaponKind +「粒子莢艙」「固定武裝」、同步硬編碼清單
  • Phase C 建檔：4 筆固定武裝武器文件（全部 manual: true）+ 補帕斯卡兩個模組的 descriptionRefs
  • Phase D 前台：[固定武裝] badge、武器圖鑑篩選、機甲詳情頁固定武裝區塊
  • Phase E 清理：刪三個死武器槽 + MechAdmin 分頁 + SlotEditor，bump 版本
  • Phase F：docs 同步 + 網站更新履歷
不在範圍內：
  • forms 集合、機師形態分頁、形態武器過濾 → PLAN-041
  • 武器 → 技能的引用連結（千星的［虛粒子矩陣］、衝擊炮的［退敵激波］）→ PLAN-032
  • 模擬器的固定武裝 gate：模擬器是無回合模型的配裝器，且 Build.weaponId 是單值 string；形態獨立配裝（海莉絲三套裝備）是 breaking change，延後
  • 42 筆「形態 × 武器種類 → 子技能」矩陣 → PLAN-041 第二階段
  • 建立非 EX 基礎版技能：skill_虛粒子刃 / 炮 / 矩陣 已存在於 pilotSkills（710 筆），無須新建
Acceptance
驗收條件

  • 耀星 / 隕星 / 千星 / 衝擊炮 四筆在武器圖鑑可搜尋、可篩選，且帶 [固定武裝] badge
  • slot-scoped 校驗腳本輸出 0 筆 斷鏈（naive 全掃的 115 筆誤報不計）
  • 全庫懸空引用從 3 條降到 0 條（且動工後不得增加）
  • 模擬器讀得到彌造者的帕姆斯陣列
  • leftShoulderSlot / rightShoulderSlot / backSlot 三個識別字已從 codebase 完全消失
  • npm run build 通過；四個異動集合（weapons / modules / mechs / glossaryTerms）版本已 bump
