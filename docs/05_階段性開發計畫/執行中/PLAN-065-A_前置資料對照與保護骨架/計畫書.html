Problem
問題背景
引擎吃的是遊戲 ID，站上沒有存
站上的 gameId 是圖片／圖示編號（PLAN-054／056），不是遊戲設定表的記錄 ID，不能當身分；武器最缺。 天賦、神經驅動槽位、技能掛載層的 ID 可以由身分鍵推導，不必存。
人工效果欄位從未被填，卻還開放輸入
效果數值全庫 0 筆；保留輸入口只會讓兩套數值來源將來打架。
保護的不可逆前提
public repo 一旦 commit 就永久公開；私有 repo 必須在第一行模擬程式之前存在，契約與 Worker 骨架也要先就位。
Design
設計決策
文件政策：本計畫書會公開
docs/05_階段性開發計畫 會被 copy-docs 發布到 /documents，repo 也是 PUBLIC。所以 PLAN-065 系列只寫工作項目、介面結構與驗收方式； 傷害公式、條件判斷規則、實測數值與預測值一律放私有 repo mecharashi-sim 的 docs/，以及站長本機的評估報告（_local-notes/2026-10/2026-10-25_傷害模擬計算機_初步評估.html）。 審 PR 時若在 public 檔案看到公式、常數或判斷規則，一律退回。
決策一：統一用 gameRef 物件存遊戲身分鍵
每個集合一個選填物件欄位，只存推不出來的鍵：機師 pilotInfoId、機甲 suitId、武器 weaponInfoId、模組 entryId／itemId、 元件 weaponEntryId、背包 backpackInfoId、技能 mainSkillIds[]／passiveSkillIds[]、形態 passiveSkillId。 不改 doc id（分享碼依賴）、不改 gameId（圖片依賴）。天賦、神驅槽位、掛載層 ID 由引擎推導、不寫回。
決策二：對照規則在私有 repo，寫入腳本在公開 repo
「怎麼從設定表挑對記錄」屬於要保護的對照規則：由私有 repo 的 pipeline 讀本機資料包，產生 gameref-proposals.json（每筆附分類：唯一／等價／待確認）。 公開 repo 的 scripts/backfill-game-join-keys.mjs 只負責把建議寫進 Firestore：依 data-patch 流程備份 → dry-run 報告（附 ✅／⬜ 照抄清單）→ --write → bump 版本。 例行檢查（改版後身分鍵是否仍存在、有無漂移、有無新實體沒對照）也在私有 pipeline，報告附照抄清單，站長不靠 AI 也能跑。
決策三：「未連結」要看得見
後台各實體頁顯示唯讀「遊戲 ID」與「未連結」標示；回填報告與例行檢查列出缺 gameRef 的可上配裝實體，必須補上或列入白名單。
決策四：凍結人工效果，不刪資料
後台停用效果數值的輸入（改成說明「數值由遊戲資料帶出」）；型別保留並標 deprecated，前台讀取與顯示照舊。
決策五：Worker 骨架先只回版本
/sim/v1/ping 回傳 engineVersion／dataVersion；附 kill switch。部署由站長手動 wrangler deploy，並量測啟動時間與延遲，作為 065-B 的基準。
Scope
實作範圍與不在範圍內
在範圍內：
  • 私有 repo 骨架、契約 v1（正本在私有 repo）、ping Worker。
  • 8 種實體的 gameRef 型別、資料模型文件同步、回填腳本與報告、後台唯讀顯示。
  • 凍結人工效果輸入；PLAN-001 決策一加註。
  • workerData.ts 遇 429／暫時性錯誤時退避重試。
不在範圍內：
  • 任何傷害計算（065-B 起）。
  • 後台存檔時對照資料包驗證（瀏覽器端沒有資料包，改由例行檢查負責）。
  • 配裝頁拆檔（移到 065-D 開頭）。
驗收
  • 可上配裝的機師、機甲、武器、模組、元件、背包全部有 gameRef，或列在白名單並註明原因。
  • /simulator、圖鑑與後台行為不變；舊分享碼照常解碼。
  • npm run build、npm test、npm run lint 全綠。
  • /sim/v1/ping 部署後可回應，量測數字記錄在私有 repo。
  • public repo 中找不到傷害公式與判斷規則。
