◆ PLAN-058

描述欄位單一正本模組 · BUFF · levels[] 為正本 · 頂層鏡像

模組與 BUFF 的「頂層描述」和「各等級描述」是兩個都能手動編輯的位置，卻沒有規定誰是正本，前台又各讀各的。本計畫把各等級定為唯一正本：模組頂層改由程式在存檔時鏡像 LV.MAX，分級 BUFF 的頂層改為選填的「通用說明」。

Problem
問題背景
同一句效果描述存了兩份，沒有人知道該改哪一份
模組的「效果描述（滿等效果）」是早期還沒分等級時的設計；後來加了 levels[]，兩邊並列成同等的可編輯欄位。 後台說明還寫錯了：ModuleAdmin 說頂層「會直接顯示在前台模組卡片上」，實際上模組卡顯示的是等級描述。 BUFF 的慣例又剛好相反——分級 BUFF 的頂層多半是空的。
前台各讀各的，修正只修到一邊
模組卡、模擬器讀等級描述；模組引用浮窗、形態卡反查、圖鑑「搜能力」讀頂層。等級描述沒有批次修改的工具，修一個詞要改 4–8 次，於是只改了頂層： 燎原模組頂層補了 [燃燒地形]，LV1–8 全缺；殘心芯片、迷光驅動器頂層補了 [百分比耐久扣除]，各等級都沒有——模組卡顯示的正是缺字版。

Design
設計決策
決策一：各等級描述是唯一正本
人只編輯各等級。所有修正都落在等級上，頂層不再是第二個輸入口。
決策二：模組頂層＝LV.MAX 的鏡像，由程式在存檔時寫入（不刪欄位）
頂層 description 與 32 個數值欄位在存檔時由 syncModuleTopFromMaxLevel() 從 LV.MAX 複製。 讀頂層的前台點（引用浮窗、形態卡、圖鑑搜尋、後台列表）、entityRefs 掃描、cascadeDelete 與型別都不必改。 代價是 DB 仍存一份副本，但沒有人能手動改它，因此不會再漂移。「基本屬性」「武器增傷」兩分頁拿掉。
決策三：頂層 descriptionRefs 保留，改稱「共用引用表」
1,182 個模組等級段落中有 1,062 個沒有自己的引用表，靠頂層回退。它其實是各等級共用的引用表，不能拿掉。 共用引用表的「改 key／語法糖」改寫改成套用到所有等級（原本只改頂層，等級會殘留舊 key）。
決策四：分級 BUFF 的頂層＝「通用說明」（選填、不寫數字）
BUFF 的頂層和模組不同，它有自己的用途：未指定等級的引用與形態卡才顯示它，所以不做鏡像。 留空時前台改列各級（Lv1／Lv2…），30 筆空白不必人工補。後台依是否分級切換欄位標籤，並對「通用說明含數字」「與某一級完全相同」給軟警示。 等級引用表未自填時回退頂層，與模組、背包技能一致（原本 BUFF 不回退，和後台註解矛盾）。
決策五：「只有某機師能發動」由 unlockCondition 表達，不寫進正文
觀星者單元、帕姆斯陣列的「※只有[曜]／[海莉絲]能發動此模組※」從正文移除，模組卡改顯示 unlockCondition 標籤（復仇女神四顆「需〈迸發模組〉滿級」同時受惠）。
順序：先把頂層較正確的內容搬進各等級，再跑鏡像
鏡像會用 LV.MAX 蓋掉頂層。殘心、迷光、燎原三筆是頂層較正確；攻堅、原點核心、帕姆斯陣列、觀星者是頂層有排版。這些都必須先寫進等級，否則修正會被蓋掉。 形態卡用換行把模組正文切成「一行一形態」，帕姆斯陣列與觀星者的換行若沒搬進 LV.MAX，鏡像後形態卡會整段顯示。
個案裁決（站長，2026-10-13，依遊戲內截圖）
  • 殘心芯片、迷光驅動器：所有等級都是 [固定傷害][百分比耐久扣除]
  • 燎原模組：所有等級都是「場上每有1格友方[燃燒地形]」
  • 警戒模組：維持原樣（LV8 本來就正確）
  • 觀星者單元：照建議——套用頂層排版、移除 ※ 行；「和／與」取「和」（LV1 與頂層一致）
  • BUFF：幹勁、情報、被命中概率提升清空頂層；失穩改 termRef: term_失穩
  • 掠食 LV1 無資料：未裁決，不動
Scope
實作範圍與不在範圍內
在範圍內：
  • 模組後台：存檔鏡像、頂層描述唯讀預覽、共用引用表、拿掉頂層數值分頁、「套用到所有等級」文字取代、新增等級預帶上一級描述
  • BUFF：描述解析 helper（前台浮窗、形態卡共用）、後台欄位語意與等級描述 RefPicker
  • 模組卡顯示 unlockCondition
  • 一次性資料修正與鏡像搬遷（備份 → dry-run → 寫入 → bump）
  • 唯讀稽核腳本 scripts/check-description-drift.mjs（照抄清單式輸出，站長可自行跑）
  • 資料模型與資料庫設計文件的欄位語意
不在範圍內：
  • 刪除模組頂層欄位本身（鏡像後已無漂移風險，日後要刪只剩機械替換）
  • BUFF 等級的結構化數值（描述寫「可疊加3層」但 maxStack 空白之類）——另一筆技術債
  • 背包技能的同型問題（未盤點）
  • 模組名稱與遊戲不符（遊戲為「殘心晶片」，站上為「殘心芯片」）——留給站長決定
