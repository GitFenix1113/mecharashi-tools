目標效果： 玩家在任何一頁發現資料錯誤或想許願，都能就地按下回報並自動帶上定位資訊；維護者在後台一處看完所有待辦、流轉狀態並回覆—— 讓「站上的錯誤」第一次有一條會回到維護者手上的路。
建議實作順序： A → C → B → D。先做後台再做前台——後台一旦能用，就可以自己手動塞幾筆假回報驗證整條流程， 避免前台做完了卻發現後台的資料形狀不對而回頭改型別。Phase E 為選配，視實際回報量再決定。
