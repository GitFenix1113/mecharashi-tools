Problem
問題背景
問題一：042-A 的顯影動畫「沒有如預期展現」，三個真因都在 LoreArt.tsx / index.css
① 時間軸從元件掛載起算，不等圖片載入——彩圖的 transition: opacity 900ms … 450ms 在掛載後無條件開跑； art.webp（平均 130KB）多半在這之後才到。實測把圖片延遲 900ms 模擬冷快取：線稿 0 幀，只看到空黑框→彩圖直接出現。暖快取也只露約 300ms。
② 線稿被關在 #0a0c10 黑框裡——color-dodge 偽線稿在黑底上是「白色負片」，與計畫書 A-4「白紙黑線」相反；黑框本身在紙色館內就是一塊突兀的長方形，要 1.75 秒後才消失。 實機驗證容器改紙色後線稿照樣成立，index.css 註解 M-10「紙色會讓 dodge 飽和成純白」的顧慮不成立（人物內部的 backdrop 是灰階層本身，不是容器底色）。
③ 只動 opacity，沒有任何運鏡——官網是 scale 1.2→1 ＋ 上移 ＋ 斜切擦入，彩圖到 40% 才出現並帶 1px 模糊收斂；我們的進場遮罩也只是 300ms 黑→透明，從深色全站點進來只像閃了一下。
問題二：官網 hero 的四個特色，我們一個都沒有——但它們的技術本質都很便宜
官網 #section3[data-anchor=hero] 沒有 canvas、SVG、影片、JS 動畫庫，全部是 PNG 圖層＋CSS keyframes： 背景一張 bg.jpg（紙紋＋紅帶＋機甲線稿＋格線）、標題區塊一張 sl.png、粒子是兩張 1–2KB 點陣 PNG × 7 個 div × fly/fly2 keyframes、 每位機師四層（手繪線稿／帶溶解邊彩圖／名字書法／資料），在 fullpage.js 把區段標成 .active 時播 heroLine/heroColor/mechaData，而圖早在頁面載入時就在快取裡。 名字不是 webfont，是每人一張 PNG；但八張名字層的字母造型一致，證明是同一套筆刷體字型，不是手寫。
問題三：官網只做了 8 位機師的圖層
洛莎、虹、凱登、白月、葉夫根尼、艾琳、黛娜、梅利莎。其餘 82 位沒有名字書法、沒有手繪線稿、沒有溶解彩圖； 而 CDN 的 character/*_Raw.png 實測就是本站的 full.webp（1240×1080，alpha bbox 逐像素相同），36 位缺全身像的問題不會因素材鬆綁而解決。 全員一致仍要靠我們自己的字型子集＋濾鏡管線；官方素材是校準基準與招牌機師的加成。
Design
設計決策
決策一：顯影時間軸改由圖片 decode 起算，等待期是紙色不是黑框
線稿層 img.decode()（失敗退 onload）resolve 後才加 --revealed；等待期容器維持紙色＋極淡佔位。 保險 timer 改成「decode 逾時 2s 直接淡入」，背景分頁 bail 的語意保留（rAF 不跑時仍要能收工）。 驗收數字：冷快取（art.webp 延遲 900ms）逐幀線稿幀 ≥ 3。
決策二：線稿改「紙上鉛筆」，保守版換底色、進階版 multiply 群組
保守版：.lore-art 底色改館內紙色 token，--settled 不再需要底色過渡。 進階版：線稿兩層包成白底群組、群組 mix-blend-mode: multiply，只留鉛筆線沒有白色人形填充—— 前提是 .lore-portrait-col 自己塗紙色（position: sticky 自成堆疊脈絡，否則會留下白框，實機已踩到）。 換底之後 C-1 在黑底量的高光門檻全部失效，至少抽零／戰部渡／卡米拉／虎王／凱登五位重看，LORE_ART_TUNING 可能可以把「零」的線稿打開。 官方 8 張手繪線稿極淡、線條稀疏，我們的濾鏡反而更清楚；只拿它當濾鏡濃度的校準目標，不混用。
決策三：運鏡照抄官網 keyframes，但 blur 與 clip-path 有效能上限
heroLine（1s：scale 1.2→1、translateY 3%→0、opacity 0→1、clip-path 平行四邊形→全幅）與 heroColor（1.05s：同運鏡；opacity 到 40% 才開始；blur 1px→0 於 40–70%）原樣搬進 index.css，線稿層與彩圖層各掛一段， --lore-art-delay 改成 keyframe 百分比。blur 只做 1px 且只在 40–70% 區間；clip-path 動畫在 Chrome 不走 compositor， 863×1600 的圖要用 DevTools Performance 實測（CPU 4× 節流不低於 30fps），掉幀就退回只做 scale＋translate＋opacity。 prefers-reduced-motion 維持現有 150ms 淡入。名字／徽記／引文卡三段用 mechaData（scale 1.3→1 淡入）錯開 0／200／350ms 進場。
決策四：官方素材直接自託管使用，邊界寫死
前提：站長與官方人員有非營利不追究的共識（2026-09-17）。可用：bg.jpg／bg-m.jpg、sl.png／sl-m.png、snow*.png、top8.jpg（KV）、bgm.mp3、 8 位的 line／color／name 三層、mecha 區八台四層（留給 042-B）。
邊界：① 一律自託管、轉 WebP、裁到內容 bbox，不熱連官方 CDN（PLAN-029 自託管慣例，且代理商網域可能改路徑）； ② 素材夾內放 README 記來源 URL 與取得日期；③ 站上維持無廣告、無贊助連結的非營利前提； ④ 資料層 h0N-4 與手機合成圖不用——文字烘進圖會讓字級三顆按鈕、搜尋、可編輯性全部失效； ⑤ 字型授權屬字型公司，不在共識範圍：先用字型辨識工具比對八張名字層找原字型，授權不明就選免費可商用的相近筆刷體。
決策五：名字字體三層方案——中文子集可行、英文草書要先有資料、書法 PNG 不做
a. 中文直書名：LXGW WenKai TC（SIL OFL 1.1，繁中字形完整）只子集機師名——88 個立繪資料夾名只有 127 個相異字，加 fullName 估不到 300 字， woff2 約 40–80KB。名字是封閉集合，避開 042-A 計畫書擔心的「字集漂移」：只漂在新機師身上，而新機師進圖庫就會重跑 build。 管線比照 generate-art-index.mjs 做成 build 前置腳本，需新增 dev 依賴 subset-font（repo 目前沒有任何字型工具）；font-display: swap，fallback Noto Sans TC。
b. 英文草書大字：資料裡沒有羅馬拼音（fullName 89 筆全是 CJK）→ 新增 nameEn?: string（型別＋PilotAdmin 一欄＋docs 同步）， 8 位官方拼法已知（Rosa Diaz／Rainbow／Kaidan Newman／White Moon／Yevgeny Ivanovic Goman／Erin／Dana Yano／Melissa），其餘 82 位對照英文 Wiki 人工輸入，空值不渲染。 排版 rotate(-72deg)、字級 clamp(120px,14vw,220px)、mix-blend-mode: soft-light 壓在立繪柱右後方。
c. 官網那種每人一張的書法 PNG＝美術產出，不做，也不用 AI 生成假書法。
決策六：粒子與背景走「素材＋純 CSS」，不引入 canvas 或動畫庫
粒子：6 個 div 掛在 .lore-shell（position: absolute，不用官網的 fixed，免得蓋到 header）， fly／fly2 照抄參數、延遲 0／.5／.8／1.5／5／5.2s 錯開，pointer-events: none；lg: 以下不掛（官網手機版也沒有）；reduced-motion 整組 display: none。 背景：bg.webp 當 .lore-shell 背景（cover、object-position 對齊立繪柱），紙色 token 保留為 fallback；不再需要 CSS 重建紙紋／格線／紅帶。
決策七：8 位招牌機師做成 LoreArt 的 official 變體，判定在渲染前
素材裁到 alpha bbox 後存 public/images/pilots/<名>/official-{line,color,name}.webp，generate-art-index.mjs 加 PILOT_OFFICIAL_INDEX（含 bbox 偏移，名字層才定位得回去）。 hasOfficialArt() 與 hasPilotArt() 同一種形狀：渲染前分流，不等圖載失敗才換構圖。名字層以絕對定位疊在彩圖上、跟 mechaData 節奏進場。 黛娜、梅利莎目前走 full.webp 半身 fallback，順帶升級為官方彩圖。
⚠ 驗收動畫別用內建瀏覽器截圖
桌面 App 內建瀏覽器的分頁一在背景，document.hidden 即為 true，Chrome 不推進 CSS animation／transition 的時間軸，截圖也是舊幀—— 盤點時第一輪量測就因此誤判成「遮罩永遠不透明、彩圖永遠 0」。驗收一律用 Playwright headless（2026-09-16_filmstrip.mjs），或先確認分頁在前景。
Scope
實作範圍與不在範圍內
在範圍內（估 ≈ 12 人日，不含 nameEn 資料輸入）：
  • A 顯影修正（4 項，≈3 天）：decode 起算、拆黑框、運鏡、推門進場與 stagger
  • B 官方素材切版（5 項，≈1.5 天）：素材自託管與 README、背景、標題區塊、粒子、KV banner
  • C 招牌機師官方變體（3 項，≈1.5 天）：裁切轉檔與索引、official 變體、黛娜／梅利莎升級與 8 位驗收
  • D 名字字體（5 項，≈2.5 天＋資料）：中文書法子集管線、套用、英文草書字型、nameEn 欄位、資料輸入（管理員長期）
  • E 檔案感與聲音（2 項，≈1 天）：裝飾字（編號／版本／紅標／細線）、BGM 開關
  • F 打磨（6 項，≈3.5 天）：牆、章節切換過場、換機師交叉淡出、手機、底緣溶解、hover 微視差（選做）
  • G 驗收與文件（3 項）：逐幀驗收、reduced-motion 與 a11y、docs 同步
  • B／C／D 三段的產出兩館共用，042-B 機甲館直接沿用（mecha 區八台的四層已下載）
不在範圍內：
  • 官方資料層 h0N-4 與手機合成圖（文字烘圖）——維持 HTML 文字
  • fullpage.js 式整頁滾動與滾輪換區（PLAN-050 拆舊輪播的教訓；館內只有一個 scrollport）
  • 每人一張的書法 PNG、AI 生成書法、手繪線稿補製
  • 頁面載入即抓全部機師圖層（官網 8 位 4.2MB 的做法）——本站 90 位且是低流量純欣賞，decode 起算就是為了在 lazy 前提下仍看得到線稿
  • 逸聞內容輸入與 042-A 的部署前置（wrangler deploy、firestore rules、CF Transform Rule 白名單）——它們阻塞的是 042-A 的 push，不是本計畫
  • 042-B 機甲館本體
