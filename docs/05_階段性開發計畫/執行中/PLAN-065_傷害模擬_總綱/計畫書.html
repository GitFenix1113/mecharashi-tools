◆ PLAN-065

傷害模擬 總綱 · 私有引擎 · 煉獄首領驗證

在既有配裝模擬器上加「傷害模式」：前端送遊戲 ID 與情境，後端私有引擎回傳結果；以武裝討伐煉獄首領與遊戲內預覽逐步驗證，拆成 A–I 九個子計畫。

Problem
問題背景
傷害模擬從 2026-05 起就是第一核心模組，但一直沒有做出來
結構地基都建好了（實體引用、BUFF 等級化、階覆寫層、配裝模擬器），數值層卻始終是空的：人工填寫的效果數值全庫 0 筆、官方公式未知，站上原則是「不放猜測值」。
2026-10-17 的遊戲參數資料包改變了前提
設定表與客戶端程式讓傷害計算、攻擊時序與 Buff 判定都有了依據；站上機甲、機師、武器數值與資料包同口徑，不必重建。 2026-10-25 完成初步評估（兩輪多代理調查＋私有試算原型），10-28 站長拍板架構決策。
站長列的五個痛點
  • 技能觸發 BUFF ID 當初沒完成。
  • 攻擊方式（進入對戰、指令、追擊、額外打擊）沒有設計。
  • 底層架構不明確，怕套不上遊戲公式。
  • 手機難以舒適展開。
  • 操作流暢度（元件等希望拖曳與點擊並存）。
Design
設計決策
文件政策：本計畫書會公開
docs/05_階段性開發計畫 會被 copy-docs 發布到 /documents，repo 也是 PUBLIC。所以 PLAN-065 系列只寫工作項目、介面結構與驗收方式； 傷害公式、條件判斷規則、實測數值與預測值一律放私有 repo mecharashi-sim 的 docs/，以及站長本機的評估報告（_local-notes/2026-10/2026-10-25_傷害模擬計算機_初步評估.html）。 審 PR 時若在 public 檔案看到公式、常數或判斷規則，一律退回。
決策一：引擎放後端、程式放私有 repo（站長 10-28 拍板 C2、C3）
計算在 Cloudflare Worker /sim/v1/* 執行；引擎、資料編譯管線、測試案例放私有 repo GitFenix1113/mecharashi-sim（10-28 已建立）。 前端只送「遊戲 ID＋養成假設＋目標＋情境」，不送展開後的數值；引擎資料在部署時打包進 Worker，Worker 不讀 Firestore、不持有 Firebase secret。 路由 mecharashi.wiki/sim/*，不加進 SPA 白名單；傷害模式頁面放在既有 /simulator 之下。
決策二：公開範圍（C1）
對一般玩家：最終結果、分組小計、以及「哪些效果有算／沒算」的清單（含原因）。逐 Buff、逐擊明細只給管理者。不提供任意數值的敏感度掃描。
決策三：站上資料只存「遊戲身分鍵」，效果數值由遊戲資料帶出（C6）
各實體集合新增 gameRef（武器的 weaponInfoId 最必要），用腳本回填、站長確認少數歧義；不動 doc id 與既有 gameId（那是圖片編號）。 人工填寫 Buff 效果數值的欄位凍結（型別保留、前台顯示照舊）。站上顯示層（台版譯名、說明、引用、圖示）維持後台人工維護。
決策四：第一版做「單擊快照＋情境開關」（C7，取代 PLAN-001 決策一）
條件式效果不再只是顯示標籤：第一版以單次攻擊為單位計算，條件轉成玩家可切換的情境開關、已觸發狀態宣告與數值輸入；完整回合序列模擬留到第二版。 未模擬的條件一律列進「未計入」並可手動強制開關，不默默算錯。
決策五：數字一律標明可信度
通過遊戲內實測的武器類別標「已驗證」，其餘標「推算」並加「約」字；結果卡明寫假設（機甲品質、科研進度、改裝）。
決策六：驗證以武裝討伐煉獄首領為主
武裝討伐沒有期限、已開放期數都能回頭打，但每週只能選 3 關，站長只能打煉獄 → 驗證排程以週為單位；初試～死境的首領面板維持「推算值」。 遊戲內「確認攻擊」畫面的預估數字是主要的對帳來源。實測協定、預測值與案例庫放私有 repo。
尚未拍板（做到相關子計畫前再定）
  • C4 Workers 方案（Free／Paid）與升級時機；C5 zone 限流規則如何涵蓋 /sim/——065-A 的 Worker 對外前。
  • C8 科研輸入方式、C9 改裝資料進分享碼、C10 機率效果預設、C11 版面、C12 手機範圍、C13 是否收玩家實測回報——065-D 動工前。
  • C14 等價武器記錄取哪筆——065-A B-4。C15 公開物處理、C16 21-4 首領面板修正、C17 PLAN-052 決策一④ 註記——065-I 或順手。
Scope
子計畫拆分與驗收
子計畫產出前置驗收
065-A
前置資料對照與保護骨架		私有 repo、契約 v1、/sim/v1/ping；各集合 gameRef 欄位與回填；後台顯示遊戲 ID；凍結人工效果欄位；/api 429 退避本總綱決策可上配裝的實體全部有 gameRef 或列入白名單；ping 部署可回應；/simulator 行為不變；build／test／lint 全綠
065-B
引擎 A（面板＋單擊）		資料編譯管線 v0、面板彙總、單擊計算、Worker run 端點（結果＋分組小計）、golden 測試065-Agolden 全綠；Free 方案冷啟動批次在 CPU 上限內
065-C
管理者驗證台＋案例庫		貼分享碼、選首領、輸入實測、看完整拆解與誤差、匯出私有回歸案例065-B首批實測入庫，單擊誤差達標或已歸因
065-D
傷害模式 UI		[配裝｜傷害] 分段、目標挑選器、結果列、分組瀑布、情境面板、改裝輸入、面板覆寫；先拆出配裝頁控制器065-B（可先接 mock）延遲預算達標；舊分享碼照常解碼
065-E
引擎 B（常駐效果）		Buff 展開、第一批條件處理器、元件配對、天賦／神驅／模組／背包／武器被動065-C常駐效果 0 遺漏；帶常駐效果的實測每擊 ±1
065-F
引擎 C（條件＋攻擊方式）		玩家狀態類條件、已觸發宣告、首擊／連續／追擊／額外打擊、機率列舉065-E；C4 拍板多數條件可判定；攻擊段發生率落在統計區間；期望值 ±5%
065-G
拖曳＋手機快查		元件／武器拖曳（與點擊共用判定）、手機傷害快查模式、裝置遙測065-D拖曳 e2e；鍵盤可操作
065-H
引擎 D（支線）		固定傷害、濺射、連帶、盾、保留耐久、擊破所需行動數、協力、再攻擊065-F支線單擊 ±1；擊破行動數 P50 ±1
065-I
上線與文件		過時公開物處理（社群傷害公式文件加註、配裝頁橫幅、種類係數、/research 入口）、收回門檻、kill switch任一階段對外前公開檔案中找不到公式與判斷規則
不在範圍內：
  • 在任何公開文件或程式寫出傷害公式、常數與判斷規則（見文件政策）。
  • 人工輸入效果數值（決策三凍結）。
  • 完整回合序列與首領回合模擬（第二版另議）。
  • 武裝討伐以外的玩法驗證（重裝征伐、首領剿滅…）。
對外開放時機
065-B＋065-C 完成、首批實測達標後才考慮讓傷害模式對外；在那之前只對管理者開放。開放後依武器類別逐類標「已驗證」。
