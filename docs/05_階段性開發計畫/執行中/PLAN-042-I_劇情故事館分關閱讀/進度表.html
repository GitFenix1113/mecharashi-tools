2026-11-28 開發完成並上線： A、B、C、E-1、E-3 全部完成。npm test 1838／1838 通過（新增 storyNav 11 條、storyProgress 7 條），npm run build 通過，改到的檔案 eslint 0 錯 （全站 npm run lint 另有 93 個錯誤，都在本案沒碰的檔案：emulator 測試、workers 型別、時間線元件）。 剩下兩項：E-2 的 iPhone 實機（桌機 1366×768 與 Chromium 375×812 模擬已驗）與 D-1 選配（等站長決定）。
實作時與原計畫不同的三處： ① 路由參數叫 :part 而不是 :stage：App.tsx 明訂故事館參數一律 :id／:part（entityHits 依名讀參數），網址形狀不變。 ② 同書換關用 replace 而不是 push：照 LoreChapterPager「章節之間用 replace」的慣例，一本二十幾關時上一頁不必一關一關退；跨到隔壁那一本才用 push。 ③ 關卡列多一條收納規則：實測 event-8（22 個正關、沒有分幕）攤開要 808px，超過 1366×768 的館內 scrollport（722px），黏著的關卡列底部會永遠看不到； 因此不分幕、超過 14 列的長串切成「1～10」「11～20」一截一截、只展開目前那一截。量過全部 43 本，停在任何一關最多 15 列。
目標效果： 讀劇情時一次只面對一關：跳到任一關只要點一下，讀完一關直接接下一關，離開再回來會提示上次讀到哪裡。 「1-3 跳 1-5」從「往上捲約 4 個螢幕再點」變成點一下。
D-1 為選配：整章連續檢視等 B 段驗收後由站長決定做不做。決定不做就把它標成「不做」並從分母扣掉。
