◆ PLAN-063

機甲圖鑑卡池條 Key Art Banner · 卡池狀態 · 展開動態

機甲圖鑑頁首下方加一條卡池橫條：招募插畫裁成帶狀，左側是池名與狀態（開放中剩幾天／新機甲預計台版登場／上次開放）；點一下從橫條長成整張全景並播放卡池動態。之後回填台版歷史卡池，讓「上次開放、開過幾次」有內容。

Problem
問題背景
玩家最常問的三件事，圖鑑一件都答不了
「這台現在抽得到嗎？」「抽到哪天？」「什麼時候會再來？」——檔期在版本時間線的甘特圖裡，要先知道是哪個版本才找得到； 招募插畫與卡池動態只在機甲故事館卷宗的最後一張。查機甲的人最先打開的是圖鑑，而圖鑑上什麼都沒有。
素材已經齊了（2026-10-17 實測）
  • 招募插畫 61／93 台（GAME_MECH_CARDS）；沒有的 32 台多為 A 級、沒開過專屬卡池，不是缺漏。
  • 卡池動態 23 台（src/data/gachaFx/*.json，PLAN-042-B Phase J），lazy 載入、不點開 0 byte。
  • 狀態推導全部現成：activityStatus()（開放中／剩幾天）、gachaTitleSuggestions()（機甲 → 卡池活動）、bannerIsRerun()（復刻判定）。
但卡池紀錄幾乎是空的
  • patchVersions 只有 3 筆台版機甲池（赫克托爾 08/06、莫比烏斯X 10/01、君權 10/15 推估），陸版 0 筆。
  • 半版本新增名單有 20 台、搭配台版日期 → 「新機甲預計台版登場」現在就推得出來。
  • 台版公告封存（2024-03～2026-08）有 54 台、93 次卡池提及 → 歷史可以回填，但只有公告日，結束日要另外推。
所以本計畫分兩段：先用現有資料把橫條做出來（插畫 61 台、狀態 3＋20 台），再回填歷史讓「已結束」那一格有內容。
Design
設計決策
決策 1：擺法＝頁首下方橫條，狀態與插畫在同一條（站長 10-17 選定）
站長看過三種擺法的原型（頁首橫條／右欄卡片／頁首縮圖，真插畫＋真動態＋真檔期）後選定橫條。 取捨：桌機多出約 136px，壓縮 2026-10-10「一屏看完」改版的成果——站長接受。 原型與截圖：_local-notes/2026-10/2026-10-17_機甲圖鑑卡池條_原型/（本機，不進版控）。
決策 2：修正 PLAN-042-B 決策 B-5（插畫不只是故事館的附件）
B-5 原定招募插畫「不上舞台、只當卷宗最後的附件」。圖鑑改為也引用，但定位不同： 圖鑑裡的插畫是卡池資訊的視覺（讓人認出這個池），故事館裡的是典藏品。 同一個檔案、不複製資料；故事館卷宗那張卡不動。
決策 3：維持 B-7 單向依賴——圖鑑不讀 mechLore
  • 池名取自 patchVersions 的活動名，不用 mechLore.gachaTitle；沒有活動紀錄時標題退回「招募插畫」。
  • 插畫用 mechCardArt(mech)（靜態索引＋gameId）；動態用 gachaFx 登錄表（lazy）。兩者都不碰 Firestore。
  • patchVersions 走既有的 usePatchVersions()：每個 session 一次 Worker 請求、與首頁共用快取；沒逛過首頁的人才多這一次。
決策 4：狀態只看台服，優先序與文案
順位狀態文案（例）來源
1開放中開放中・剩 26 天（至 11/11）；結束日是推估時寫「預計至 10/28」＋虛線框活動 startDate＋weeks、confidence
2即將開放10/29 開放・2 週同上
3新機甲預計 10/22 台版登場（5 天後・推估）；副行「陸版 2026/05/14 已登場・v3.3 下半」半版本 mechs＋twDate／twIsPredicted＋cnDate
4已結束最近一次 2026/08/06・共 2 次過去的台版機甲池活動
5（無紀錄）尚無卡池紀錄（有插畫才出現）—
全部由既有欄位推導（「凡是能算的，就不要問維護者」），不新增任何狀態欄位。凡是推估一律標「推估」。 活動要過前台顯示閘門（isVisibleActivity：有 weeks、未 hidden），甘特看不到的這裡也不顯示。
決策 5：收合焦點存在 mechs.cardFocus（0–100，垂直 object-position）
寬橫條只露出約 20% 的畫面高度，每張構圖不同——原型實測莫比烏斯X 要 15%、芬里厄要 40%，同一個值對不準。
  • 放在 mechs：圖鑑本來就載入，0 額外讀取。
  • 不放 mechLore（違反決策 3）；不放靜態檔（站長要能在後台自己調，不靠 AI）。
  • 後台機甲管理加一格滑桿，旁邊用前台同一個元件即時預覽。沒填用預設 30%——多數看起來還行，只調怪的那幾台。
決策 6：新元件 KeyArtViewer——從橫條的裁切位置長成整張
收合時的圖是 object-fit: cover 裁出來的一條；展開時用 transform＋clip-path 從那一條的位置與裁切範圍長成整張（原型驗證起訖點誤差 ≤1px），收回反向。
  • 落地後才掛 GachaFxLive、關閉一開始就卸載（沿用 LoreViewer 的規則）；有動態的機甲提供「動態／靜態」切換。
  • 暗色背景（圖鑑主題）；放大平移、Esc、焦點移交、捲動鎖、reduced-motion 直接開關。
  • 手機直向：原型顯示橫圖在直螢幕只佔中間一條，改為填滿高度、左右拖曳平移。
  • 不改 LoreViewer：它的等高 FLIP 與紙色舞台是故事館專屬，硬加分支兩邊都難改（同 B-12 的理由）。
決策 7：卡池共用元件搬到 components/gacha/
components/lore/gacha/（引擎、模擬、型別、登錄表、GachaFxLive）改由圖鑑與故事館共用，搬出 lore 目錄， 圖鑑才不必 import 故事館的資料夾。橫條（GachaBanner）與 KeyArtViewer 也放這裡。純搬移＋改 import，測試跟著走。
2026-10-18 動工時改為延後：引擎資料夾一天內有 10 筆 commit（機甲 J-1、機師 Phase J 正在密集改），現在搬會一直衝突， 而且本計畫先在分支試做、可能整個退回。新元件照樣放 components/gacha/，直接 import 現有引擎；等引擎穩定、確定保留再搬。
決策 8：沒有插畫的機甲
有卡池紀錄 → 只顯示一行文字狀態；沒有紀錄 → 整塊不出現（不留空殼）。
決策 9：名稱比對只在寫入端正規化
活動的 mechs 存的是中文名。公告與資料庫已知有用字差異（塔納托斯／塔納託斯、光輝／光暉、巨象／巨像、奥德修斯／奧德修斯、吉雨萊斯／吉爾萊斯）。 回填時在寫入端換成資料庫用字；前台只做 trim 後的精確比對，不做模糊比對——比錯比沒比到更糟。
決策 10：不做復刻預測
陸版機甲池 0 筆、復刻沒有規律可循。唯一誠實的推估是「新機甲預計台版登場」（半版本日期）。 陸版池資料累積起來後，「陸版已復刻 → 台版約晚 N 週」可以另案評估。
決策 12：卡池資料以站內活動時間線為準（站長 2026-10-18）
「卡池資料參考站內的活動時間線即可，有必要的話也可以優化那個功能。」據此：
  • 狀態只讀 patchVersions 的台服活動，三種「拿得到這台」的活動都算：機甲池（mechs）＞ 跨域海運（自選名單 selection，退回 half.mechSelection，與時間線一致）＞ 戰令（mechs）。同時開放時依此順序取一個。
  • 大標題只用機甲池的池名：插畫屬於那期機甲池；海運、戰令寫在狀態列（「可自選」「戰令中」＋副行）。沒有機甲池紀錄就叫「招募插畫」。
  • 「時間線 ↗」深連結到那一期的版本（/versions/timeline/:version）。
  • 盤點後發現時間線的機甲池漏得多（台版公告同期 16 筆沒進來），主因之一是活動編輯器的 UP 機甲欄「有值才顯示」——補成按型別開格＋名稱檢查（進度表 D-2）。
決策 11：歷史回填走審核，不直接寫 patchVersions （2026-10-18 由決策 12 取代：不另做公告封存回填，改成補登時間線；原文保留）
封存公告解析成待審活動送後台 /admin/announcements，由站長逐筆放行；不替站長清佇列。 ⚠ 2024–2025 年的活動要掛在 v2.x 的半版本上，而那些半版本目前是空白佔位（沒有台版日期）。 回填前要先調查怎麼補半版本日期（Phase D 第一步），調查結果由站長拍板後才動資料。
Scope
實作範圍與不在範圍內
在範圍內：
  • 卡池共用元件搬家（components/lore/gacha/ → components/gacha/）
  • 狀態推導純函式＋node 測試
  • GachaBanner（收合橫條）、KeyArtViewer（展開鑑賞）、機甲圖鑑詳情頁接線
  • Mech.cardFocus 型別、後台滑桿與預覽、資料模型文件同步
  • 時間線的卡池資料：盤點、活動編輯器按型別開格＋名稱檢查、補登缺漏（Phase D，2026-10-18 依決策 12 改寫）
  • 跨域海運自選名單、戰令獎勵機甲也算狀態來源（決策 12）
不在範圍內：
  • 復刻預測、陸版卡池檔期（決策 10）
  • 機師圖鑑的角色池橫條（做完這台可比照，另案）
  • 公告封存（2024-03～2026-04）的歷史回填：會落在 v2.x 空白版本，要先補半版本日期（決策 12 後不做）
  • 解析器辨識機甲池（PLAN-048 範圍，進度表 D-4 建議另案）
  • 故事館卷宗的卡池卡（不動）
  • 窄版縮圖衍生檔：先在 B-4 量 LCP，確定變慢才另做
