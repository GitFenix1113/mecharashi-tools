Problem
問題背景
機甲側說不出「我有幾個槽、哪個槽被佔住」，而模擬器連左右手都表達不了
武器側說得出自己的限制（weapon.ts:118 mechRestriction、:119 equipSlot）， 但反方向完全空白：Mech 型別沒有任何容量欄位； mech.parts.*.fixedArmament 實測 90 台全空； 三個被 PLAN-040 凍結的死槽位（leftShoulderSlot／rightShoulderSlot／backSlot） 也是 0/90 有填。沒有這一層，模擬器連「破曉者-01 的兩個肩槽已被嵐質儲能艙佔滿」都問不出來。
首屏最大的三個數字目前都算錯
① 重量：現行只有 w.weight <= mech.output - mech.weight， 而備用武器組不是加總、是取較重者（先鋒形態加總會得 2625，官方是 1825，誤差 44%）。
② 出力：漏算出力背包 +200/250/300、強襲者背包 +300、出力模組 +100 （官方畫面的 3675 就是 3375＋300）。
③ 火力：mech.firepower 是爬蟲抓官方欄位的產物 —— 實測 83 台的頂層值 ＝ 單一部位值、7 台手建的 ≈ Σ 四部位。 正確算法是 Σ 四部位，也就是說 MechsPage／MechDetailPage 現在顯示的火力是實際的 1/4。
PLAN-047 的驗收數字全部過期，不能照抄
PLAN-047 寫於 2026-08-09，其引用的筆數在兩週內成長 10%–43%： weapons 172→180、mechs 63→90（輕型 27／中甲 36／重型 27）、pilots 82→89、行號漂移 2 行。 其決策七「equipSlot × mechRestriction 完全無交錯」也已被 weapon_176_耀星／weapon_177_隕星（singleHand + medium）推翻 —— 但結論更強：gate 一律寫 mechRestriction（medium 49 筆 vs 戰術 44 筆，差 5 筆）。
本子計畫吞下 PLAN-047 的 Phase A＋B，並以 2026-08-23 實測數字重寫全部驗收條件。
Design
設計決策
本子計畫的定位：先把「數字對不對」與「槽位存不存在」解決，UI 一律留到 052-B
交付物以純函式 ＋ 型別 ＋ 資料為主，唯一的前台改動是機甲詳情頁的唯讀區塊。 這樣安排的理由：這些是 052-B／C 全部要依賴的地基，而且它自己就能單獨上線 （機甲頁的槽位資訊是今天全站沒有的東西）。
決策一：三支數值純函式先於一切，並以官方四組數字當 golden fixture
// src/utils/loadoutWeight.ts totalWeight(set, chassis) = chassis.weight // Σ 四部位（N2 確認） + Math.max(Σ mainHandWeights, Σ backupHandWeights) // ⚠ 取較重者，不是加總 + Σ shoulderWeights + backWeight // 背包 XOR 背部武器 // src/utils/effectiveOutput.ts —— ⚠ 必須吃 formKey（出力是 per-form 的） effectiveOutput(chassis, set, modules) = chassis.output // ＝ parts.torso.output，只有軀幹有 + backpackOutputBonus(set.backpackId) // 強襲者 +300／出力背包 +200/250/300 + Σ moduleOutputBonus(modules) // output_bonus，走 levels[] // src/utils/chassisStats.ts chassisFirepower(parts) = Σ parts[p].firepower // ⚠ 全站停止讀 mech.firepower
golden fixture（彌造者 ＋ 海莉絲四形態，全部來自官方截圖）：
先鋒 825 + max(800, 850) + 150 = 1825 / 3675　突擊 825 + max(800, 920) + 150 = 1895 / 3675
戰術 825 + 1200 + 1100 = 3125 / 3375　虛粒子 825 + 100×3 = 1125 / 3375
決策二：ResolvedChassis —— 機體數值的唯一入口
Q20 決定允許混搭部位之後，「一台機甲」降級成「四個部位的預設組合」。 本子計畫先把 derive 層做出來（UI 在 052-G），讓後續所有計算從第一天就走對的路徑。
export interface ResolvedChassis { parts: Record<MechPartPosition, { sourceMechId: string; part: MechPart }> weight: number // Σ parts.weight output: number // parts.torso.output（只有軀幹有） firepower: number // Σ parts.firepower armorType: ArmorType // 不能跨類型混搭 ⇒ 無歧義 moduleSlots: Record<MechPartPosition, { iface: PartInterface }> moduleLevelOf(moduleId): number // 本輪一律回滿級（N3） }
⚠ 其餘數值（耐久／護甲／命中／閃避／抗暴／移動）的合成規則尚未確認（總綱 Q-1）， 本輪不實作，型別上先不開欄位，避免把猜測寫成事實。
決策三：槽位型別沿用 PLAN-047 決策一，只新增正交的 SlotBank
export interface ArmamentMount { weaponId: string; slot: WeaponEquipSlot; side?: 'left'|'right' } export type SlotBank = 'main' | 'backup' // 與 slot 正交，不是第四套部位詞彙 export interface SlotCapacity { singleHand; shoulder; back; backupHand } // slotKey(bank, slot, side) → 'main:singleHand:left'；parseSlotKey() 為其反函式
硬不變式（校驗腳本 0 例外）：mount.slot === weapons[mount.weaponId].equipSlot。
mechSlotCapacity()：singleHand: 2／shoulder: isMedium ? 2 : 0／ back: 1／backupHand: 0（由背包給）。 ⚠ 條件一律寫 ArmorType.MEDIUM，禁止中文字面量 —— SimulatorPage.tsx:179 的 '中甲' 就是打錯字面量而 tsc 抓不到的現成教訓。
occupiedSlots()（佔據型・機甲部件層）與 lockedSlots()（全鎖型・機師形態層） 禁止合併成一個函式：UI 要講得出「這格被嵐質儲能艙佔住」與「這個形態不能換裝備」的差別。
決策四：固定武裝 8 筆（比 PLAN-040 的窮舉多 2 筆）
掛在 MechPart.fixedArmament?: ArmamentMount[]，左臂 → 左肩、右臂 → 右肩。
來源武器槽位狀態
mech_022_帕斯卡衝擊炮 ×2左肩 ＋ 右肩武器文件已存在
mech_027_破曉者-01嵐質儲能艙 ×2左肩 ＋ 右肩武器文件已存在
mech_050_霸王多功能彈倉 ×2左肩 ＋ 右肩武器文件已存在
form_海莉絲_虛粒子耀星／隕星／千星右手／左手／背部武器文件已存在，補槽位
form_曜_巡航幽弧／夜燼右手／左手武器文件不存在，本輪新建
幽弧／夜燼全庫查無（實測 180 筆武器中沒有這兩個名字），流水號接續為 weapon_181_幽弧／weapon_182_夜燼； 比照耀星／隕星／千星填 isFixedArmament: true、manual: true， 數值列入 variableStats（使用者逐字：「這兩個武裝連遊戲中都看不到詳細設定，只有進入戰鬥變形才能看到」）。
決策五：型別收緊與資料修正做成一個批次，不散在各處
Mech.armorType／Pilot.license 由 string 收成 enum（實測值域乾淨： armorType 只有 中甲36／輕型27／重型27；license 只有 中型37／重型26／輕型26）。
MechPart.interface 收成 PartInterface = 'Ⅰ' | 'Ⅱ' ＋ MechAdmin 改下拉選單 —— 使用者逐字：「除非要統一改用列舉、輸入資料用下拉式選單一步到位，不然（單獨修錯字）意義不大」。 一次性正規化 4 格「ⅠⅠ型接口」錯字與 S 機甲 4 格空白；B 機甲 40 格不補（沒人配 B 機甲）。
順帶修 globalResearch：型別宣告是 Record 但實際資料是 Array （['格鬥家'] 恆 undefined 且 tsc 抓不到），且它的 armorType 鍵是「中型」而 mechs 是「中甲」 （直接 join 會讓 36/90 台中甲靜默拿 0）。⚠ 這個集合不可刪 —— 它是全庫唯一填滿的公式數值表（六職業／三裝甲／五武器種類全有值）， 對照全庫 SkillEffect 是 0/225 buffs、0/841 skills。
Scope
實作範圍與不在範圍內
在範圍內：
  • 三支數值純函式 ＋ golden fixture 測試（totalWeight／effectiveOutput／chassisFirepower）
  • src/types/slots.ts ＋ src/utils/mechSlots.ts（吞下 PLAN-047 Phase A）
  • ResolvedChassis derive 層（不含混搭 UI）
  • MechPart.fixedArmament 型別 ＋ 8 筆固定武裝落盤 ＋ MechAdmin 編輯器
  • forms 型別升級（independentLoadout、weaponIds→mounts）＋ 6 筆資料調整 ＋ FormAdmin 擴充
  • 型別收緊批次（ArmorType／MechLicense／PartInterface）＋ 資料修正
  • 機甲詳情頁的唯讀「槽位配置 ＋ 固定武裝 ＋ 四部位表」區塊；火力顯示改 derive
  • 槽位一致性校驗腳本；SIMULATOR_KEYS 加 forms
不在範圍內：
  • 任何配裝 UI（三欄版面、挑選器、級聯）→ 052-B
  • 分享碼與存檔 → 052-C／052-E
  • 元件面板 → 052-D；形態分頁 → 052-F；模組槽與部件混搭 UI → 052-G
  • 耐久／護甲／命中／閃避／抗暴／移動的混搭合成規則（總綱 Q-1，使用者裁決先備註）
  • 科技加成納入火力顯示（第一版標註「不含科技」）
