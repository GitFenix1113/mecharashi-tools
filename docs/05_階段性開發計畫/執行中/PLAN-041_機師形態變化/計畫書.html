◈ 2026-08-09 訂正（實機截圖 + Firestore 查證）
本計畫先前把「突擊／先鋒形態多出右手備用／左手備用槽」與「各形態出力上限不同」當成形態的能力——兩者都錯， 它們是背包的效果。以下為逐項實測佐證。
先前的陳述2026-08-09 實測影響
「突擊／先鋒形態多出右手備用／左手備用武器槽」＝形態能力 備用槽來自「強襲者背包」，與形態無關。實測 backpacks/60101706： type: 'BackupEquipment'（backpacks 181 筆中僅此 1 筆）、slot: 'back'、weight: 150、 assemblableArmorType: ["Light","Medium","Heavy"]（無機甲限制）、 skillIds: ["bpskill_強襲者驅動·增傷"]。 技能正文逐字含「可以使用［武器切換］指令，每回合最多使用1次；行動結束時，若雙手完好，可以額外使用［武器切換］指令，每2回合最多使用1次」。
追加實測（同日）：備用槽裡的武器是玩家自選的（只要負重夠；雙手武器佔滿 2 格；交換是兩手一起換的原子操作）， 不是背包內含的固定武器 → Backpack 沒有「背包內武器」欄位缺口， type: 'BackupEquipment' 已是正確標記；真正的缺口在 Build.weaponId，見「不在範圍內」。		 決策不變 形態不需要表達槽位
「各形態出力上限不同（3375 vs 3675）」＝形態改機甲數值 +300 出力來自同一個背包技能：bpskill_強襲者驅動·增傷 正文逐字「機兵獲得額外300出力，軀幹耐久值提升10%，造成傷害提升5%」。 mech_052_彌造者 的 output 實測 3375，3375+300=3675 ✅ 決策不變 形態不需要 effects
⇒ 結論：形態不改機甲數值、不改槽位配置。兩個原決策因此維持不變：
  • MechForm 刻意不開 effects（決策二）——3375→3675 的差是背包給的，形態身上沒有任何數值可寫進 effects。原本唯一看起來需要 effects 的證據就是這個出力差，它已被歸還給背包。
  • FormRestrict 用 discriminated union（sum type）（決策二）——「突擊形態需要同時表達武器白名單與備用槽，所以 restrict 應該是 product」這個指控因本訂正而失效：備用槽根本不是形態的屬性，突擊形態要表達的仍然只有 allow: ['突擊'] 一件事。
四形態的統一解釋（四個數字全部對上）
形態背部槽內容備用槽出力上限
虛粒子千星（固定武裝，equipSlot: 'back'）無3375
戰術熠光（戰術武器，戰術類限中甲、裝背後）無3375
突擊強襲者背包·增傷有3675 = 3375 + 300
先鋒強襲者背包·增傷有3675 = 3375 + 300
背部槽只有一個，裝什麼決定了有沒有 +300 與備用槽——四個形態的差異全部由「背部槽裝了什麼」解釋完畢，沒有殘留需要形態層負責的部分。
官方形態卡左側那組數字不可落盤
1125 / 3125 / 1895 / 1825 是當前裝備重量總和，會隨玩家配裝即時改變，是 derived 值。 絕對不可寫進 MechForm：落盤等於製造第二個真相源，且任何一次配裝變更就失準——與決策二「能 derive 的不落盤」同一條原則。
紅字「僅裝配格鬥與射擊武器」是形態的限制，不是背包的
三條佐證：
  • (a) 強襲者背包 assemblableArmorType 為 ["Light","Medium","Heavy"]（無限制），bpskill_強襲者驅動·增傷 正文完全沒有武器類型字樣；
  • (b) 若這是背包的限制，同樣裝強襲者背包的突擊形態就不能裝突擊武器——與實機截圖直接矛盾；
  • (c) 「格鬥＋射擊」精確等於本計畫決策二記載的先鋒形態 allow: ['格鬥','射擊']。
→ 這條限制的歸屬就是 FormRestrict 的 { kind: 'weaponType', allow: [...] } 那一支，不需要任何新欄位。

Problem
問題背景
問題一：形態資料已經存在，但沒有任何頁面會渲染它
四筆形態文件（skill_先鋒型態 / skill_突擊型態 / skill_戰術型態 / skill_虛粒子形態） 躺在 pilotSkills 的 710 筆裡，正文逐字完整——但實測 0 位機師的 skills 陣列引用它們（海莉絲的 9 個技能不含任何一筆）。
前台 resolvePilotSkills 只渲染機師 skills 陣列裡的東西 → 這四筆從建立到今天，一次都沒有被顯示過。 玩家在機師頁看得到天賦寫著「駕駛的機甲擁有多種形態」，然後就沒有然後了。
問題二：PilotSkill 型別裝不下形態需要的東西
形態要表達的四件事，PilotSkill 一件都接不住：
  • 武器限制（「只能裝備格鬥和射擊武器」）→ 無欄位
  • 固定武裝鎖定（虛粒子形態「無法變更武裝和技能」）→ 無欄位
  • 顯示順序（先鋒→突擊→戰術→虛粒子）→ 無欄位
  • 形態增益的連結（指向 buffs 的形態增益文件）→ 無欄位
而 skill.weapon.categories 已經被拿來硬撐了——skill_虛粒子程式 把「固定武裝」當成 pseudo-category 塞進去。現況已在借殼。
問題三：命名已經在腐爛，而且沒有人會發現
這四筆文件的 id 用「型態」、name 用「形態」（skill_先鋒型態 ↔ 「先鋒形態」）。 全庫另有 skill_巡航型態 / skill_機兵型態 同款。 BUFF_型態增益 的 name 也是「形態增益」。
因為它們都是孤兒、沒有渲染面，不一致不會被任何人看到，也就不會被修。
問題四：mutexGroup / FormGroup 引擎是純死碼，但還在誘導維護者
PLAN-019-B 為形態互斥蓋的引擎——GameBuff.mutexGroup（buff.ts:114）、 reachableBuffs.ts 的 FormGroup、SimulatorPage.tsx 的形態切換 UI（:55/:274/:834/:868/:880-893）—— 實測 全庫 0 筆 buff 有 mutexGroup → 那段 UI 永遠算出 0 組、從未渲染過。
但 BuffAdmin.tsx 的互斥群組欄位（:95/:470/:685）還在，且 :527 的說明文字仍在講「取代 mutexGroup」。 新調構師上線時，後台唯一長得像「建形態」的地方仍然是 BuffAdmin，而走錯不會有任何錯誤提示。
Design
設計決策
決策一：開獨立的 forms 集合，不續留 pilotSkills、也不塞回 buffs
三條可驗證的理由（刻意不寫「怕與機師資料混雜」——pilot.skills 早在 PLAN-004 已是純 ID 陣列，那個理由會被 reviewer 正確推翻並連累整個 PLAN）：
  • 形態不是技能也不是 buff：它要承載 restrict union / order / grantedBuffIds / isSignature，兩個既有型別都裝不下（見問題二）。
  • 續留 pilotSkills 會讓孤兒狀態永久化：形態不能加進 pilot.skills——那會讓它們混進「技能 (9)」分頁，與一般技能同列顯示，而形態不是技能。
  • 0/5 定律：本專案每一個新開的集合都被填滿了（pilotSkills 710 / buffs 217 / glossaryTerms 162 / neuralDriveAbilities 全 flip），每一個投機性的選填欄位都是空的（SkillVariant 0/710、SkillArea 0/710、effects 全庫非空 0 個）。唯一的共同點不是「集合 vs 欄位」，是「有沒有頁面在渲染它」。

暴擊率 vs 命中率是不同屬性軸，唯一「看起來重複」的只有 15% 這個數字。 分工：固有＝形態的身分，永遠生效 → 住 Form；增益＝天賦另給的一次性 buff（正文均有「觸發效果後移除」）→ 續留 buffs。 這就是 grantedBuffIds 指向 buffs、而不是把增益吞進 Form 的依據。
◈ 2026-08-12 實作訂正：增益是三筆獨立 buff，不是原先假設的單一 BUFF_型態增益。 實際建成 buff_形態增益先鋒／buff_形態增益突擊／buff_形態增益戰術（顯示名「形態增益·先鋒」…）。 這比單一 buff 好：一形態一筆，前台可直接顯示該形態那條，不必從一段混寫三形態的正文裡挑句子。 BUFF_型態增益 已不存在，本計畫書其餘處提及該 id 者一律以此為準。 虛粒子形態的 grantedBuffIds 刻意留空——它靠［粒子爆發］「獲得所有形態增益效果」拿滿三份，由 UI 特例標註（決策五）。
決策四：三層來源全部標示，且明標「可疊加」
形態卡分三段：形態固有（Form）／形態增益（天賦滿星，指向 buff）／模組加成（帕姆斯陣列）。 每段標來源，不聚合成單一數值——丟失來源標註的聚合表會產生誤判。

決策五：虛粒子形態的三個特例
  • 同時吃滿三份增益：skill_粒子爆發 正文逐字「消耗所有［激發能］切換為［虛粒子形態］，獲得所有形態增益效果」。而形態增益 buff 只有三個戰鬥形態各一筆、沒有虛粒子專屬的一筆 → UI 需特例標註「同時獲得三份形態增益」，否則玩家在虛粒子卡上找不到增益。
  • 固有技能被強化為 EX：skill_虛粒子程式「［虛粒子形態］時的固有技能強化為［虛粒子刃EX］［虛粒子炮EX］［虛粒子矩陣EX］，並可以使用［逐世者強襲］」。基礎版與 EX 版都已存在於 pilotSkills。（2026-08-12 更新：原本要用 lockedSkillIds 指基礎版，該欄位已依決策十移除——三支技能由形態正文的 [虛粒子刃] 等引用表達，EX 版則由虛粒子程式的正文表達，兩層都不重複編碼。）
  • 裝備獨立：每個形態各一套武器背包（海莉絲要準備三套）。本計畫不落盤，只寫進「已知未做」——見不在範圍內。
◈ 2026-08-09 實機補充：fixedArmament 鎖的是「全部槽位」，比官方原文更強
問題二引的官方原文只寫「無法變更武裝和技能」，實機比這更嚴格。使用者 2026-08-09 實測逐字： 「不只是不能帶背包，虛粒子形態沒辦法調整任何裝備」。
  • 語意寫進型別註解：restrict.kind === 'fixedArmament' 的鎖定範圍是該形態的 全部槽位（雙手＋雙肩＋背部），不是只有被 weaponIds 那三把（耀星／隕星／千星）佔住的三格。 實機截圖中虛粒子形態的雙肩顯示為空的 [+] 但不可用，正是此意——空槽 ≠ 可填。
  • 「不能帶背包」的理由改寫：先前是由「千星 equipSlot: 'back' 佔住背部槽」推導出來的； 今天有了直接依據——不是因為那一格被佔住，而是因為整個形態不開放調整。結論相同、理由不同，註解要寫後者（推導會在未來槽位模型改動時失效）。
  • PLAN-047 已據此把槽位封鎖拆成兩個正交的 derive： 佔據型（機甲部件層——某槽被固定武裝實際佔住，其他槽照常可用）與 全鎖型（機師形態層——該形態下所有槽位皆不可調整，與佔據與否無關）， 對應 occupiedSlots() 與 lockedSlots() 兩個獨立函式。 本計畫的 fixedArmament 分支對應後者；帕斯卡／破曉者-01／霸王的肩槽封鎖屬前者，不歸本計畫。

決策七：箭頭方向——form → weapon、skill → form，反向一律禁止

2026-08-09 補（第二條箭頭的由來）：固定武裝實際有 6 種，不是本計畫原先記的 4 種。 除了帕斯卡的衝擊炮×2 與海莉絲虛粒子形態的耀星／隕星／千星，另有 破曉者-01（mech_027_破曉者-01）的嵐質儲能艙×2 與 霸王（mech_050_霸王）的多功能彈倉×2，兩者皆為純封鎖型（無數值、無技能）。 這兩台在 modules 241 筆與官方 API 83 台全掃中零命中武裝來源模組（mod_破曉者-01_fixed_1/_2 講手臂修復與傷害加成、mod_2064 只是命中率+10%）， 走不了帕斯卡那條 module ─(descriptionRefs)→ weapon 的路 → 只能由機甲直接指向武器，即圖中第二條。 該箭頭的實際形狀（掛 chassis 還是 MechPart）由 PLAN-047 定案，本計畫不依賴——海莉絲那三把仍走 form → weapon，與機甲層無關。

決策十一（2026-08-12 拍板）：refType: 'form' 的點擊落點＝機師頁的形態分頁

決策九（承接 PLAN-040）：「特殊／固定武裝」不參與形態武器過濾
三個戰鬥形態的「只能裝備 X 武器」原本把 WeaponType 切成無重疊無遺漏的分割（先鋒=格鬥+射擊 / 突擊=突擊 / 戰術=戰術）。 PLAN-040 為衝擊炮新增「特殊」型別後，這個分割不再完整。
