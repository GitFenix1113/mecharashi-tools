PLAN-046 · 網站使用統計

目前唯一的觀測手段是 Firebase 主控台的讀寫次數，它能回答「花了多少額度」，卻答不出「哪些頁面真的有人用」——而後者才是決定改版順序與資料補齊順序的依據。更關鍵的是 PLAN-029 的中國訪客策略至今無從驗證：Worker 同源代理、字體自託管、邊緣改寫都做了，卻只能說「應該有用吧」。本計畫用長期閒置的 Firestore 寫入額度，建一套同源第一方埋點（走既有 /api，攔截器擋不掉、中國訪客也統計得到，這正是不用 GA4 的理由）。去重採三層識別碼：visitorId／sessionId（10 分鐘閒置，且閒置由活動訊號判定，否則慢讀者的 session 會被誤切）／已報頁面 Set，同頁同次造訪只計一次 UPV，但 PV 雙軌保留——兩者比值即「折返率」，是資訊沒給足的訊號。資料走預聚合日文件（看 30 天＝30 reads），一個 session 離站時 sendBeacon 批次寫一次，寫入量與逛幾頁完全脫鉤。
安全面：不開匿名 Firestore 寫入，改由 Worker 代寫，但這讓 Worker 從純唯讀變成有匿名可觸發的寫入路徑，因此立兩條鐵律（文件路徑由伺服器時間算出、欄位路徑一律由程式碼組出，payload 只准給數字）。另含寫入預算熔斷器（超出免費額度自動停止計數並標記 truncatedAt，避免報表默默說謊）與 COLLECT_ENABLED kill switch。Worker 端刻意不放頁面白名單，改用格式正則防護——放名單就是重演 PLAN-043 的雙名單不同步事故。不記錄個別使用者行為。

開發收束：2026-08-08 · 24 / 26 任務 · 維護內容：C-2 驗收的 ②折返率 ③CN 佔比 ④寫入量已於 2026-08-23 通過（折返率 2.10、CN 4.5%、單日寫入最高僅預算 0.79%、零熔斷零缺漏日），僅餘 ① 與 Cloudflare Web Analytics 的同期趨勢對照待補；另長期觀察 Workers 請求數與 Security Events

PLAN-043 · 背包技能集合與編輯強化

背包技能過去只以「SS 專屬的內嵌 mainSkill」存在——那是爬蟲時代官方 WIKI 欄位形狀的殘留，實測 22/22 精確對應 22 個 SS，因為官方只在 SS 條目填了技能欄位。但遊戲內連 B 級的「移動背包」都掛著被動技能「移動強化Ⅰ」。本計畫開獨立的 backpackSkills 集合（刻意與 PLAN-032「武器技能併入 pilotSkills」的裁決相反）、掛載側改 skillIds[] 並支援 @N 等級、技能等級化沿用 PLAN-024 的 levels[] 同構模式，兩段式硬切遷移已完成 flip。同時補上背包後台的刪除（第四個可刪集合，並新增 hardRef 機制擋下前置鏈／複合武器融合的硬外鍵）與 IconPicker，圖示另闢 skills/背包技能/ 資料夾。

PLAN-033 · 後台編輯視窗加寬

後台編輯彈窗由固定 672px 放寬到 min(90vw,1920px)，並把多出的寬度轉為欄位密度而非胖輸入框：格線改 auto-fill 自動排欄（Phase B），再精簡分頁數並把「長到必須捲兩屏」的天賦編輯／模組基本資訊／武器改裝方案改為左文本右結構化的雙欄版面（Phase C）。全程只改版面，不動 state 與 Firestore 寫入路徑。

PLAN-029 · Cloudflare 化與 App Check 退場

用 Cloudflare 一層邊緣基建接手「反白嫖 + 反爬 + 加速」，讓 App Check／reCAPTCHA 退場。公開遊戲資料改走 Worker 代理、Firestore 規則收成 read:if isAdmin()（比 App Check 硬）；反爬為兩層——Worker 內建守門（Origin/Referer + 機房 ASN）+ zone 託管 per-IP 限流。資料端點已同源掛在 mecharashi.wiki/api/*，深層路徑改由邊緣改寫回 200，並移除中國被封鎖且阻塞渲染的 Google Fonts。
