◆ PLAN-057

引用編輯器直觀化 RefPicker · 標註檢視 · 段落分開指派

後台引用挑選器改成「在正文上點詞編輯」：同色＝同一筆引用、膠囊標出等級；天賦初始／最大強化可一鍵分開指派到不同等級。

Problem
問題背景
同一個詞、兩段正文要指到不同等級，後台卻分不清哪個是哪個
珂賽特天賦「未來之羽」：初始版 [鋒勢] 疊層上限 5、應指 Lv1；最大強化版上限 10、應指 Lv2。 資料模型（PLAN-039 消歧 key ＋ PLAN-024 EntityRef.level）其實做得到，正式庫也已存成 [鋒勢|buff_1]／[鋒勢|buff_2]，但後台的引用清單與正文分開、前台兩邊都只顯示 [鋒勢]， 維護者只能靠內部後綴猜哪一筆是哪一處。
舊的「同名引用標記」面板誤報、而且做不到整段拆分
已消歧過的 key（[鋒勢|buff_2] 出現 4 次、全指同一實體——正是想要的狀態）仍被報成重複，預設後綴一律 skill； 拆分按鈕只有「各段的第 N 處」，做不到「最大強化段全部換一個 key」，只能手改正文。
前台「最大強化」區塊的引用整段退回純文字
DiffHighlight 的切字正則漏了 _，[鋒勢|buff_2] 被切成 鋒勢|buff2、查不到 refs。 初始正文走 RefText 不受影響，所以只壞半邊。
來源提案：_local-notes/2026-10/2026-10-11_引用編輯器直觀化提案.html（站長 2026-10-11 拍板 A＋B＋C 全做）。
Design
設計決策
決策一：在正文上點詞（A）
RefPicker 頂部新增標註檢視（RefOccurrenceText）：每個 [xxx] 變成膠囊，顏色＝屬於哪一筆引用、右側標 Lv、虛線＝未指派。 點膠囊選取該引用，下方清單列以同色顯示「初始 N · 最大強化 M」並展開改 key 工具。工具掛在清單列上、不另開常駐面板， 避免同一筆引用出現兩份指派 UI。
決策二：段落後綴用語意命名，不叫「滿星」
天賦第二段對應遊戲潛能提升的「天賦能力加強」，不是滿星；前台本來就標「▶ 最大強化」。 段落定義：天賦 初始／最大強化（後綴 強化）、武器技能 技能描述／專武強化天賦（後綴 專武）。 潛能等級的模型不在本計畫延伸（站長指示）。
決策三：一鍵「依段落分開指派」自動 +1 級（B）
同一個 key 在兩段都出現時提供；把該段全部出現處改寫為 [顯示字|後綴]、帶走原指派，階梯 BUFF 有更高一級才 +1（nextLevel）， 否則沿用原級——不編造不存在的等級。
決策四：onCompileText(transform, nextRefs?)，且 nextRefs 必須同次寫入
改 key 會同時改正文與引用表。天賦編輯器的 upd 是 onChange({ ...talent, ... }) 閉包，分兩次呼叫後者會蓋掉前者， 所以擴充既有管道而非另開 callback；transform 另帶 part 索引，多段呼叫端逐段傳入。14 個呼叫端全部改接。
決策五：併入規則
目標 key 仍有正文在用 → 沿用目標設定（併入）。目標只是殘留引用 → 「全部改」與「段落分開」以來源設定取代它 （實測案例：把 [鋒勢|buff_1]（Lv1）改回 [鋒勢] 時，沒設等級的殘留 [鋒勢] 會默默蓋掉 Lv1）； 只拆出一部分 → 新 key 留白待指派（或沿用殘留的舊設定），讓「已指派 n / m」亮黃燈。來源 key 改完已無出現處就自動移除，不留殘留。
已知行為：色票依 key 首次出現序分配，同一畫面內一致；新增 key 後，排在後面的 key 顏色會位移。 改用雜湊固定色會讓同顯示字的兩個 key 有機會撞色——那正是此檢視最需要區分的東西，故不採用。
Scope
實作範圍與不在範圍內
在範圍內：
  • 0：DiffHighlight 切字修正（src/utils/diffTokens.ts，不變式：切完接回等於原字串）
  • A：標註檢視、清單列同色＋出現位置、改 key（這一處／這一段／全部）
  • B：refKey.ts 新增 renameKeyword／renameRefEntry／nextLevel；段落分開指派按鈕
  • C：移除 PLAN-039 頂部同名面板；殘留引用長說明收合
不在範圍內：
  • 機師潛能提升（1–5 級、大師／超適體）的資料模型
  • 正式庫珂賽特資料的整理——部署後由站長用新工具操作並儲存（見進度表 D-3）
  • .input-field 寫在 @layer 之外、蓋掉 w-*／py-*／text-* utility 的全站問題（本計畫只避開，不修）
