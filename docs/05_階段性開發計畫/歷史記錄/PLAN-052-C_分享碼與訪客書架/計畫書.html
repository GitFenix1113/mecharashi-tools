分享碼與訪客本機書架 · Loadout Code · Local Shelf

零後端出貨：把整套配裝壓成一串可貼進 Discord 的網址，並讓未登入的訪客也能把配裝存在自己的瀏覽器。

Problem
問題背景
052-B 上線後，玩家配完的東西留不住也傳不出去
現行只有一顆「匯出分享圖」（html2canvas），圖片沒辦法被還原成配裝。 而總綱決策九已定案全面公開（未登入也能用）—— 訪客配了半小時，關掉分頁就沒了。
直接把 doc id 塞進網址會爆長
本站 doc id 是含中文的字串（weapon_176_耀星、mech_022_帕斯卡）。 實測：同一套典型配裝用 JSON ＋ 原樣 doc id 約 700+ bytes，而二進位打包只要 ≈70 bytes（差 10 倍）。
codec 一旦上線就同時是「儲存格式」，bug ＝ 使用者資料全毀
總綱決策二把落盤收斂成「一串分享代碼」，所以 loadoutCode 不只是分享功能。 它的三個高風險點：流水號被回收（舊碼靜默指向另一把武器）、 格式版本缺失（英文 WIKI 已經踩過：新增第 18 欄時舊碼已流出，只好同時接受兩種長度）、 解碼器 throw（一個壞碼讓整頁白畫面）。
Design
設計決策
決策一：純前端自包含編碼，不開後端短碼
零後端、零 Firestore 寫入、零 Cloudflare Dashboard 改動 （分享碼放既有 /simulator?b=，該路徑已在 SPA fallback 白名單內）。 後端短碼要新增寫入面與濫用防護、吃 Worker 100k/日 額度，而且是不可逆的資料負債（發出去就永遠要能解）。
長度實測（估算）：典型配裝 ≈70 bytes → 網址 ≈130 字元； 海莉絲多套 ≈216 字元；理論最壞 ≈743 字元。Discord 單則上限 2000 字元，最壞情況只佔 37%。
決策二：TLV/section 版面，header 永久凍結
header（跨版本永久凍結，Worker 的 OG 只解這一段） FMT 1B 格式版本 = 1 // ⚠ 與文件 schema 版本分開，不共用常數 GAMEVER 1B // 只用於提示文案，不參與解析 PILOT 1-3B / MECH 1-3B // varint(LEB128)，上限 3 bytes body（每段一個 tag + length，未知 tag 一律跳過並記入 unmodeled） tag=1 §SETS NLOADOUT varint ＋ ACTIVE 1B ＋ 每套 { KEY str, NMOUNT 1B, mounts…, BPFLAG 1B ＋ BACKPACK } mount: SLOTB 1B (bit0-2 slot / bit3-4 side / bit5 bank / bit6 hasComp) ＋ WEAPON varint ＋ [NTRIG 1B ＋ NEFF 1B ＋ ids] tag=2 §PARTS NPART varint ＋ {部位 1B, 來源機甲 shareId} // 只寫與原廠不同的部位 tag=3 §MODULES NMOD varint ＋ {部位 1B, 模組 shareId varint} // ⚠ 不存 level（部位推導值） tag=4 §ND NZONE varint ＋ {分區名 str, Lv 1B} // PLAN-052-I D-2 tag=5 §NAME 方案名稱 str // PLAN-052-I E-1 CHK 1B FNV-1a 低 8 位 // 專治 Discord 換行截斷 str ＝ 長度 varint ＋ UTF-8 位元組。空段落一律整段不寫。
三個必須在 v1 就正確的細節（事後補要洗掉所有已存資料）： ① SLOTB 的 bank 位元（少了它就編不出任何有備用武器的配裝）； ② §MODULES 段（「code 是唯一落盤格式」＋「v1 不含模組」＝玩家選的模組存不下來，而 UI 看起來一切正常）； ③ 形態身分不可用 form.order（FormAdmin.tsx:269-270 是自由輸入欄位）。
⚠ 2026-08-26 實作定案：本版面已依實作修訂，上表就是 codec.ts 的真實版面。 與原規格的三處出入：
① 原寫 FORM 1B，但沒有可用的 1 byte 形態身分——上面第③條禁止用 form.order，而形態 doc id 是 form_海莉絲_先鋒 這種純名稱、沒有數字可推。 改成長度前綴的 UTF-8 內嵌：典型配裝只有一個 default 鍵（+8 bytes）， 海莉絲三套實測整串 119 字元。換得零解析器耦合、精確 round-trip， 且形態被改名時說得出「原本是哪個鍵」。
② 原寫 mount 的 NCOMP ＋ COMP[]，但 MountSetup 是觸／應兩條清單， 合成一條就得再找一個位元存「這顆是觸還是應」，而 varint 裡沒有空位元可借 ⇒ 改成 NTRIG 1B ＋ NEFF 1B ＋ ids。
③ 新增 §ND（算力，來自 052-I 的跨計畫修訂）與 §NAME（方案名稱）兩段， 兩者都在 v1 就開。
另補 ACTIVE 1B（目前分頁的索引，0xff ＝ 不在清單內）—— 不編它的話 round-trip 就不是深等於，而深等於是決策六的驗收條件。 實測長度：空草稿 7 字元、典型單套 36、含元件與算力 79、海莉絲三套 119。
決策三：shareId 用既有流水號，並用 lock 檔擋回收
不新增 Firestore 欄位 —— 流水號已經印在 doc id 上，再開一個 shareId 就是第二個真相源。 核心不變式：流水號是身分不是位置（新增 weapon_179 不會讓 weapon_178 位移）。
映射：pilots/mechs/weapons/components → ^{prefix}_(\d+)； backpacks → 官方 8 位數字 − 60,000,000；modules → mod_<數字>。
⚠ 唯一破口是流水號被回收：src/utils/idSlug.ts:82 的 maxEntitySeq 是「掃現有 ID 取 max」， 刪掉 178 再新增會再次產生 178。而本專案確實會改 doc id（08-17 備份裡 mechs／pilots 各有 6 筆無流水號，08-23 才補號）。 ⇒ share-id.lock.json 進版控 ＋ check-share-ids.mjs 改指即 exit 1 ＋ 後台續號改 max(lock, live)+1，並寫進 data-patch skill 的流程。
旁證 英文 WIKI 也用一張進版控的永久別名表，註解逐字寫 「never changes once assigned, so a shared build stays valid forever」。
決策四：解碼「先結構後語意」，且永不 throw
① 輸入清洗：去空白換行（Discord 會在 ~70 字元處換行）、抓 b= 之後、必要時 decodeURIComponent。
② 結構防護（不過就拒絕）：長度上限、字元集、checksum、varint ≤ 3 bytes（擋 varint 炸彈）、 NLOADOUT／NMOUNT／NCOMP 上限（擋「小代碼展開成十萬個物件」）、讀完後不得有剩餘 bytes（擋 padding 走私）。
③ 版本分派：FMT 比本 client 新 → 「這串代碼來自比你手上更新的版本，請重新整理頁面（Ctrl+F5）」—— 站是 SPA，使用者 bundle 舊是最可能的原因，比「代碼無效」誠實且給得出下一步。舊版解碼器永不刪除。
④ 語意驗證：全部放行，只標警示（「此配裝有 N 項不符合現行規則」）—— 對方可能在分享改版前的配裝，或想看看改了什麼。絕不因此拒絕套用。
⚠ 舊快取誤判：解不開時先打一次 /api/versions，版本落後就強制重載該集合， 重載後仍解不開才判為「已下架」—— 否則本週新上線的武器會被顯示成「已下架裝備 #181」，語意完全相反。
決策五：訪客本機書架 10 套（不分機師）
與登入者的「每機師 5 套」語意不同，UI 文案要分開寫： 訪客「本機書架 7/10」／登入者「海莉絲 3/5」。
只存代碼字串。每張卡永遠有一顆「複製代碼」當人工備份出口， 且 UI 明講「未登入的配裝只存在這台裝置」。052-E 上線後提供手動勾選匯入 （不自動合併 —— 自動合併會在配額滿時產生無聲的取捨）。
決策六：測試是驗收條件，不是加分項
① round-trip property test：隨機產 10,000 份合法配裝，斷言 decode(encode(x)) 深等於 x。
② 模糊測試：隨機位元翻轉 10,000 次，斷言不 throw、不無窮迴圈、checksum 攔截率 > 99%。
③ golden fixture：每個 FMT 版本凍一組代碼字串 ＋ 期望解碼結果，舊版解碼器永不刪除。
④ 邊界：空碼、只有 header、超長、非法字元、未來版本號。
Scope
實作範圍與不在範圍內
在範圍內：
  • src/utils/loadoutCode/：shareId.ts／codec.ts／fixtures ＋ 三組測試
  • share-id.lock.json（進版控）＋ scripts/check-share-ids.mjs ＋ 寫進 data-patch 流程
  • /simulator?b= 讀取與「複製分享連結」；貼碼預覽卡與全套錯誤文案
  • 訪客 localStorage 書架 10 套 ＋ 自動草稿
  • 匯出圖重做（html-to-image、螢幕外固定 1080×1350、印全部 mounts ＋ 分享網址）並移除 html2canvas 依賴
  • SITE_NAME 收成單一常數（現行全站第 5 份硬編）
不在範圍內：
  • 雲端存檔與 Firestore rules → 052-E（本階段只有本機書架）
  • OG 預覽卡（要動 Cloudflare Dashboard 的 Transform Rule）→ 052-H
  • 配裝標籤與熱門統計 → 052-H（標籤白名單見總綱 Q-3）
  • 元件／模組挑選 UI → 052-D／052-G；但 codec 的對應段在本階段就要開好
