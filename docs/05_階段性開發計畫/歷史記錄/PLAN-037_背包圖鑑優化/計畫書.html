◆ PLAN-037

背包圖鑑優化 · 預設特種 · 能力循前置鏈 · 包含武器

背包圖鑑最終優化：預設只顯示特種(SS)、「能力」沿 craft 前置鏈篩選（SS/S+ 循線）、移除前置背包 facet、「包含武器」預設開。整合 PLAN-035 階層與 PLAN-036 前置關係。

立案背景（2026-07-25，站長四點優化）：背包圖鑑經 PLAN-035（階層）、PLAN-036（前置主背包）後，站長提出最終優化：預設只看特種、把「變體」子篩選升級為「能力」並沿前置鏈跨階篩選、移除已被取代的前置背包 facet、把「特種背包製作」toggle 改為「包含武器」預設開。
Design
設計決策
決策一：預設階層只選「特種」(SS) → 移除分頁限制
DEFAULT_TIERS 由 ['base','composite','special'] 改為 ['special']，落地只顯示 22 個 SS ＋（包含武器時）3 把複合武器＝25 項。查詢量小，移除 displayCount 分頁與「載入更多」，直接渲染全部 filtered。
決策二：「能力」沿 craft 前置鏈篩選（原「變體」）
核心新增純函式 backpackAbility(bp, byId)：沿 craft.prereqBackpackId 遞迴，取底層 S 變體背包（強化背包·X / 干擾背包·X）的 { line, variant }。
// 主宰者背包(SS) → 飛行強化背包·首攻(S+) → 強化背包·首攻(S) 篩選 強化 + 首攻 ⇒ 命中 主宰者背包（原本 SS 名字無變體、無法被舊「變體」篩到）
UI 標籤「變體」改為「能力」。line 篩選改為嚴格：能力線不符（含無能力的功能背包／武器）即排除——此舉一併定案 PLAN-035 遺留的「line 對無軸條目是否排除」問題（改為排除）。
決策三：移除「前置背包」facet（PLAN-036）
PLAN-036 的「前置背包種類」facet（依 SS 前置 type 篩）被決策二的能力循鏈取代——能力循鏈更直覺（強化→首攻）且跨 SS/S+，故移除該 facet。craft 資料仍用於能力循鏈與浮窗「衍生自」。
決策四：「特種背包製作」toggle 改「包含武器」，預設開
語意由「切換清單」改為「把複合武器加進來源池」：items = 全部背包 ＋（包含武器 ? 複合武器 : []），再由階層/類型等統一收斂；武器與背包同條件篩選。
讀取權衡預設開 → 進頁即 ensureLoaded(['weapons'])，冷快取新訪客多付約 169 筆 weapon read（複合武器僅 3 把但需整包才能篩）。因 PLAN-017 版本快取，回訪 0 read；169 非「暴增」（相當於背包本身量級），故預設開。若日後在意，改 useState(false) 即回退為預設關。
