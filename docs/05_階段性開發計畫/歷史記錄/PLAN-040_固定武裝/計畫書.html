◆ PLAN-040

固定武裝 · Fixed Armament · 資料衛生 · 武器建檔

把「無法更換的武器」建成真正的武器文件（6 筆）、修好帕斯卡今天就壞著的引用，並讓固定武裝在圖鑑與模擬器有正確的預設行為。槽位模型與機甲側落盤已於 2026-08-09 拆出，移交 PLAN-047。

本計畫的定位（2026-08-09 縮減後）
PLAN-040 只做四件事：資料衛生 → 型別擴充 → 建 6 筆武器文件 → 前台呈現。 「機甲有幾個肩槽／背槽」「固定武裝怎麼佔槽」「模擬器的裝備合法性檢查」全部移交 PLAN-047 槽位與裝備限制模型—— 本計畫刻意不對槽位的表達形狀表態（見決策四、決策六）。

誠實聲明：阻塞已解除，但範圍確實比原定位大。 舊版計畫書那句「本計畫無爭議、無阻塞」在 2026-08-09 的查證後不再成立——一次查證就長出 7 個待確認事項， 設計決策也從原本的 6 條擴到 10 條（新增：七 naStats、八 預設排除、九 COMPONENT_WEAPON_TYPES、十 不加「扇形」）。 這件事要誠實記著：「無爭議」是當初沒查夠，不是題目真的簡單。
但 Q1–Q7 已於 2026-08-09 由使用者全數答覆（見文末 Open Questions）—— 原本會擋住 Phase C 的四題（Q1 衝擊炮能不能普攻／Q2 另外 4 台高嫌疑中甲／Q3 千星扇形朝向／Q6 rarity 填什麼）全部拿到確定值， C-1 六筆的欄位值現在可以直接寫進 Firestore，不再有「答錯要回頭改資料 + 重新 bump 版本」的風險。 另有兩題（Q5 掛 chassis 還是 MechPart、Q7 強襲者背包的備用武器）的答案各推翻一項先前判斷，已轉交 PLAN-047。

但「先做 PLAN-040」的論證仍然成立：PLAN-041 的 Form.restrict.fixedArmament.weaponIds 只需要其中 3 筆（耀星／隕星／千星）， 而這三筆在 weapons 集合 172 筆中 0 命中（name 完全相符與模糊含字皆 0 筆）。 形態計畫第一天就會卡在「無物可引」，且這 3 筆不含任何待確認項（數值、type/kind、equipSlot 皆已由遊戲內卡面確認）。 範圍縮減後，PLAN-041 的阻塞不變、不加深。
Problem
問題背景
問題一：帕斯卡的 [衝擊炮] 引用今天就是壞的
mod_帕斯卡_fixed_2（彙編矩陣）與 mod_帕斯卡_fixed_3（深採模型）的描述逐字為 「固定裝備[衝擊炮]，可使用[退敵激波]；同時攜帶兩門[衝擊炮]時，可使用[浪潮來襲]」， 但 weapons 集合 172 筆裡沒有衝擊炮。
而懸空引用不會靜默降級成純文字：引用層只檢查 token 在不在 refs、不檢查 refId 解不解析得到 → chip 照樣渲染成可點擊的彩色底線，點下去顯示「找不到對應資料」。
問題二：彌造者的三把固定武裝完全不存在，擋住 PLAN-041
耀星／隕星／千星在 weapons 集合 0/172。 這三把是海莉絲［虛粒子形態］唯一能使用的武裝（官方形態卡逐字：「無法變更武裝和技能」）， PLAN-041 的 fixedArmament 分支沒有它們就建不出來。
問題三：Mech 的三個武器槽是死欄位——但「形狀錯」的舊論證已被推翻
leftShoulderSlot / rightShoulderSlot / backSlot（src/types/mech.ts:56-62） 實測 63 台機甲 0 台有填，唯一消費端是 MechAdmin.tsx:552-561 的 SlotEditor（前台從不讀）。
訂正： 舊計畫書寫「它的形狀本身就錯：只有肩、背，沒有手持」——這個論證不成立。 2026-08-09 查證後，被固定武裝封鎖的槽位精確地就是肩與背： 帕斯卡雙肩（衝擊炮 ×2）、破曉者-01 雙肩（嵐質儲能艙 ×2）、霸王雙肩（多功能彈倉 ×2）、彌造者背部（千星）。 唯一的手持案例是耀星／隕星，而它們來自海莉絲虛粒子形態（機師層），本來就不該由機甲底盤欄位表達，屬 PLAN-041。
真正的問題另有其三：(a) 0/63 填寫率；(b) 三態語意（undefined=無此槽／null=空槽／string=固定武器）撞上 firestoreCore.ts:43-53 的 stripUndefined——SlotEditor 取消勾選時寫的就是 undefined，會被整個濾掉， 一旦某台機甲寫進了槽位欄位，後台再也無法取消；(c) scalar 表達不了帕斯卡「同一把 × 左右兩肩」。
→ 這三點都是槽位模型的問題，不是 PLAN-040 該回答的。本計畫改為凍結（決策六），處置權移交 PLAN-047。
問題四：moduleFixedIds 有 6 筆斷鏈，其中一筆讓模擬器讀不到帕姆斯陣列
mech_052_彌造者 的 moduleFixedIds 只有 ["sub_mod_火力模組"]， 漏收了 mod_彌造者_fixed_1（帕姆斯陣列）——那是海莉絲唯一的形態強化模組，圖鑑看得到、模擬器看不到。 另有 mech_034_復仇女神 的 mod_復仇女神_fixed_1..4（模型-武／憐愛／月升／無恙）、 mech_星夜女神 的 mod_星夜女神_fixed_1（觀星者單元）同樣漏收——三台機甲的現有值皆為 ["sub_mod_火力模組"]。 反向（moduleFixedIds 指向不存在的模組）0 筆。
另有 3 筆 boundPart 存成純字串 "torso" 而非 ["torso"]： mod_帕斯卡_fixed_4（張量核心）／mod_影虎_fixed_1（虎魄·無束）／mod_輝龍_fixed_2（龍威·啟明）。欄位缺漏 0 筆。
校驗腳本的 slot-scoped 定義必須用 slot === '機甲專屬模組'，不可用 doc id 前綴
mod_2064（AI火控單元，霸王）的 slot 是「機甲專屬模組」，但 id 是 mod_2xxx 形式。 用「排除 mod_2xxx／mod_3xxx」這種 id 前綴規則會靜默漏檢它。 兩種定義今天同分（皆判出 6 筆斷鏈），但 id 前綴法有盲點，未來新增同型 id 就會失效。
訂正： 舊計畫書曾拿「naive 全掃的誤報基數」當佐證，該數字在 2026-08-09 無法重現（實測為 25 筆，其中 19 筆誤報）， 已從計畫書與驗收條件整個刪除——誤報基數會隨 modules 資料量漂移，不是可驗收的量。 驗收只認一件事：slot-scoped 掃描結果為 0 筆。
問題五：固定武裝實際有 6 種 不是 4 種（Q2 已答 → 已窮舉），其中兩種是「純封鎖型」
舊計畫書只認得 4 種（衝擊炮／耀星／隕星／千星）。2026-08-09 確認另有兩種，且它們的性質與前四種不同； 同日使用者答覆 Q2：「目前有固定武裝的我都列上來了」→ 這張表就目前遊戲版本而言是窮舉，不是抽樣：

「純封鎖型」不是我們的臆測，遊戲的 lore 層有明文對應。 mech_027_破曉者-01 的 lore 逐字： 「REV-01捨棄了肩部戰術武器的部署接口與空間，替換為嵐物質粒子儲存裝置，能在手臂部位被破壞時使用儲存的嵐物質粒子即刻修復手臂」—— 這句話同時說明了「肩槽被吃掉」與「換來的是什麼」。
→ 兩個直接後果：(a) 這兩筆沒有任何數值可填，逼出決策七的 naStats； (b) 它們在 modules 241 筆與官方 API 83 台全掃中零命中（「固定装备」只命中帕斯卡的兩個模組）， 無法從模組層 derive——這推翻了舊決策四（見設計決策）。
⚠ 「可用載重 1150」這個訊號已作廢，寫下來以免有人再推導一次
舊 Q2 的推導是：25 台中甲裡可用載重卡在 1150 的恰好 4 台，其中一台（霸王）已確認有固定武裝， 第 5 名跳到 1650（斷層 500）→ 所以另外 3 台高度可疑。
2026-08-09 使用者實機確認：這條訊號不具判別力。 mech_051_君權（君權）／mech_010_青鳥（青鳥）／mech_奈芙蒂斯（奈芙蒂斯）同樣是 1150， 但三台都沒有固定武裝；另一台被列入嫌疑的 mech_034_復仇女神（復仇女神，肩部未排除）也沒有。
→ 1150 與「有沒有固定武裝」沒有相關性，霸王只是恰好同值。 這條訊號已作廢，日後不要再拿載重數字去猜固定武裝，也不要把它寫進任何校驗腳本的啟發式規則。
仍然保留的：UI 硬規格「沒有固定武裝 ⇒ 整區不渲染」不因「已窮舉」而放寬—— 未來新機甲仍可能有固定武裝，而「整區不渲染」讓「未知」與「沒有」共用同一種呈現，才不會把未知渲染成肯定的否定陳述。見「不在範圍內」。
問題六（本輪新發現的資料語意問題）：戰術武器沒有普通攻擊，attack 服務的是它的天生主動技能
Q1 的答案不只回答了衝擊炮，還推翻了一條全站的隱含預設。使用者原話逐字： 「每一個戰術武器都有自身天生配備的主動技能，戰術武器本身不存在『普通攻擊』。目前我們沒有把戰術武器的主動技能寫上，但未來可能會補。」
這是全類通則，不是衝擊炮特例：實測 type === '戰術' 共 43 筆 （equipSlot 分佈：shoulder 22 筆 + back 21 筆），全部適用。 衝擊炮雖標 特殊 / 固定武裝，但佔肩槽、行為與戰術武器同型，一併適用。
→ 兩個後果：
  • 欄位語意：戰術武器的 attack / hitCount 是餵給「天生主動技能」的，不是普攻數值。 這句話要寫進 weapons 資料模型的欄位說明（Phase F），否則未來的傷害計算器會把它當普攻算。
    兩個對照組把界線畫得很乾淨：千星的［虛粒子矩陣］造成 1.1 倍範圍傷害 → 千星有 attack: 194 / hitCount: 6； 衝擊炮的［退敵激波］純位移、不造成傷害 → 卡面攻擊欄顯示 -（見決策七）。
  • 缺口（不在本計畫範圍）：這 43 把戰術武器的「天生配備主動技能」全站完全未記錄—— 既不在 weapon.skills（WeaponSkillRef），也不在任何模組。 本計畫 C-3 只掛得出衝擊炮［退敵激波］與千星［虛粒子矩陣］兩筆，既有 43 筆一筆都沒有。 列入承接待辦（見「不在範圍內」）。

決策一（維持）：Weapon 只加旗標欄位，不動既有語意
// src/types/weapon.ts export interface Weapon { // …既有欄位 /** * [固定武裝]：無法更換的武器。 * 已窮舉 6 種（2026-08-09 使用者確認，就目前遊戲版本而言即為全部）： * 衝擊炮(帕斯卡)、嵐質儲能艙(破曉者-01)、多功能彈倉(霸王)、 * 耀星/隕星/千星(彌造者·海莉絲虛粒子形態)。 * 純粹供 badge 渲染 + 圖鑑/模擬器過濾，不編碼「來源」也不編碼「佔哪個槽」。 * * ⚠ 命名刻意避開既有的 fixedMod（:96「固定改裝」）—— * 同一個 interface 上同時有 fixed(固定武裝) 與 fixedMod(固定改裝) 是維護地雷。 * ⚠ 【不要】複用 isExclusive(:90) / exclusiveFor(:91)：那是「機師專武、可選裝、SS、強化天賦」， * 與固定武裝「強制、鎖死、無法更換」語意相反；且 exclusiveFor 被 useFirestore.ts 與 * PilotsPage.tsx 當「機師→專武」索引消費，塞進去會被渲染成金框專武， * 並破壞 isExclusive ⇔ rarity === 'SS' 的既有不變式。 * ⚠ 槽位歸屬（誰佔了哪個肩／背槽）不在這裡，見 PLAN-047。 */ isFixedArmament?: boolean /** * 手建文件保護旗標。官方 API / WIKI 無這六筆資料、100% 手動維護。 * weapon.ts 是唯一缺此旗標的主要型別（對照 mech.ts:75 / pilot.ts:40）。 */ manual?: boolean // naStats?: string[] —— 見決策七 }
決策二（維持 + 警告）：enum 要補三個值
現行 WeaponType 只有 4 值、WeaponKind 17 值。實測 172 筆武器中 type 無「特殊」值、kind 無「固定武裝」「粒子莢艙」值，六筆全部落在 enum 外面：
武器官方 type / kind裝配位置enum 現況
耀星格鬥 / 刀劍右手 → singleHandenum 已有
隕星突擊 / 機槍左手 → singleHandenum 已有
千星戰術 / 粒子莢艙背部 → backkind 要新增
衝擊炮 ×2特殊 / 固定武裝雙肩 → shouldertype + kind 都要新增
嵐質儲能艙 ×2特殊 / 固定武裝雙肩 → shoulder同上
多功能彈倉 ×2特殊 / 固定武裝雙肩 → shoulder同上
WeaponEquipSlot 現有四值（singleHand / dualHand / shoulder / back）完全夠用，不動。 RangeType 本輪不動，見決策十。
⚠ 「加一個 enum 值」在本專案不是安全操作——ComponentsPage 用 enum 清單長度當判準，見決策九。
決策二的連帶效應（必須寫進 PLAN-041，否則三個月後會被推翻）
PLAN-041 的核心論證之一是「三個戰鬥形態的『只能裝備 X 武器』把 WeaponType 做成無重疊無遺漏的 partition （先鋒=格鬥+射擊 / 突擊=突擊 / 戰術=戰術）」。
一旦 WeaponType 多了「特殊」，這個 partition 就不再完整。 正確的表述是：「特殊／固定武裝不參與形態的武器過濾——因為固定武裝本來就無法更換，過濾器對它沒有意義」。 這句話必須逐字寫進 PLAN-041 的設計決策，不能只留在這裡。
