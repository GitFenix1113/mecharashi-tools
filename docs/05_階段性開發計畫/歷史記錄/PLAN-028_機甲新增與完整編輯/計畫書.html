◆ PLAN-028

機甲後台新增與完整編輯 · Mech Create · Full Editor

讓管理員在後台自建機甲，並完整編輯屬性（數值＋四部件）、能力（模組引用）與介紹文本，補足官方資料更新的空窗期（與 PLAN-025 機師版同構）

Problem
問題背景
官方資料更新太慢，社群等不及（同 PLAN-025 機師情境）
新機甲上線後，官方資料（本站爬蟲來源）常有明顯落後。夥伴們希望能自己先把新機甲的資料建進站內， 不必枯等官方更新。目前後台「機甲管理」只能編輯既有機甲，沒有「新增機甲」入口。
機甲編輯面板目前只能編「模組配置」，其餘欄位全靠爬蟲
MechEditModal 現況只編 module4Id / module8Id / moduleFixedIds。 機甲的核心數值（火力 / 裝甲 / 閃避 / 機動 / 重量 / 出力）、四部件詳細資料 （parts.torso / leftArm / rightArm / legs）、護甲類型、肩膀 / 背後武器槽、立繪路徑等， 後台完全沒有編輯 UI。手建機甲若不能編這些欄位，資料就是空殼。 （與機師版最大差異：機師 PilotEditPanel 本就能編所有欄位，機甲則須從頭補齊這些編輯器。）
唯一例外是「能力」＝機甲模組：模組本就有獨立的「模組管理」後台（ModuleAdmin）， 已支援手動新增與 managedBy:'manual' 保護，機甲端只需「引用」模組 ID，不必重造能力編輯器。
手建機甲有被爬蟲補丁覆寫的風險
爬蟲 scrape-mechs.js 以機甲名比對、只補丁 Firestore 既有機甲。 手建機甲目前天然安全（官方查無同名），但一旦官方日後出了同名機甲，補丁就會覆寫人工資料—— 比照 Pilot.manual（PLAN-025），機甲層也需要一個保護旗標（Mech 目前無此欄位）。
Design
設計決策
決策一：沿用 upsert，不新增 addMech（同 PLAN-025）
已驗證 updateMech() 內部即 setDoc(doc(db,'mechs',id), ...)，本身即 upsert—— 新增與更新走同一條路徑。資料層完全不用動，只需在 MechAdmin 補「新增」入口， 以空白預設值開啟既有的 MechEditModal。
決策二：文件 ID 走 mech_<中文名>（PLAN-020 慣例）
用 makeEntityId('mech', name) 由名稱生成 ID（makeEntityId 前綴為泛用字串，無須註冊）， 天然與官方機甲 ID 分流、不撞號。建立前以 docExists('mechs', id) 做伺服器端撞名檢查， 導引去編輯既有項。複用 useNewItemCreation + NewItemDialog（PilotAdmin / SkillAdmin / BUFF 都用它）。
決策三：新增隱形 Mech.manual 旗標（純爬蟲保護，不做前台標示）
比照 Pilot.manual 語意：手建機甲設 manual: true，爬蟲 scrape-mechs.js 補丁迴圈遇到即整筆跳過。前台不因此顯示任何「社群自建」標記（手建與官方機甲外觀一致）， manual 僅作後端防覆寫用途。
決策四：MechEditModal 由「只編模組」擴充為分頁式完整編輯器
在既有 Modal 內加入 tab 列，拆為五個分頁：基本數值（護甲類型 / 六大數值 / 品質 / lore）、 部件（四部件詳細數值）、模組配置（既有邏輯原封保留）、 武器槽（肩膀 / 背後固定武器 ID）、外觀（立繪路徑）。 這是本計畫工程量的主體——機師版此處是現成的，機甲版要新寫。
決策五：「能力」＝模組，沿用既有 ModuleAdmin，機甲端只做引用（同 PLAN-025 神驅能力庫分層）
機甲的「能力」由模組提供（特性 / 8級 / 副 / 專屬模組，含各級數值、條件效果、BUFF 引用）。 模組早已是獨立集合 modules + 專屬後台 ModuleAdmin，且已具備手動新增 （makeDefaultModule 預設 managedBy:'manual'）與爬蟲保護 （scrape-modules.js 跳過 managedBy==='manual'）。 因此本計畫不重造能力編輯器：機甲編輯面板的「模組配置」分頁只負責引用模組 ID （module4Id / module8Id / moduleFixedIds），能力本身（名稱 / 效果 / 各級 / BUFF） 仍在「模組管理」維護——與 PLAN-025「機師只引用神驅能力庫」的分層完全一致。
邊界：手建機甲的專屬模組須跨分頁先建立
專屬模組由 Module.boundMechId === 機甲 ID 反查而來，並非存在機甲文件上。 手建一台全新機甲時，其專屬 / 綁定模組在「模組管理」中尚不存在，須先到 ModuleAdmin 新增模組並把 boundMechId 設為新機甲 ID；機甲端的模組下拉才選得到（module4Id / module8Id 下拉的 availableModules 以 boundMechId===form.id || 未綁定 過濾）。 此跨分頁工作流需在 UI 上以提示引導，避免夥伴卡住（比照 PLAN-025「神驅連結能力庫須先有能力」）。
邊界：部件的條件式欄位需依 position 顯示
MechPart 有位置相依欄位：左右臂才有 hit（命中）、腿部才有 dodge（閃避）/ move（移動力）、 軀幹才有 antiRiot（抗暴）/ output（出力）。部件編輯器須依 position 顯示對應欄位， 避免填出無意義的資料。共通欄位：durable / armor / firepower / weight / interface。
邊界：手建機甲缺少爬蟲衍生的資產路徑
部件 icon / mechaIcon（CDN waparts/ 資產名）與 portrait / halfPortrait 無官方來源。預設值工廠給空 / 選填，前台既有渲染皆已對這些欄位做選填處理（需回歸驗證）。 本計畫不做圖片上傳 UI，資產路徑維持字串手填。
Scope
實作範圍與不在範圍內
在範圍內：
  • Mech.manual?: boolean 型別欄位 + 同步 docs/02_技術文件/02_資料模型/mechs.html
  • MechAdmin 新增「＋ 新增機甲」對話框（ID 自動生成 + 撞名檢查）
  • 新機甲預設值工廠 makeDefaultMech(id, name)（六大數值 0、空四部件、moduleFixedIds:[]、manual:true）
  • MechEditModal 分頁化，新增編輯能力涵蓋三類資料：
    • 屬性：基本數值分頁（護甲類型 / 六大數值）＋ 部件分頁（四部件詳細數值）
    • 介紹文本：lore 敘述（基本數值分頁）＋ 立繪路徑（外觀分頁）
    • 能力（模組引用）：模組配置分頁沿用既有邏輯，引用 module4Id / module8Id / moduleFixedIds
  • 另含武器槽分頁（肩膀 / 背後固定武器 ID）
  • 部件分頁依 position 顯示條件式欄位（臂 hit、腿 dodge/move、軀幹 antiRiot/output）
  • 手建機甲的專屬模組跨分頁工作流提示（引導去「模組管理」建模組並設 boundMechId）
  • 爬蟲 scrape-mechs.js 補丁跳過 manual === true 的機甲
  • Phase C（實測後強化）：固定模組下拉納入本機甲專屬模組並標示、非選項值不再誤顯示「未設定」＋唯讀專屬模組區； 部件補圖片路徑 icon；圖片改用 IconField 挑選器並可「依機甲名稱自動帶入各部位路徑」
不在範圍內：
  • 前台區分「玩家自建 / 官方」的視覺標記（本次決定不做）
  • 部件 icon / mechaIcon 與立繪的圖片上傳 UI（維持字串手填 / 空預設）
  • 新的權限角色（夥伴沿用既有 ADMIN 權限）
  • 機甲刪除功能（本次僅新增 / 編輯）
  • 模組（能力）本身的新增 / 編輯：已由既有 ModuleAdmin 完整支援（手動新增 + manual 保護），本計畫僅在機甲端引用，不重造
