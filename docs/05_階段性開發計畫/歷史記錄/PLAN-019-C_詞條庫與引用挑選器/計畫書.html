詞條庫與引用挑選器glossaryTerms · RefPicker · 非工程維護

補完引用層最後一塊：建詞條庫讓 term 引用有資料源，並提供後台 RefPicker 讓任何人把描述裡的 [xxx] 標成可點引用。

一句話：引用層（019-A）已能渲染與互動，但 term 類引用沒有資料源、且後台沒有任何工具能填 descriptionRefs。 本子計畫建 glossaryTerms 詞條庫（收無專屬集合的機制關鍵字）並打造 RefPicker（描述內 [xxx] → 指派引用的後台 UI）， 讓引用層真正可由非工程人員維護。
Problem
問題背景
缺口一 — term 引用無資料源： EntityRefView 的 resolve() 對 refType:'term' 仍走 default → pending （src/components/EntityRefView.tsx 第 143–145 行）。技能/被動已有 pilotSkills、BUFF 有 buffs、機體/武器/模組各有集合， 唯獨 [固定傷害]、[啟動]、[形態增益] 這類「無專屬集合可放」的機制關鍵字無處可查，點開只有佔位訊息。 引用層因此尚未真正「全部解析」。
缺口二 — descriptionRefs 無後台編輯工具： 全後台沒有任何地方能填 descriptionRefs（src/pages/user/admin/ 的描述欄位全是純 textarea）。 目前要讓一段描述裡的 [xxx] 變成可點擊，只能手改 scripts/seed-plan019-demo.mjs 之類的腳本 — 只有工程人員能標引用，與「讓非工程人員協助輸入資料」的目標直接衝突。這也是 019-A 進度表最後一條（RefPicker 後台填值 UI）所指。
Design
設計決策（聚焦版）
決策一：glossaryTerms 集合（仿 buffs / pilotSkills，整包預載小集合）
詞條庫量小、回訪走 PLAN-017 版本快取，直接整包預載即可。RefType 已含 'term'、RefChip 已有 term 顏色 → 型別零返工。
// src/types/index.ts — 新增 export interface GlossaryTerm { id: string // term_<名稱>（與 skill_/buff_ 一致） name: string // = [xxx] 內文字 category?: string // 機制分類（傷害/狀態/資源/通用…） description: string descriptionRefs?: DescriptionRefs // 解釋內也能再引用其他實體 aliases?: string[] // 同義詞 → 同一詞條 icon?: string }
決策二：firestoreApi getter / writer（仿既有 pilotSkills）
getGlossaryTerms = fetchCollection<GlossaryTerm>('glossaryTerms')； updateGlossaryTerm 走 setDoc + bumpDataVersion（仿 updatePilotSkill，src/lib/firestoreApi.ts 第 205 行）。
決策三：GameDataContext 接線（自動吃版本快取）
glossaryTerms 加進 CollectionKey / ALL_COLLECTION_KEYS / GameDataState / useState / applyData / fetchFromFirestore / provider value。 新集合自動納入 PLAN-016 預載 + PLAN-017 localStorage 版本快取，回訪 0 讀取。
決策四：EntityRefView 解析 term
REF_TO_COLLECTION 加 term:'glossaryTerms'；新增 case 'term' resolver （title=name、subtitle=category、description + descriptionRefs、image=icon）；把 term 移出 default(pending)。 此後 [固定傷害] 等詞條 hover/點擊即顯示解釋，並可繼續 drill。
決策五：RefPicker 通用元件（本計畫核心）
給定一段 description + 現有 descriptionRefs，自動 tokenize 出所有 [xxx]，逐 token 提供：refType 選擇 + 可搜尋的實體挑選器， 選定後寫入 descriptionRefs[token] = { refType, refId, label? }。候選清單直接讀 GameDataContext 的 in-memory 陣列 （pilots / mechs / weapons / modules / backpacks / components / buffs / pilotSkills / glossaryTerms）＋ STAT_LABELS（stat key）。 旁附 RefText 即時預覽。複用：useGameData、STAT_LABELS（src/utils/moduleStats.ts）、RefText（src/components/RefText.tsx）。
決策六：GlossaryAdmin + 後台接線
新增「詞條管理」分頁，沿用 src/pages/user/admin/shared.tsx 的 AdminModal / Field / useNewItemCreation 樣式； AdminPage 加 Tab 與 TAB_CONFIG 設定。詞條編輯面板含 id（term_<名稱>）/ name / category / description（textarea）＋ RefPicker / aliases / icon。
決策七：RefPicker 接進 PilotSkillsTab
技能「效果說明 description」欄位下方掛 RefPicker，編輯技能即可把描述內 [xxx] 標進 skill.descriptionRefs（寫入 pilotSkills 單一資料源，全站生效）。
決策八：安全規則
firestore.rules 與 security-rules.html 加 glossaryTerms（所有人可讀、管理員可寫，仿 pilotSkills）。 規則部署需使用者授權。

Verification
驗證方式
  1. 型別：npm run build 通過；GlossaryTerm 為新增、不破壞既有頁面。
  2. term 解析：建一筆 term_固定傷害，前台某描述的 [固定傷害] hover/點擊顯示解釋（先前 pending）。
  3. RefPicker：在詞條管理 / 技能效果用 RefPicker 把 [xxx] 指派到實體 → 儲存後前台該詞變可點擊；未指派者原樣顯示不報錯。
  4. 非工程流程：非 OWNER 的 ADMIN 帳號全程用表單 + RefPicker 新增詞條並在前台引用，不碰程式碼。
  5. 查詢量：glossaryTerms 經預載 Map + localStorage 版本快取，回訪 0 讀取。
