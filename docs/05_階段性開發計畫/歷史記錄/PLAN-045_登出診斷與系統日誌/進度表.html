⚠ 已知限制（本計畫範圍外，未修）
多分頁主動登出會產生假的 tokenRevoked 記錄。 explicitSignOut 旗標是 module-scope，每個分頁各有一份。在分頁 A 按登出時， 分頁 B 收到 onAuthStateChanged(null) 但自己的旗標是 false，而判定只看哨兵 （B 的哨兵一定在）→ 必定記一筆 tokenRevoked。sessionStorage 去重擋不住（B 是另一個分頁）。
維護者常同時開後台與前台，故這會固定發生。修法不難（signOut 時往 localStorage 寫一個短時效標記， 判定時併入 explicit 判斷），但屬於獨立議題，留待日後處理。
判讀影響：看到 tokenRevoked 時，若該使用者當時開著多個分頁， 要先排除這個可能再當成真實故障。
🐛 瀏覽器實測抓到的缺陷（已修正）—— IndexedDB 探針測不到東西
初版讓「Firebase 的 firebaseLocalStorageDb 還在不在」參與判定。實測發現那顆探針 恆為 present：該 database 會在 SDK 初始化時自動重建， 等 onAuthStateChanged(null) 觸發、探針執行時，就算前一秒手動刪光整個 database，它也回來了。

兩層後果：① idbEvicted 永遠產生不出來，該情境全數落到 tokenRevoked； ② 更嚴重——「cookie 沒了但 IDB 還在 → 證明登入過 → storageCleared」這條，讓 每個第一次進站的匿名訪客都會看到登出橫幅。

修正：判定只用不受 Firebase 干擾的兩顆哨兵；探針改為檢查 firebase:authUser:* 記錄是否存在（名實相符），保留為佐證欄位但不參與判定；idbEvicted 退場。

順帶修掉重複記錄：onAuthStateChanged(null) 不是「登出那一瞬間」才觸發， 只要處於未登入狀態，每次重新載入頁面都會再觸發一次 —— 實測時刪 IndexedDB 就抓到兩筆 （刪除當下一筆、F5 重整一筆）。改用 sessionStorage 旗標去重：重整保留、關閉分頁清除、登入時解除。 橫幅不受影響（重整後仍顯示——提醒使用者與記不記錄是兩件事）。

單元測試為什麼沒抓到：它測「給定探針值 → 判定是否正確」， 而錯的是探針值本身測不到真實狀態。那一層只有真實瀏覽器測得出來—— 這正是把手動驗證列為獨立任務的價值。現已補一條測試釘住 「authRecord 的任何值都不得改變判定結果」。
🐛 使用者實測抓到的缺陷（已修正）—— 草稿存錯了層
初版把 autosave 接在列表元件、監聽 editing。但 12 個編輯頁的共同結構是 編輯器內部自己持有表單狀態（const [form, setForm] = useState({ ...item })）—— 使用者打字改的是 form，外層的 editing 從打開編輯器到按下存檔之間完全不變。 於是草稿存下來的是「打開編輯器那一刻的原始快照」。
症狀極具欺騙性：偵測提示會正確跳出（確實有未存編輯），但按下還原拿回來的是原始版本。 這比沒有草稿功能更糟，因為它讓使用者以為內容救回來了。

修正：拆成兩個 hook —— useDraftWrite 接在編輯器內部監聽 form、 useDraftRestore 留在列表層負責讀取與還原。還原之所以生效，正是因為編輯器用 useState({ ...item }) 從 prop 初始化：setEditing(草稿) → 編輯器 mount → form 即為草稿內容。

連帶修掉三個同層級的問題：
· 打開就留草稿：加 dirty 比對（與掛載當下快照比較），「點開看一眼就切走」不再留下無意義的草稿；
· 還原後草稿被自己吃掉：還原後 dirty 基準變成草稿本身，使用者若「還原後先去查點東西」而切換分頁， dirty 判斷會認定沒改而清掉剛救回的內容。加了還原保護（只有存檔成功或明確捨棄才能清）；
· 按取消不清草稿：取消等於明確放棄，11 處 onCancel 補上 draft.discard()。

決策已抽成 shouldClearOnRevert() 純函式並以測試釘住 —— 這一層唯一的失效模式是 靜默的資料遺失，沒有錯誤訊息，只能靠測試守。
⚠ 實作過程中與原規劃不符的四點（已修正本表）
① 誤報漏洞：一顆哨兵不夠。原設計只在 localStorage 種哨兵，但從未登入過的訪客 同樣沒有哨兵、同樣觸發 onAuthStateChanged(null)，會被誤判成 storageCleared —— 而前台每次載入都會觸發。 改為 localStorage ＋ cookie 兩顆（不同存活條件），先回答「這台裝置登入過沒有」，並新增 neverSignedIn 態代表「不產生事件」。
② TTL 不需要到 Console 手動設定。原本以為要人工操作，實際上 firestore.indexes.json 的 fieldOverrides 支援 "ttl": true 宣告（changeHistory 早已如此），隨 deploy 一併生效。
③ firestoreCore 原本沒有寫入函式。原計畫寫「在 firestoreCore 的寫入路徑攔截」， 但實際寫入分散在 12 個模組的 update*（8 個自己 setDoc、4 個走 saveWithHistory）。 改為新增 writeDoc / writeDocRaw 統一入口並改接全部呼叫端 —— 順帶讓 stripUndefined 不再有人漏掉。
④ GrayOpsAdmin 的編輯模型不同。它沒有 editing: T | null 的開關生命週期， form 從掛載到卸載都存在，照接會變成「永遠有草稿」而每次進頁都跳假提示。 改以「與已存檔內容不同」（dirty）為存草稿條件，並用 useMemo 穩定 reference （否則 debounce 每次 render 重新計時 → 靜默永不寫入）。
