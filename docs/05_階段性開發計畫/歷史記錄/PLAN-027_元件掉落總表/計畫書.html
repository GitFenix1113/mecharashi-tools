◆ PLAN-027

元件掉落總表Component Drops · 攻略資料工具 · 可匯出圖片

攻略區第一個資料工具頁：把各關 BOSS 的元件掉落整理成可切換分頁、帶圖示的矩陣總表，並能一鍵匯出成圖片分享。純前端組裝現有 Firestore 資料，零新型別、零寫入。

與 PLAN-010 攻略系統的關係： PLAN-010 是 TipTap 手寫圖文 CMS（管理員撰寫敘事型攻略），目前 PENDING 且尚未開工。 本計畫是資料驅動的工具頁（從 Firestore 自動生成，非手寫），性質同 guides/tools/ 下的彩甲規劃器（PLAN-018）。 兩者互相獨立 —— 本計畫不依賴、也不阻塞 PLAN-010，可即刻開發。
Problem
問題背景
掉落資訊只能逐一查、沒有總覽
元件的 BOSS 掉落關卡（dropStages）目前只在各元件詳情的 BossDropTooltip 裡分散顯示。 玩家想回答「某一關能刷到哪些元件」或「想要的元件要去打哪關的第幾個 BOSS」時， 必須一個個點開元件比對，缺少一張把「元件 × 關卡 × BOSS」攤平的總覽表。
社群靠手工 Excel 表分享，難維護
現況玩家間流傳的是人工維護的 Excel 掉落表（如本計畫參考的截圖），資料會隨改版過期、也無法對上站內元件圖示。 我們已有結構化的 dropStages 資料，理應能自動產生一張永遠與資料同步、帶官方圖示、可匯出分享的表，取代手工表。
Design
設計決策
決策一：定位為獨立「資料工具頁」，而非 PLAN-010 的 CMS 文章
內容 100% 由 useComponents() 的資料自動生成、無敘事文字，與 PLAN-010 的手寫富文本本質不同。 因此比照彩甲規劃器，實體檔案放 src/pages/guides/tools/ComponentDropsPage.tsx， 路由掛 /guides/component-drops。與 PLAN-010 CMS 解耦，不受其 PENDING 狀態阻塞。
決策二：5 個 Tab 直接映射現有型別維度，零新資料
分頁維度完全對應既有欄位，不需要新增任何型別或 Firestore 欄位：
// Tab ← componentType（觸=Condition / 應=Function）× componentsWType（W / Normal） 總表 = 全部元件 觸元件 = componentType==='Condition' && componentsWType==='Normal' 觸元件W = componentType==='Condition' && componentsWType==='W' 應元件 = componentType==='Function' && componentsWType==='Normal' 應元件W = componentType==='Function' && componentsWType==='W'
英文命名對照（供 Tab 標籤 / 匯出檔名 / i18n 用）：
  • 觸元件 = Trigger（型別值仍為 componentType: 'Condition'，勿混淆）
  • 應元件 = Reaction（型別值仍為 componentType: 'Function'）
  • W 版即在後方加 W：Trigger W / Reaction W（呼應官方 Excel 表頭「TriggersW」）
決策三：矩陣表結構 —— 列＝元件、欄＝首領關卡、格＝BOSS 編號
沿用 src/data/bossDrops.ts 既有純函式組裝，前端不重造輪子：
  • 欄（首領關卡）：getAllStages(list) 蒐集該 Tab 出現過的 stage，由小到大當表頭；表頭配 getBossImagePath() BOSS 頭像。
  • 列（元件）：每列一顆元件，左側「名稱」欄用 ComponentIcon 顯示圖示＋名稱（呼應「不要純文字」需求），並有「等級」欄顯示 probabilityLevel（Lv.N）。
  • 格：以 getComponentDrops(comp) 找出該元件在該 stage 掉落的 bosses[]，格內標 #BOSS編號（如 #3）；無掉落則留白。
決策四：匯出「當前 Tab」為 PNG，沿用已裝的 html-to-image
專案已安裝 html-to-image（SimulatorPage / VersionQuickTable 已在用），不需新依賴。 點「匯出圖片」對當前 Tab 的表格容器 toPng() 產生下載。第一版只匯出當前分頁那張表（符合截圖情境），一鍵匯出全部 5 張列為未來增強。
⚠️ 邊界與注意
  • 大表寬度：關卡多時表格很寬，畫面需可橫向捲動；匯出時應擷取完整表格（非可視區），必要時鎖定匯出用的固定寬度樣式。
  • 深色背景：toPng 預設透明背景，需指定 backgroundColor 為站台深色，避免匯出圖透明/白底。
  • 圖片載入時機：BOSS 頭像與元件圖示均為同源本機圖（/images/...），無跨域 CORS 問題；但匯出前需確保圖片已載入完成再截圖。
  • 無掉落元件：部分元件 dropStages 為空（非 BOSS 掉落）。需決定是否列出——第一版於「總表」保留、掉落欄全空即可，或加篩選「只看有掉落」。
Scope
實作範圍與不在範圍內
在範圍內：
  • 新頁 /guides/component-drops，5 個 Tab 切換（總表／觸元件／觸元件W／應元件／應元件W）
  • 元件 × 首領關卡 × BOSS 編號的矩陣表，含「等級」欄（probabilityLevel）
  • 元件以圖示（ComponentIcon）呈現，表頭以 BOSS 頭像呈現
  • 匯出「當前 Tab」表格為 PNG
  • 攻略頁（GuidesPage）新增此工具的入口卡片
不在範圍內：
  • 手寫敘事型攻略 CMS（屬 PLAN-010，另案）
  • 掉落機率數值 / 期望次數等統計（目前無此資料來源）
  • 後台編輯掉落資料（已由 PLAN-025 的 ComponentAdmin 管理 dropStages）
  • 一鍵匯出全部 5 張表（列為未來增強）
