◆ PLAN-023

神經驅動能力庫與模擬接入 · Ability Collection · 算力閘控 · 模擬就緒

把神經驅動的「能力節點」抽成以能力名為唯一鍵的共用庫，解決分區內共用節點的重複維護，並讓每個能力成為傷害模擬可達性的結構化來源。

🔄 本計畫 supersede（取代）PLAN-004 技能資料抽離 的「下半場 neuralDrives」部分——PLAN-004 原以「分區為單位 + scope 欄位」建模，本計畫依實機資料更正為「能力節點為單位」。PLAN-004 重新定義為純 pilotSkills 抽離並準備收尾。本計畫亦為 PLAN-019 總綱 Layer 1（引用）+ Layer 2（模擬可達性）在神經驅動上的落地。

一句話：神經驅動真正可共用的最小單位是「能力節點」（如 運動戰4、AP優化3、終結者1）， 不是分區。把能力抽成以能力名為唯一鍵的 neuralDriveAbilities 集合；機師的分區排列（哪個能力放哪個位置、算力門檻）仍嵌在 Pilot，但每個位置改為引用能力 ID。一舉同時解掉「重複維護」與「模擬缺結構化來源」兩個問題。
Problem
問題背景
問題一：分區內存在大量重複的共用能力節點
實機資料顯示，同一分區裡有些節點跨機師完全相同、有些是機師專屬。以 γ1 區 兩位格鬥家為例：
γ1 · 終結者機師 γ1 · 窮追猛打機師 Lv1 終結者1 算力1 Lv1 窮追猛打1 算力1 ← 機師專屬 Lv2 AP優化3 算力4 Lv2 AP優化3 算力4 ← 完全相同（共用） Lv3 運動戰4 算力7 Lv3 運動戰4 算力7 ← 完全相同（共用） Lv4 終結者2 算力10 Lv4 窮追猛打2 算力10 ← 機師專屬 Lv5 終結者3 算力13 Lv5 窮追猛打3 算力13 ← 機師專屬 Lv6 終結者4 算力16 Lv6 窮追猛打4 算力16 ← 機師專屬
再加上 α 區 對同職業機師幾乎整片相同。現行 Pilot.neuralDrive[] 把這些能力連同分區整個嵌入機師文件， 導致共用能力（運動戰/AP優化/動力革新）在大量機師中各存一份副本，改一處要逐機師同步。
問題二：PLAN-004 下半場的原模型抽象層級錯誤
PLAN-004 想把「整個分區」抽成一份文件、加 scope: 'class' | 'pilot' 區分職業共用 / 機師專屬。 但上表證明共用發生在「節點」層級，不是「分區」層級：同一個 γ1 同時混有共用節點與專屬節點。 用分區當單位會兩頭不到岸——γ1 因機師而異 → 仍每人一份；真正重複的 AP優化3/運動戰4 → 又沒被去重。
問題三：模擬缺結構化來源 + 引用層缺口
神經驅動能力大量牽涉傷害 / BUFF（如 火力至上4「每消耗 1AP 傷害提升 7.5%，最多 45%」、終結者4 對軀幹造成 [固定傷害]）， 是未來傷害模擬的重要輸入；但 NeuralDriveLevel.effect 目前是純字串，沒有可被模擬器消費的結構化來源。 另外 NeuralDriveLevel 沒有 descriptionRefs——它是全站唯一「帶描述卻沒接上 PLAN-019 Layer 1 引用層」的實體， effect 內的 [再攻擊]/[固定傷害] 等 token 永遠無法點擊。
能力的異質性（為何需要「集合」而非單純去重）：神經驅動能力可能是 直接強化數值（AP上限+1）、改變天賦、賦予 BUFF（火力至上「獲得 1 層 [怒放]」）、 提升 / 強化既有技能，未來還會出什麼效果難以預測。需要一個可擴充的容器來承載這些異質能力， 而不是把它們鎖死在字串裡。這正是「能力庫」的核心價值——不是為了搬家，是為了給異質能力一個結構化、可演進的家。
Design
設計決策
決策一：以「能力名」為唯一鍵的 neuralDriveAbilities 集合
每個能力節點獨立為一份文件。實機資料中能力名不重複（一個名字恆指同一能力）， 因此「能力名」即天然主鍵——比 pilotSkills 當初要用「名稱 + description」去重更乾淨、零碰撞風險。 ID slug：nd_<能力名>（如 nd_運動戰4、nd_AP優化3、nd_終結者1）。
決策二：分區排列嵌入、能力內容抽離（混合）
「哪個能力放在哪個分區的哪一級、算力門檻多少」是機師專屬排列 → 維持嵌在 Pilot.neuralDrive； 能力的內容（描述 / effects / buffIds）是可共用資產 → 抽到集合，分區的每一級改為引用 abilityId。 α 區整片相同的能力自動去重；γ 區雖排列因機師而異，但也只是「不同的 ID 引用組合」，成本極低。
決策三：能力是「累積」生效，不是互斥
實機顯示算力達標後，同分區多個能力同時「已啟動」並持續疊加（非 PLAN-021 凝勢 I/II/III 那種取最高）。 因此模擬時 神驅貢獻 = Σ(該區所有 minSum ≤ 當前算力 的能力 effects)，能力層不做互斥收斂。 互斥只發生在 buff 層——若某能力賦予一個形態 buff，才依該 GameBuff.mutexGroup 收斂。兩者分層、不衝突。
決策四：不設 scope 欄位，共用為引用圖的湧現屬性
一個能力被 N 位機師引用 = 它就是共用的；被 1 位引用 = 它就是專屬的。不需要、也不該存一個易判斷錯的 scope 欄位（PLAN-004 原設計的風險點之一）。後台若要顯示「此能力被幾位機師使用」，由引用反查推導即可。
決策五：雙格式過渡 + 爬蟲改 ID-aware；PLAN-021 完全不動
比照 pilotSkills 的安全過渡：分區的 level 暫時相容「嵌入舊欄位」與「abilityId 新欄位」， 以 resolveNeuralDriveAbilities() 解析，穩定後再 flip。同時爬蟲的 neuralDrive 合併要改 ID-aware （目前 mergeNeuralDriveArray 無條件用嵌入合併，flip 後會倒退；需比照 skills 加「已是 ID 則跳過」邏輯）。 天賦改寫（PilotTalent.ndVariants）由 PLAN-021 負責， 因 zone / minSum 仍留在 Pilot，本計畫零回頭改 PLAN-021。
Schema
資料模型
// 【新集合】neuralDriveAbilities —— 能力庫，以能力名為唯一鍵 export interface NeuralDriveAbility { id: string // nd_運動戰4 / nd_AP優化3 / nd_終結者1 name: string // = 現 NeuralDriveLevel.skillName（卡片標題） effect: string // 描述正文（= 現 NeuralDriveLevel.effect） descriptionRefs?: DescriptionRefs // PLAN-019 Layer 1，補完神驅引用缺口 icon: string iconLocal: string effects: SkillEffect[] // 數值強化 → 模擬加總 buffIds: string[] // 賦予 buff（形態 / 狀態） manual?: boolean // 比照 pilotSkills，補丁不覆寫人工填值 } // 【改】Pilot.neuralDrive —— 分區結構保留嵌入，level 改引用能力 export interface NeuralDriveZone { name: string // α / β / γ1 / γ2 icon: string slots: string[] // 插槽芯片類型（顯示 + 未來晶片裝配） levels: { level: number minSum: number // 算力門檻（位置決定，資料驅動不寫死） abilityId: string // → neuralDriveAbilities }[] }
過渡型別（雙格式）：flip 完成前，levels[] 元素相容「嵌入舊欄位（skillName/effect/effects/buffIds）」與 「abilityId + minSum」兩種；resolveNeuralDriveAbilities(zone.levels, abilityMap) 統一解析成 NeuralDriveAbility[]，前端不需在意目前是哪種格式（完全比照 resolvePilotSkills）。
模擬啟用流程（Layer 2 接入，給未來模擬器）
算力（來自算力晶片，見 N3） │ 每區加總 ▼ 各區達標能力（minSum ≤ 算力，全部啟用、累積） │ 收集 effects[] + buffIds[] ▼ effects 直接加總 ── buffIds 注入可用 buff 池 ── 依各 buff mutexGroup 收斂 ── 面板輸出
Scope
實作範圍與不在範圍內
在範圍內：
  • N1 能力庫抽離：NeuralDriveAbility 型別 + Pilot.neuralDrive 雙格式；以能力名去重的遷移腳本（dry-run + __REVIEW__ 報告）；爬蟲 neuralDrive 改 ID-aware；getNeuralDriveAbilities + GameDataContext 預載 + resolveNeuralDriveAbilities；PilotDetailPage 神驅渲染改走 resolve；Stage 2 flip。
  • N2 引用層 + 後台：能力加 descriptionRefs（RefText 接 refs，補完神驅 Layer 1 缺口）；NeuralDriveAbilityAdmin 後台分頁（複用 SkillAdmin 模式 + RefPicker）；資料模型文件。
不在範圍內（標為後續 / 暫不納入）：
  • N3 算力晶片系統：算力晶片（帳號級養成道具，帶六維 / 算力 / 額外效果）為獨立系統。 無官方爬蟲源、能力固定且不易新增 → 走 一次性手動維護 的 biochips 集合（連 scrape 都不需要，純後台手 KEY）。 其「算力 → 能力啟用」resolver 與接 PLAN-019-B 反向索引、γ 區算力上限規則，深度綁定模擬器。本計畫先把能力模型設計到位，讓 N3 之後無痛插入，但不在本計畫實作。
  • 天賦改寫（PilotTalent.ndVariants）：已由 PLAN-021 完成，本計畫不動。
  • 模擬器計算核心（buff 面板 / 傷害加總）：屬 PLAN-019-B / 未來模擬器 PLAN。
