Problem
問題背景
官方資料更新太慢，社群等不及
新機師上線後，官方資料（本站爬蟲來源）常有明顯落後。夥伴們希望能自己先把新機師的資料建進站內， 不必枯等官方更新。目前後台「機師管理」只能編輯既有機師，沒有「新增機師」入口。
神經驅動完全無法在後台編輯
Pilot.neuralDrive[]（分區 / 插槽 / 各級算力門檻 / 對應能力）目前標註「由爬蟲腳本管理」， 後台沒有任何編輯 UI。手建機師若不能編神驅，資料就是殘缺的。
手建機師有被爬蟲補丁覆寫的風險
爬蟲 scrape-pilots-v3.js 以機師名比對、只補丁 Firestore 既有機師。 手建機師目前天然安全（官方查無同名），但一旦官方日後出了同名機師，補丁就會覆寫人工資料—— 比照 PilotSkill.manual / PilotTalent.manual，機師層也需要一個保護旗標。
Design
設計決策
決策一：沿用 upsert，不新增 addPilot
updatePilot() 內部是 setDoc(doc(db,'pilots',id), ...)，本身即 upsert—— 新增與更新走同一條路徑。資料層完全不用動，只需在 PilotAdmin 補「新增」入口， 以空白預設值開啟既有的 PilotEditPanel。
決策二：文件 ID 走 pilot_<中文名>（PLAN-020 慣例）
用 makeEntityId('pilot', name) 由名稱生成 ID，天然與官方長碼 Pilot_1010XXXX 分流、不撞號。 建立前以 docExists('pilots', id) 做伺服器端撞名檢查，導引去編輯既有項。 複用 useNewItemCreation + NewItemDialog（技能 / 神驅能力庫 / BUFF 都用它）。
決策三：新增隱形 Pilot.manual 旗標（純爬蟲保護，不做前台標示）
比照技能 / 天賦的 manual 語意：手建機師設 manual: true，爬蟲補丁迴圈遇到即整筆跳過。 前台不因此顯示任何「社群自建」標記（依需求：手建與官方機師外觀一致）， manual 僅作後端防覆寫用途。
決策四：神經驅動編輯器只做「結構 + 引用」，不在此編能力效果
PLAN-023 已把神驅拆成兩層：能力庫（neuralDriveAbilities 集合，已有完整後台） 與機師引用（Pilot.neuralDrive[].levels[].abilityId）。 本計畫的機師神驅分頁只負責「這位機師有哪些分區、插槽是什麼芯片、各級算力門檻多少、每級連到能力庫哪個能力」， 能力本身（名稱 / 效果 / BUFF）仍在既有「神經驅動」分頁維護。 因此機師端是一個結構性表單 + 下拉引用，複雜度可控。
邊界：手建機師缺少爬蟲衍生欄位
statsBase / apBase / profile.additionalInfo / portraitUrl 無官方來源。 預設值工廠給空物件（statsBase:{}、additionalInfo:{}）與合理回填（apBase 複製 ap）。 前台既有渲染皆已對這些欄位做 ?? {} / 選填處理，不會因此崩壞（需回歸驗證）。
邊界：神驅連結能力庫須先有能力
機師神驅每級要連到 abilityId，前提是能力庫已有該能力。編輯器在下拉查無時， 需提示「請先到『神經驅動』分頁建立能力」並提供引導，避免夥伴卡住。
Scope
實作範圍與不在範圍內
在範圍內：
  • Pilot.manual?: boolean 型別欄位 + 同步 docs/02_技術文件/02_資料模型/pilots.html
  • PilotAdmin 新增「＋ 新增機師」對話框（ID 自動生成 + 撞名檢查）
  • 新機師預設值工廠（六維 0、ap、空 base、空 talents/skills/neuralDrive、manual:true）
  • 爬蟲 scrape-pilots-v3.js 補丁跳過 manual === true 的機師
  • PilotEditPanel 新增「神經驅動」分頁 + PilotNeuralDriveTab 元件（分區 / 插槽 / 各級門檻 / abilityId 引用）
  • 神驅未連結能力的提示與引導
不在範圍內：
  • 前台區分「玩家自建 / 官方」的視覺標記（本次決定不做）
  • 神驅「能力」本身的效果編輯（仍在既有「神經驅動」分頁）
  • 新的權限角色（夥伴沿用既有 ADMIN 權限）
  • 機師刪除功能（本次僅新增 / 編輯）
  • 爬蟲衍生欄位（statsBase/apBase/additionalInfo）的人工編輯 UI（維持唯讀 / 空預設）
