BUFF 後台管理BuffAdmin · buffs CRUD · 引用挑選器

為 buffs 集合補上寫入 API 與後台管理面板，讓非工程人員也能新增／編輯 BUFF，並在描述裡標引用——補完 019 引用層最後一個「只能讀、不能在後台維護」的實體。

前置依賴
PLAN-019-A（引用層）· PLAN-019-C（RefPicker）— 皆已上線
一句話：其他帶描述的實體（模組／武器／元件／背包／技能／詞條）都已能在後台 CRUD 並標引用，唯獨 buffs 至今只有 getBuffs 讀取、沒有寫入 API、也沒有後台 UI，新增一筆 BUFF 只能靠 seed 腳本或 Firestore console。 本子計畫補上 updateBuff 與一個 BuffAdmin 分頁，讓 BUFF 也能像其他實體一樣在後台維護、並在描述下方掛 RefPicker 標引用。屬總綱 019-E「引用型 Admin」收尾的一塊。
Problem
問題背景
buffs 沒有寫入路徑：src/lib/firestoreApi.ts 只有 getBuffs()（讀），沒有對應的 updateBuff。 AdminPage 的分頁列也沒有 BUFF。維護者要新增／修改一筆 BUFF，只能改 seed 腳本（firebase-admin）或直接進 Firestore console 手動建文件——非工程人員無法操作，與「讓維護者自助維護資料」的目標衝突。
引用閉環缺一角：RefPicker 已能把描述裡的 [xxx] 指向 buff，前台 EntityRefView 也能解析 buff 並顯示詳情； 但由於 buff 本身無法在後台建立/補資料，buffs 集合長期偏空，導致「指向 buff 的引用」常常查無候選或內容不全。先讓 BUFF 能被維護，引用體驗才完整。
Design
設計決策
決策一：補 updateBuff 寫入 API（仿 updateComponent）
走既有寫入慣例：剝離 id → setDoc 寫入 buffs/{id}（stripUndefined）→ bumpDataVersion() 使快取失效。 firestore.rules 的 buffs 已具備 allow write: if isAdmin()，無需改安全規則。
// src/lib/firestoreApi.ts export const updateBuff = async (buff: GameBuff): Promise<void> => { const { id, ...data } = buff await setDoc(doc(db, 'buffs', id), stripUndefined(data)) await bumpDataVersion().catch(() => {}) }
決策二：新增「BUFF 管理」分頁 + BuffAdmin 面板（仿 ComponentAdmin / GlossaryAdmin）
AdminPage 的 Tab 型別與 TAB_CONFIG 加 'buffs'（keys: []、selfLoading: true、searchable: true）， 加一顆 TabButton「BUFF 管理」 與對應渲染。新檔 BuffAdmin.tsx：列表以 getCollectionPage('buffs') 分頁查詢 + 名稱開頭搜尋； 新增（id 規則 buff_<名稱>）；編輯面板欄位如下。
// BuffAdmin 編輯面板欄位（對應 GameBuff） name // 名稱 buffType // 下拉，用 BuffType enum：statBoost/resource/state/debuff/control maxStack? duration? mutexGroup? // 疊加 / 持續回合 / 互斥群組 description // 描述；下方掛 <RefPicker> 標 [xxx]（buff 也可引用其他 buff） effects[] // 複用 PilotAdmin export 的 <SkillEffectItem> 編輯器 icon?
決策三：最大化複用，零新元件骨架
效果編輯器複用 SkillEffectItem（PilotAdmin 已 export）、引用挑選器複用 RefPicker、列表/Modal/搜尋複用 shared.tsx 的 AdminModal / Field / useServerPaged / LoadMoreButton / useNewItemCreation。buffs 已接入 GameDataContext（讀、預載、reload）， 寫入後 bumpDataVersion 即同步全站；前台引用顯示無需任何改動。
Scope
實作範圍與不在範圍內
在範圍內：
  • updateBuff 寫入 API
  • AdminPage「BUFF 管理」分頁接線
  • BuffAdmin 面板：列表 + 新增 + 編輯（含 buffType 下拉 / effects 編輯器 / 描述掛 RefPicker）
  • docs（skills_buffs 資料模型、Firebase buffs 設計文件）、019 總綱進度、siteChangelog feat
不在範圍內：
  • PLAN-019-B 的模擬器 buff 反向索引／形態互斥面板（可用 buff = ⋃ 配裝 buffIds[]）—— 屬 Layer 2 模擬層
  • buff 刪除：先做 新增/編輯（C+R+U）；刪除涉及「是否仍被 descriptionRefs / buffIds 引用」的連動檢查，視需求後議
  • buff 圖示上傳（沿用既有 icon 字串欄位即可）

Verification
驗證方式
  1. 型別/建置：npm run build 通過。
  2. 新增：後台 BUFF 管理 → 新增一筆 BUFF（buff_xxx）→ 填名稱/類型/描述/效果 → 儲存後列表可見。
  3. 引用：描述含 [xxx] → 下方 RefPicker 可指派；前台某描述指向此 buff → 可懸停預覽、點擊看詳情。
  4. 持久化：儲存走 updateBuff + bumpDataVersion，重整後資料仍在、快取更新；其他分頁/前台同步看得到。
