我的配裝 Tab
版面與互動
項目 說明
資料來源 users/{uid}/builds/{pilotId}（一位機師一份文件，slots 是 '0'～'4' 的 map，每格是一串 base64url 分享代碼）。經 listCloudBuilds() 一次讀取，不用 onSnapshot。
⚠ 2026-08-29（PLAN-052-E）換過模型：舊版一份文件是一整套配裝（buildName／weaponId…），已整條刪除，userApi 的 getUserBuilds／saveBuild／deleteBuild 三支也不存在了。
分組與排序 依機師分組，每組最多 5 張卡並依格位（1–5）排序；機師之間依該機師的 updatedAt 由新到舊。
配裝卡片 格號、方案名稱（或機甲名）、機甲、武器數、形態數。全部由代碼當場解出來，不存名稱快照——第二個真相源遲早會對不上。
失效三態走 classifyBuild()（lib/buildStatus.ts，與模擬器書架同一支）：degraded 標「有 N 項裝備已下架」，broken 停用載入鍵並說明原因。
載入配裝 導向 /simulator?b=<代碼>，與書架、分享碼同一條進場路徑。
⚠ 舊版那條 navigate('/simulator', { state: { build } }) 已刪除——第二種進場方式意味著 LoadoutPage 要維護兩套還原邏輯。
刪除配裝 兩段式確認後呼叫 deleteCloudBuild(uid, pilotId, slot)。刪掉最後一格時整份文件一起刪，不留 slots: {} 的空殼。
空狀態 說明「在配裝模擬器配好一套，打開『書架 → 雲端』就能存進來」，並點出每位機師 5 格、換裝置看得到。
載入成本 清單獨立成 components/profile/CloudBuildList.tsx，只在本分頁開啟時掛載——它要 useLoadoutGameData('equip')（六個集合）才解得開代碼，寫在 ProfilePage 裡會變成「只是開個人資料頁也把整個遊戲資料庫拉一次」。
