版本速覽 /versions/quick

五個版本 × 各更新類別的濃縮對照表，可輸出 PNG 分享。置中 max-w-[1500px]：表格本身 minWidth: 880px（縮圖放大後調高，原 720px），過去塞在首頁面板裡幾乎永遠貼著下限 （十一個欄位每格只剩 60px）。 2026-08-19 起首頁不再放資料，這裡是它唯一的呈現位置，寬度給到底。

灰燼行動 /versions/grayops

四間公司的未來機甲一覽（lg:grid-cols-4），標註各機甲的預期登場版本。置中 max-w-[1400px]。

版本時間線 /versions/timeline

頂部信箱式橫幅帶（版本名／服別切換／◀▶／常駐版本選擇列），下方左右主從分割： 左為版本資訊表 ＋ 活動甘特（55%），右為活動卡片流（45%），兩欄各有獨立捲動軸、比例可拖曳。

ℹ️ 時間線為什麼沒有「先選版本再展開」這一步：原本是焦點輪播 ＋ clip-path modal， 抵達甘特要四步（捲過 Hero → 點 tab → 滾輪切版本 → 點中央項目），而且 modal 讓 「比較兩個版本」變成不可能 —— 那正是版本頁最常見的問題。 現在版本選擇列常駐、每個版本都有自己的網址，要比較就開兩個分頁並排（PLAN-050 C-2）。
ℹ️ 為什麼是三個獨立網址而不是一個頁面內切分頁：獨立網址同時拿到深連結、上一頁、Ctrl+F 與使用統計分流，又保留「這三者是一組」的心智模型 —— 導覽列只 +1 項（一個下拉）而不是 +3 項。

頁內的分頁列已於 2026-08-19 隱藏：導覽列的「版本情報 ▾」已經是三個檢視的入口， 頁內再放一條同樣的分頁列是同一組導覽出現兩次，而它吃掉的是 Timeline 最缺的垂直空間。

2026-08-20：分頁列以另一種形式回來了——改由 layout/SubNavTabs 貼在 header 下方而非頁內，版本情報／圖鑑／攻略三群共用同一套。當初拿掉頁內分頁列的兩個理由 在那邊都解掉了：高度固定 2.25rem 且由 --subnav-h 從 .viewport-shell 扣除（不會多擠出捲軸），而它取代的是「每次換檢視都要把滑鼠移上導覽列、 等展開條出來、再挑一個」這段手續。
components/versions/VersionViewTabs.tsx 因此不要再加回 VersionsLayout， 元件本體留著只為了 VERSION_VIEWS。

✅ 已實作（PLAN-050 Phase A）
· 外殼高度：.viewport-shell＝calc(100vh - 3rem - 1px - var(--subnav-h, 0px))，行動版再扣底部 Tab Bar； --subnav-h 由 Layout 依當前路由設成 2.25rem（有常駐分頁列）或 0px。 改分頁列高度時兩邊要一起改，否則這三頁會多出一條文件捲軸。 Layout 對 /versions 不渲染 footer 與底部佔位（比照首頁）
· 分頁列元件：src/components/layout/SubNavTabs.tsx（header 下方常駐，全站群組共用）。 舊的頁內分頁列 src/components/versions/VersionViewTabs.tsx 不渲染也不要加回來（見上）。 其 VERSION_VIEWS 仍在使用 —— 首頁的入口連結由它產生，首頁自己不放任何版本資料， 但要有地方讓人點進來
· Timeline 以 lazy() 載入，首頁初載 bundle 減少約 43 KB
· /versions/timeline/:version：網址就是狀態。第一次選版本為 push、之後的切換為 replace —— 否則在版本選擇列上點五下，上一頁就要按五次
· 主從分割比例存 mecharashi_timeline_splitPct（35–75% 夾住，雙擊分隔線還原 55%）； <lg 不套用分割，退回單欄單軸（左右分割在 390px 上等於原病復發，行動版正解是 Phase D 的分段切換器）
· 正式名稱：「版本速覽」（2026-08-19 定名，舊稱「版本濃縮資訊」）—— 與導覽列、首頁入口按鈕一致，站內只有一個叫法。 區塊標題字級同步由 11px 的眉標樣式改為 18px 的頁面標題（灰燼行動同步）， uppercase 一併拿掉：中文沒有大小寫，那個 class 從來沒有作用
· 字級與縮圖尺寸重新校準（2026-08-19）：這兩張表的字體與圖片是當年為了塞進 首頁面板（48vw）而壓小的，獨立成頁後顯得空曠且比例失衡。 速覽表縮圖 43 → 57px、內文 13 → 14px、版本號 13 → 15px； 灰燼行動縮圖 28 → 38px、機甲名 14px 並吃滿剩餘寬度（版本徽章因此對齊到列的右緣）。 並重新擠出垂直預算，讓 1080p 不必捲動：版本號與日期改成同一行（省 22px）、 縮圖列的上下內距 py-2.5 → py-1.5（縮圖自帶邊框，7px 留白已足夠）、 專武配對卡與外層內距一併收緊。實測 1920×914（1080p 視窗扣掉分頁列與書籤列） 內容高 817px / 可用 856px，三頁皆不捲動；字級切到「大」(21px) 時會捲，那是選了大字級的必然
· 橫幅改為頂部信箱式色帶：資料區因此是不透明實色， BANNER_OPACITY / BANNER_SCRIM / SURFACE 三顆透明度旋鈕全數退場
· 使用統計：五個樣板已登記於 src/lib/analytics/routeKeys.ts，routeKeys.test.ts 會擋下漏登記
