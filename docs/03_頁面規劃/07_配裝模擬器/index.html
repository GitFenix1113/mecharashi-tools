三斷點版面

≥1280 三欄「機師卡＋算力 340 ｜ 槽位 HUD 1fr ｜ 情境欄 380」／1024–1279 兩欄（機師卡與槽位圖同欄，算力面板掛在槽位圖下方）／ <1024 單欄。彈性欄是槽位圖不是清單（PLAN-052-I B-2）： 槽位圖是「左節點／機甲／右節點」三區橫排，給固定 400px 每欄只剩 ~80px，武器名全被截掉。
右欄＝情境欄，一欄三種內容（PLAN-052-I D-3）：預設武器與元件列 → 開挑選器時整欄換成挑選器 → 點武器列鑽進元件面板。 刻意不做覆蓋層：四塊同時常駐會讓中欄掉到 ~430px， 低於 LoadoutRig 的 DENSE_MAX_WIDTH = 570， 而且覆蓋層要新增 z-index 層級、focus trap、Esc 三份互動負債。
斷點用視窗寬（useLayoutBreakpoint）， 與指標粗細（useIsMobile，決定就地面板 vs BottomSheet、有無 hover 預覽）正交—— 平板因此得到「兩欄 ＋ BottomSheet ＋ 無 hover 預覽」，是刻意的組合。
單欄版面（PLAN-052-I F-1）：動作鍵移到底部固定列、方案名稱移出 sticky、 帳本列改兩列 narrow 版 ⇒ sticky 抬頭 381px → 225px。 槽位圖多一階 tight（門檻同 LINE_MIN_WIDTH：不畫引線就不需要那道縫）， gap-x-2 ＋ 機甲圖 76px ＋ 名稱折兩行。
⚠ 底部操作列不可貼底：Layout.tsx 已有一條 fixed bottom-0 的手機 Tab Bar（h-14 ＋ safe-area、z-50）， 本頁的列必須疊在它上面（z-40），toast 再疊在兩者之上。
⚠ 這一列的高度是量出來的，不是常數（2026-08-30）：按鈕數會變 （超重多一顆「自動卸至符合」、清空拆成兩顆之後共六顆），字級又是使用者設定 ⇒ 390px 上必然換行。列本身改 flex-wrap（不換行的代價不是難看，是最右邊那顆整顆按不到——本列沒有橫向捲軸）， 高度用 ResizeObserver 量一次，餵給內容底部留白與三處 toast 的 bottom； 原本那組寫死的 7rem／3.25rem 全部退場——它們一被換行破壞， 症狀就是「[復原] 被壓在操作列底下」。

匯出配裝長圖（052-I E）

toPng(el, { backgroundColor: '#0a0c10', pixelRatio: 2, skipFonts: false })， （052-I 初版實測 2000×2586、約 3MB、約 0.5 秒） PLAN-052-L 改版後：2000×5,584 ＝ 2,792 CSS px、4.87MB、787ms （最壞情況，離 iOS Safari 的 canvas 上限還有 33%）。裝備區換成與螢幕同構的十字， 每一格都印武器／背包圖示（2026-08-30；空槽不補空框——那會被讀成「有一件我不認得的裝備」）。浮水印兩層：footer 主標 （mecharashi.wiki＋站名全稱＋非官方聲明）與底噪 MILKHAMA wordmark； 右下印產生日期與遊戲版本（取 patchVersions 的 isTwCurrent）。 分享碼那一欄在 052-C 的 E-1 把它接進來之前整個不印——印占位會有人拿去貼，而它解不開。
⚠ 兩個 toPng 通用地雷：① StrictMode 的 effect 雙呼叫會吃掉「已啟動」旗標 （兩輪都沒拍成，而且只在 dev 出現）；② 背景分頁不觸發 rAF，裸的雙層 rAF 在「按下匯出後切分頁」時永遠不 resolve——站上既有的兩處匯出都有這個問題。

🎛️

六態槽位圖 LoadoutRig

空／已裝／🔒佔據（機甲固定武裝）／🔒全鎖（形態）／▨無槽／預覽。 ▨無槽整格說明原因（「肩部槽位只有中甲機甲才有」「先鋒形態沒有可裝在左肩的武器」）， 不是一個點不下去的空 [+]。雙手武器左右兩格都畫同一把、重量只印一次； 備用組由強襲者背包解鎖，解鎖後直接進左右兩欄。 React key 一律 slotKey()，不可用 weaponId（帕斯卡左右肩是同一把武器）。
幾何自 PLAN-052-L B-1 起集中在 src/utils/rigLayout.ts：螢幕版與匯出圖 各自渲染（字級階、互動語彙、可用寬度都不同），但「畫面左欄＝機體右側」「臂卡插在肩與手之間」 這類空間裁決只有一份 —— 各寫一次的漂移症狀是「同一台機體在畫面上與圖上左右相反」，而兩邊都不會報錯。
⚠ 十字的四端一律半寬置中（軀幹／腿部／背部，2026-08-30 起背部也是）： 整寬時內容全靠左、右半邊一片空，與正上方的腿部卡對不齊，十字的形狀因此讀不出來。 「整排不存在」的肩部仍是整寬 —— 那一列講的是一整排，不是十字的一端。
⚠ 沒有備用槽就不解釋備用槽（2026-08-30）：先前圖底固定畫一列 「未裝強襲者背包 → 沒有備用武器槽」＋一句「手部取主手／備用較重者」。 181 個背包只有 1 個解得開它 ⇒ 那兩段幾乎每張圖都在解釋一個這套配裝裡不存在的東西。 真的解鎖時兩段照印（那時圖上有兩排武器，而總重只算較重的一排）。

🧠

算力面板與「目前生效」

左欄機師卡下方（非三欄版則掛在槽位圖下方）。Lv 條與 γ 上限 （ND_RULES.gammaPairCap = 23）全部問 src/utils/ndOverrides.ts， 與 PLAN-034 的 BUFF 階覆寫層共用同一份門檻。
「目前生效」逐級全列（每一級各給一個獨立能力，只印最高的等於少講 N−1 件事）， 帶縮圖與 hover 說明，並可展開／收合 —— 互動與機師詳情頁一致。 「配裝概況」已下架：已用槽位在三個地方重複、平均射程沒有人會據以決策。

⚡

兩層拒絕呈現

situational（改別的就能解：OVERWEIGHT／BACK_SLOT_TAKEN）→ 灰掉 ＋ 原因 ＋ 解法按鈕 （「卸下 左肩 熔火 可裝」）。
structural（改別的也解不掉：MECH_RESTRICTION／FORM_WEAPON_TYPE／BACKPACK_ARMOR_TYPE／LICENSE） → 摺疊 ＋ 計數 ＋ [顯示並說明原因]。
omitted（SLOT_MISMATCH／NO_SLOT／FIXED_ARMAMENT）不列入清單； blocked（FORM_LOCKED／SLOT_OCCUPIED／數值未建檔）整個挑選器降級並說明。

🧹

兩顆清空鍵

清空裝備＝目前分頁的武器與背包（連同掛在武器上的元件）； 全部清空＝連機師與機甲一起丟掉，回到初始草稿。 拆開的理由（使用者回饋 2026-08-30）：同一列另外三顆都是「把整份配裝交出去」， 於是一顆孤零零的「清空」讀起來像「全部重來」——想換機師從頭配的人按下去， 機師與機甲卻還在原位。
⚠ 清空裝備只動當前分頁：海莉絲三個形態各有一套，站在「突擊」按下去 不該把「先鋒」那一套也帶走（那一頁要切過去才看得見，是靜默損失）。
⚠ 兩顆都跳 toast 並附 [復原]（commitClear()）： commit() 只在「有東西被級聯移除」時才給提示與復原，而清空是玩家自己按的整批刪除， 一件 RemovedItem 都不會產生 ⇒ 拆成兩顆之前，「清空」是靜默且不可復原的。 兩顆相鄰、標籤只差兩個字，按錯的代價是整套配裝。
⚠ 不做二次確認：本頁的安全網一向是事後的 [復原]， 「確定嗎？」只會讓常按的那顆每次都多按一下。顏色改為灰／紅框以區分。

🔗

級聯：降級不清空

全部集中在單一 reconcile()，不散在各 handler。換機師／機甲／背包造成的移除會跳 toast 列出被移除項並附 [復原]（只留最近 1 筆），對應的格閃橙。 超重不自動卸、不阻擋存檔——需要時由玩家主動按 [自動卸至符合]。

🚫

這一版明確不渲染

武器改裝（全庫 0/180 筆資料）、可達增益數值加總（effects 0 筆）、戰術評分（零公式依據）、 單輪理論輸出（attack 語意未定）、科研步驟（89/89 機師失效）。 不渲染，不是渲染空的。其中戰術評分永久不做，版面上連告示都不留（2026-08-25 移除）。

後續階段的可見佔位（已全數兌現）

本卡記的是 052-B 當時留下的三個佔位：武器列的「⚙ 0/componentLimit」、 海莉絲頁頂那條「形態分頁開發中」橫幅、機甲卡的唯讀四部位表 ＋「部件混搭與模組配置開發中」。
三個都已由後續子計畫接手完成：元件（052-D）、形態分頁（052-F）、 模組槽與部件混搭（052-G）。留著這張卡是為了記住那個做法本身—— 可見佔位要寫得出「之後會有什麼」，而不是渲染一個點不下去的空格。

數值口徑
只出算得準的欄位
總重機體 ＋ max(主手組, 備用組) ＋ 肩 ＋ 背（totalWeight()）。不是加總——寫成加總先鋒形態會誤差 44%。固定武裝計入。
可用出力軀幹出力 ＋ 背包加成 ＋ Σ 模組（effectiveOutput()）。15 筆「已知會給出力但數值未建檔」的背包標為未知，不猜。
機甲火力Σ 四部位（chassisFirepower()）。全站禁止讀 mech.firepower。
命中／射程DB 原值，與官方 1:1 相符。
攻擊力顯示 DB 原值並標「合計攻擊（本站口徑，含連擊）」。不做 ÷hitCount 的官方同格式渲染——官方值比 DB 高 17.3–18.6% 且逐把不同，屬傷害計算範疇（總綱決策一④）。
等級一律滿級／滿品質階；不提供武器等級與機甲品質階選擇（總綱決策十）。
