📊 使用統計儀表板的三個非顯而易見之處（PLAN-046）
· 資料來源不是 client 寫的：analyticsDaily / analyticsEntity 是全站唯一 write: if false 的集合，唯一寫入者是 Cloudflare Worker（訪客也要統計 ⇒ 不能要求登入 ⇒ client 直寫就得開匿名寫入，等於把共用寫入額度交給任何人）。
· 維護者自己看不到自己的足跡：具後台權限的角色一律不計入統計。 以本站流量規模，維護者巡站就足以構成一成以上的方向性噪音。要自測請用無痕視窗。
· truncatedAt 必須檢查：有值代表當日因寫入預算熔斷而中止記錄。 本頁會把該日排除在所有數字與排行之外、趨勢圖標紅圈——熔斷後的曲線看起來完全正常， 不標就是拿少了半天的數字在做決策。
🔗 數值引用層編輯（PLAN-019 / 022 / 024） weapons / modules / buffs / glossary / skills / neuralDrive 等分頁的描述欄位下方掛 RefPicker，可標註 [xxx] 實體引用與 <refId.attr> 數值語法糖（編輯期 $n / %n 即時編譯、永不落地）；effects 共用技能效果編輯器。

常數 / 元件值用途與注意
ADMIN_WIDE_MAX_W max-w-[min(90vw,1920px)] 編輯彈窗與 AdminPage 列表容器共用，避免兩者寬度各自漂移。 1920px 上限僅防超寬螢幕（3440px+），2133px 以下視窗不會觸發。 ⚠ 不可改用 w-[90vw]——殼層已有 w-full，兩者都在設 width， 勝負取決於 Tailwind 產生的 CSS 順序而非 class 順序。
GRID_AUTO_FIELDS grid-cols-[repeat(auto-fill,minmax(220px,1fr))] 同質短欄位群（數值、短下拉）專用。⚠ 是 auto-fill 不是 auto-fit： 後者會收合空軌道、讓現有欄位吃掉整列，正是要消滅的「胖輸入框」。 量的是元素自身寬度，窄版彈窗與巢狀卡片自動得到正確欄數。 調密度只改 220px 這一個數字，全站生效。 ⚠ 異質長欄位（名稱、圖片路徑、textarea）不要套用。
GRID_TWO_PANE grid-cols-1 2xl:grid-cols-2 長分頁內部的雙欄：左＝吃寬度的文本區，右＝天生窄的結構化資料。 ⚠ 不可改用 GRID_AUTO_FIELDS——左右欄語意不對等、順序不可互換。 用 viewport 斷點在此是準確的：彈窗寬度 min(90vw,1920px) 本來就直接綁 viewport。
AdminEditTabs pill 樣式 ＋ 數字 badge 編輯彈窗內的分頁列，四個大編輯器共用（原本各寫一份、樣式還不一致）。 badge 傳數字，>0 才顯示。
⚠ 全域紅線：編輯彈窗內不可使用 Tailwind 容器查詢工具類
容器查詢會套用 container-type:inline-size，而該值隱含 contain:layout—— layout containment 會讓該元素成為 position:fixed 子孫的 containing block。 任何 position:fixed 的浮層只要沒走 portal，一旦祖先套上就會改對齊彈窗的框而非視窗、直接錯位。 （IconPicker／GameIconPicker 的選圖浮層現已用 createPortal 掛到 body，不再受影響； 紅線仍維持，免得日後新加的浮層踩到。）內部格線用上表的 GRID_AUTO_FIELDS / GRID_TWO_PANE 達成同樣目的即可。

註：產出的 CSS 裡可能仍看得到該 utility 的定義，那是 Tailwind 掃描器不解析語法、只抓字串所致（連 docs/ 討論它時的字面量都會被掃到，因為 copy-docs 會把 docs 複製進 public/）。判斷有沒有踩雷要看「元素上有沒有這個 class」，不是看 CSS 裡有沒有這條規則。

WeaponAdmin4：基本資訊 / 戰鬥屬性・射程・插槽 / 改裝方案 / 武器技能 改裝方案頁的固定／浮動改裝為雙欄。基本資訊頁有 isFixedArmament 勾選（2026-10-10 補上；選「固定武裝」種類會自動勾）， 勾了之後顯示唯讀的宿主區塊（焊在哪台機甲／哪個形態、哪幾格；沒連結時提醒到「機甲管理 → 部件」或「機師形態」設定）。 連結本身只在宿主那側編輯，武器端不寫——固定武裝與宿主一對一，由 validate-mech-slots.mjs ⑦ 把關。
基本資訊頁底部是 WeaponUpgradeField（PLAN-031 的 upgrade，2026-10-11 補上入口）：只存前置、只有專屬武器顯示挑選器（非專屬已存的前置只標警告）、候選只列同種類（遊戲沒有跨種類製作）、「可進階為」唯讀反查；特種背包製作只對背後武器顯示，存檔前 normalizeWeaponUpgrade 統一整理
MechAdmin4：基本數值 / 部件 / 模組（能力）/ 武器槽・外觀「外觀」分頁有 PLAN-054 的遊戲 ID 欄位（MechGameArtFields：gameId／塗裝本體 skinOfId）；官配為唯讀，由機師側推導。部件分頁可編固定武裝（fixedArmament，ArmamentMountEditor）
ModuleAdmin5：基本資訊 / 基本屬性 / 武器增傷 / 等級資料 / 條件效果 四個是大分頁、無可併對象；基本資訊頁為雙欄
GlossaryAdmin · NeuralDriveAdmin · SkillAdmin（武器編輯器也會疊開它的 SkillEditPanel） 無分頁 顯式傳 maxWidth="max-w-2xl" 維持 672px 窄版——欄位數少，撐寬只會讓兩三個欄位漂在空白裡
UserAdmin · GrayOpsAdmin— inline 版面，不走 AdminModal
合併分頁的判準
彈窗內容區在 1080p 下約 760px ≈ 10～11 排欄位。只合併「各只剩 1～3 排」的小分頁， 以 section 標題 ＋ border-t 分隔。 重元件必須維持獨立分頁（PilotSkillRefsTab、 PilotNeuralDriveTab、Module 等級表）——合併會讓它們變成常駐掛載，失去 lazy mount。
