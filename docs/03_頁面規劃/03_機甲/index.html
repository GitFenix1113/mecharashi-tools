座艙式排版（3×3 格）+ 左右分欄
📐 機甲詳情版面設計 設計前提（2026-10-11「一屏看完」改版）：使用者進頁不必上下捲，一眼看完機甲與模組的大部分重點； 模組多的機甲必然要往下，但以此為目標壓縮所有不攜帶資訊的高度。實測 1920×960、「中」字級： 全站專屬模組最多的復仇女神，右欄結束於 958px（改版前 1251px）。

頁首（桌面一行，約 64px；改版前「返回連結＋名稱＋數值」三行共 169px）： ← 返回箭頭＋名稱＋裝甲類型＋登場版本＋官配／付費塗裝本體，五項重點屬性（火力／閃避／移動力／重量／出力・剩餘）靠右同一行。 手機：「← 名稱 裝甲」與「登場／官配」固定兩列，右側放立繪縮圖（取代原本 190px 的大立繪）， 五項數值一列五格（出力格放寬，容納「剩餘」）。

主體在 xl（≥1280px）以上左右分欄，比例 46 : 54：
· 左欄＝部件資訊（3×3 座艙式十字，中央機甲立繪，上軀幹／左右臂／下腿部； 上排兩個角落是肩部固定武裝，見下）＋ 機體描述
· 右欄＝機甲模組，依重要性排序：特性模組、8級模組各佔整寬（描述最長，8級中位數 53 字、最長 128 字； 半寬會擠成 4 行且兩卡高低不齊）→ 專屬模組（只有 10 台有，1 顆整寬、2／4 顆兩欄；沒有就整組不出） → 副模組單行（每台剛好 1 顆、描述約 8 字；不放滑桿與數值標籤，各等級由「全部」查看）
· 模組卡標題列：卡寬 ≥ 440px 時「名稱｜等級滑桿｜全部」同一行；較窄時「全部」留在名稱列、等級選擇獨佔第二行 （手機分段按鈕平均撐滿，8 級不再折成兩行）。專屬模組的綁定部位併進標題列（「綁定 軀幹」）。
lg～xl 單欄堆疊「部件 → 機體描述 → 模組」（機體描述在左欄內）；手機／平板（lg 以下）改為「模組 → 部件」： 改版前手機要捲過立繪、部件與約 500px 的機體描述，特性模組才出現在第 1499px，改版後在第 327px。 手機的機體描述預設收成 3 行，可展開（桌面不收：它在左欄最底下，不擋任何東西）。
🔒 肩部固定武裝卡（2026-10-10） 部件十字上排的兩個空角落放肩部固定武裝：左上＝右肩、右上＝左肩（從正面看機體， 每邊肩膀正好在同側手臂上方），與遊戲整備畫面、配裝模擬器的左右一致。手機版沒有角落可放， 改在部件 2×2 的上方加一條「右肩｜左肩」橫列（手機的立繪已移到頁首縮圖）。
· 只在肩部真的被固定武裝佔住時才出現（今天只有帕斯卡／破曉者-01／霸王）； 其餘機甲兩個角落維持空白，外觀與改版前相同。資料來源是 occupiedSlots(mech.parts)。
· 卡片內容：左右肩各自的鏡像圖（sideGameIds，沒有官方圖時退回鎖頭）、「右肩 固定武裝」、 武器名（連到武器頁）、技能（有才列；沒有不寫「無技能」，理由同下方舊規格的「不寫無固定武裝」）。 刻意不放重量／攻擊——三把肩部固定武裝全是 0。
· 今天沒有機甲把固定武裝焊在手部或背部，十字下排的兩個角落先空著。
· 資料成本：weapons 與技能庫的載入隔離在卡片元件裡，只在有固定武裝時 mount。
⏸ 槽位配置與四部位表（PLAN-052-A E-1）— 2026-10-10 起收起 站長決定先收起，以後看情況再決定要不要用。元件（MechSlotPanel.tsx）保留，恢復方式見 MechDetailPage.tsx 的 ⏸ 註解。收起的理由：
· 四部位表的重量／火力／接口，部件十字與頁首都已經有了；「來源」欄只在配裝模擬器 混搭部件時才有意義（MechPartsTable 在模擬器仍在用）。
· 槽位配置裡唯一不重複的資訊是「哪幾格被固定武裝佔住」，已搬進上方的肩部卡。
· 原本表格底部那行「本站數值一律以滿級／滿品質階計算；火力不含科技加成」移到部件十字下方。

以下為收起前的原規格，留作恢復時的參考：
槽位配置依類型分列（手部 ×2 ／ 肩部 ×2 ／ 背部 ×1），格數由 mechSlotCapacity() derive； 肩部只有中甲有、背槽全機種都有；被固定武裝佔住的格子標 🔒 並連到該武器； 沒有固定武裝時不渲染任何「無固定武裝」字樣（分不出「真的沒有」與「還沒建檔」）。 四部位表列來源／重量／火力／接口型別，接口空白顯示「無模組接口」而非留白。
🎚️ 部件屬性密度切換（精簡 / 詳細） 部件資訊區塊右側的分段按鈕，控制部件卡要顯示全部數值還是各部位的 3 個重點值 （軀幹＝耐久/火力/出力、手臂＝耐久/火力/命中、腿部＝耐久/閃避/移動力）。
· 預設「詳細」——圖鑑頁預設不藏資料，版面壓力由左右分欄與較小字級吸收。
· 偏好記在 localStorage mecharashi_mechdetail_partsExpanded（'1'／'0'）， 屬純本機 UI 偏好，不同步到帳戶（比照版本情報甘特圖的資訊列摺疊）。
為什麼要左右分欄
單欄時「屬性卡 → 部件十字 → 模組」三段串在同一條垂直軸上，模組永遠在摺線以下。 部件十字是寬而扁（3 欄 × 3 列，高度有上限），模組是窄而長（張數無上限）， 兩者的長寬比需求正交，拆成左右兩欄後模組不必等部件捲完才出現。
模組欄的雙欄門檻用 容器查詢 @[640px] 而非視窗斷點—— 要不要雙欄取決於該欄自己的寬度。
