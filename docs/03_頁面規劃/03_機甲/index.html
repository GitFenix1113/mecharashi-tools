座艙式排版（3×3 格）+ 左右分欄
📐 機甲詳情版面設計 頁首橫帶：機甲名稱 + 裝甲類型 + 登場版本，下接一列重點屬性（火力／閃避／移動力／重量／出力・剩餘）。
主體在 xl（≥1280px）以上左右分欄，比例 46 : 54：
· 左欄＝部件資訊（3×3 座艙式十字，中央機甲立繪，上軀幹／左右臂／下腿部） ＋ 槽位配置 ＋ 四部位表 ＋ 機體描述
· 右欄＝機甲模組（特性模組 / 8級模組 / 副模組 / 專屬模組）
xl 以下維持單欄堆疊；手機為「立繪 + 2×2 部件卡」。
🔩 槽位配置與四部位表（PLAN-052-A E-1） 接在部件十字之後——十字講的是「每個部位有多強」，這兩塊講的是「這台能裝什麼、數字從哪來」。

槽位配置：依類型分列（手部 ×2 ／ 肩部 ×2 ／ 背部 ×1），格數由 mechSlotCapacity() derive。肩部只有中甲有，其餘機種該列整列不渲染、 另附一行說明；背槽全機種都有（它同時是背包的位置，給 0 會讓 35 個「僅輕型可裝」的背包無處可裝）。 被固定武裝佔住的格子標 🔒 並連到該武器。
· ⚠ 沒有固定武裝時，不渲染任何「無固定武裝」字樣。我們分不出「這台真的沒有」與 「還沒有人建檔」，兩者共用同一種呈現（不說），而不是把一個我們並不知道的否定陳述寫死在頁面上。
· 分列而非單一 grid 流式排版：3 欄 grid 會把「左肩／右肩」拆到兩列，讀起來像兩個不相干的格子。

四部位表：來源／重量／火力／接口型別，唯讀（混搭 UI 屬 052-G）。
· 「來源」欄今天恆等於本機甲，看似多餘——但混搭部位之後四個部位可來自四台不同機甲， 這一欄就是那時唯一能回答「這是哪來的」的地方。先把欄位擺好，混搭上線時不必改表格結構。
· 接口空白顯示「接口資料未建檔」而非留白（留白會被讀成「這格沒有接口」）。
· 底部固定一行「本站數值一律以滿級／滿品質階計算；火力不含科技加成」。

資料成本：只有 3/90 台機甲有固定武裝，故「查武器名稱」隔離在子元件裡， 只在真的有固定武裝時才 mount——其餘 87 台的詳情頁完全不碰 weapons 集合。
🎚️ 部件屬性密度切換（精簡 / 詳細） 部件資訊區塊右側的分段按鈕，控制部件卡要顯示全部數值還是各部位的 3 個重點值 （軀幹＝耐久/火力/出力、手臂＝耐久/火力/命中、腿部＝耐久/閃避/移動力）。
· 預設「詳細」——圖鑑頁預設不藏資料，版面壓力由左右分欄與較小字級吸收。
· 偏好記在 localStorage mecharashi_mechdetail_partsExpanded（'1'／'0'）， 屬純本機 UI 偏好，不同步到帳戶（比照版本情報甘特圖的資訊列摺疊）。
為什麼要左右分欄
單欄時「屬性卡 → 部件十字 → 模組」三段串在同一條垂直軸上，模組永遠在摺線以下。 部件十字是寬而扁（3 欄 × 3 列，高度有上限），模組是窄而長（張數無上限）， 兩者的長寬比需求正交，拆成左右兩欄後模組不必等部件捲完才出現。
模組欄的雙欄門檻用 容器查詢 @[640px] 而非視窗斷點—— 要不要雙欄取決於該欄自己的寬度。
