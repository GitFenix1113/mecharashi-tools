# 台版公告語料快照（2026-08-16）

PLAN-048 開發台版公告解析器時，從官方公告站抓下來的 **266 篇公告純文字**，
外加一份 `index.json`（每篇的 id / url / type / title / 發佈月份）。

---

## ⚠ 先讀這段：這是「當時」的資料，不是標準答案

這份東西是**開發與測試過程的產物**，留下來只為了「改解析規則時能離線回歸」。
它會隨時間失去代表性，理由是可預期的：

- **官方句型逐年漂移。** 開發期間實測到三次改寫，這是這個系統唯一保證會反覆
  發生的維護事件。快照裡的句型只代表 2024–2026 這段。
- **快照當下的解析器是 `PARSER_VERSION 3`。** 之後規則只會再改，用舊快照跑出
  「和當年不同的結果」很可能是**進步**而不是回歸 —— 判讀時要自己想清楚是哪一種。
- **公告站本身可能消失。** 它寄生在前代理商網域上，`index.json` 裡的 url
  遲早會變死連結。屆時這份文字就是唯一還在的原文，但也僅止於這 266 篇。

換句話說：拿它當「改動有沒有波及既有案例」的參考很好用；拿它當「解析器正確性的
驗收標準」則會誤導。

---

## 內容

```
index.json           266 筆清單（抓取當下的官方列表）
text/<type>/<id>.txt 每篇公告的純文字（HTML 抽取後）
```

`<type>` 是官方的頻道分類：`maAffiche`（公告）/ `maNews`（新聞）/
`maGuide`（攻略）/ `maOther`（其他）。

**完整 HTML 原始檔（`raw/`，5 MB）不在這裡**，留在本機
`_local-notes/2026-08/tw-announcements-archive/raw/`。它只在「連 HTML 抽取邏輯
（`extractText` 的選擇器）都要重驗」時才用得到，那是罕見情境，不值得讓公開
repo 多背 5 MB。

---

## 怎麼用

**離線跑整條管線**（不連外網、不寫 Firestore）——
腳本讀的是 `_local-notes` 那份，所以這招需要本機還留著原歸檔：

```bash
node scripts/scrape-tw-announcements.mjs --from-archive --dry-run
```

**只驗解析器**（用這裡的語料，隨時可跑）：直接讀 `index.json` 逐篇餵進
`parseAnnouncement()`。改規則前後各跑一次、比對輸出差異，就能看出這次改動
波及了哪些篇 —— 戰令（「環島密令」）那次修正就是這樣確認的：266 篇裡 17 篇
改變、249 篇完全相同，且 17 篇全是同一個修正，於是可以判定零副作用。

單元測試在 [`../../lib/parseAnnouncement.test.mjs`](../../lib/parseAnnouncement.test.mjs)，
每組「回歸」測試都對應一個在這份語料上實際踩到的錯。
