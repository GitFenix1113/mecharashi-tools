◆ PLAN-020

文件 ID 自動生成與撞名防呆 · Auto Slug ID · 維護者只輸名稱

後台建立實體時，由系統依命名規則自動產生文件 ID（buff_[名稱]），維護者只輸入名稱並選分類；建立當下做撞名 / 撞 ID 防呆。舊資料不動，從源頭杜絕命名歧異。

Problem
問題背景
文件 ID 由維護者手打，無強制規則 → 命名風格分裂
現行「新增 BUFF」對話框（NewItemDialog）要維護者親手輸入整串文件 ID（placeholder buff_虛粒子形態）。沒有跟維護人員約定 naming style 的情況下，同一個 buffs 集合同時出現 BUFF_虎王的底力、buff_凝勢III、凝勢（無前綴）三種風格。
ID 決定點早於名稱，順序違反直覺
現流程是「先打 ID → 才進編輯面板填 name」，與「先想名稱、ID 自然衍生」的直覺相反，也讓 ID 與 name 容易對不上。
既有防呆只擋同 ID，不擋同名
docExists('buffs', id) 只能擋「同一個 ID」，無法防止「同名但 ID 不同」的孿生 BUFF；多人維護時可能各自建出 buff_星爆 與 星爆 兩筆同名資料。
影響評估：純維護端問題，前台不受影響。
文件 ID 不對使用者顯示（前台看 name）；引用以「實際 ID 精準比對」解析（buffs.find(x => x.id === ref.refId)），沒有任何程式碼解析 ID 前綴判斷型別（型別存在 buffType / refType 欄位）。因此現有歧異不影響功能，舊資料維持原狀即可；本計畫只修「建立流程」，避免未來繼續長歪。
Design
設計決策
決策一：ID 由系統生成，維護者只輸名稱
命名規則 buff_<slug(name)>。新增純函式 makeEntityId(prefix, name)（src/utils/idSlug.ts），sanitize 規則對齊 scrape-pilots-v3.js 的 safeName：保留中英數，去除空白 / 標點 / 斜線等 Firestore 不合法字元。對話框輸入名稱時即時預覽生成的 ID（唯讀）。
// src/utils/idSlug.ts export function makeEntityId(prefix: string, name: string): string { const slug = name.trim().replace(/[^一-龥a-zA-Z0-9　-〿＀-￯]/g, '') return `${prefix}_${slug}` // 例：makeEntityId('buff', '虛粒子形態') → 'buff_虛粒子形態' }
決策二：前綴統一 buff_，分類用既有 buffType 欄位、不進 ID
維護者在對話框先選大分類（沿用 BUFF_TYPE_OPTIONS：數值增益 / 資源 / 狀態 / 減益 / 控制），但該分類只寫入 buffType 欄位，不影響 ID 前綴。理由：無程式碼解析前綴、buffs 同屬一集合，避免 buff_星爆 與 state_星爆 並存造成歧義。
替代方案（保留為未來選項）：若日後確有「同名跨分類需並存」的需求，可改為 <category>_<name> 前綴方案。目前無此需求，採統一前綴最簡單。
決策三：撞名 = 撞 ID → 一律「擋下並提示既有同名項」，不自動加序號
策展型資料中「同名」幾乎等同「重複建立」，應導引維護者去編輯既有項，而非生出孿生資料。沿用 docExists('buffs', id) 伺服器檢查（涵蓋不在當前頁的 BUFF）＋ 頁內 in-memory 檢查；命中時顯示「已有同名 BUFF，請改名或編輯既有項目」。不採自動 _2 後綴（會悄悄製造近似重複）。
決策四：ID 出生即凍結
建立後若改 name，只改欄位、不動 ID（編輯面板的 form.id 已是唯讀顯示）。代價：時間久了 ID 的名稱部分可能與現名不符——可接受，因 ref 以 ID 比對、不受 name 變動影響。此決策不需改碼，僅明文記錄。
決策五：以「可選模式」擴充共用元件，不驚動其他 admin
useNewItemCreation / NewItemDialog 為 pilots / weapons / modules / components / backpacks 共用。新增一個「輸入名稱、唯讀預覽 ID」的可選模式（透過 deriveId? 參數），未傳則維持現行手打 ID 行為。buffs 先接入，其他集合日後逐一 opt-in。
Scope
實作範圍與不在範圍內
檔案變更風險
src/utils/idSlug.ts（新增） makeEntityId(prefix, name) 純函式 + 單元測試 低
src/pages/user/admin/shared.tsx useNewItemCreation / NewItemDialog 新增 deriveId 名稱輸入模式（向後相容） 中

在範圍內：
  • makeEntityId slug 工具與單元測試（含中英數保留 / 特殊字元清理 / 空 slug 邊界）
  • 共用 useNewItemCreation / NewItemDialog 的「輸入名稱、唯讀預覽生成 ID」可選模式
  • BuffAdmin 接新模式：輸入名稱、選分類 → 生成 buff_<name>；撞名 / 撞 ID 擋下並提示既有項
  • makeDefaultBuff 帶入名稱，建立後編輯面板 name 已填好
不在範圍內：
  • 既有 BUFF 改名 / 跨集合 ref migration（明確不做，舊資料維持原狀）
  • 其他集合（pilots / weapons / modules…）的 ID 方案調整（日後可逐一 opt-in）
  • 前綴依分類變動（保留為未來選項，見決策二替代方案）
