◆ PLAN-035

背包分類階層 · 合成階層(素材/基礎/複合/特種) · 強化/干擾軸 · 素材隱藏

依遊戲背包合成階層把 180 件背包分成素材/基礎/複合/特種四層——預設隱藏 A/B 素材、補上「強化 vs 干擾」第二軸篩選。階層與軸都能從既有 rarity＋名字 derive，先驗證够用再決定是否結構化。

立案背景（2026-07-24，站長於背包製作頁提出）：站長指出遊戲背包的合成有清楚脈絡—— 基礎(S) → 複合(S+) → 特種(SS) 三階進階，A/B 級是低階製作素材；並希望背包圖鑑能反映這個階層、 預設隱藏沒人用的 A/B，並補上「強化包 vs 干擾包」這條篩選軸。 本計畫的資料判斷全部來自 2026-07-24 對 live Firestore 的實測盤點（收錄於下方各決策）。
Problem
問題背景
問題一：A/B 素材背包稀釋了圖鑑
遊戲中 A、B 級背包基本是製作高階背包的素材，幾乎沒人實戰使用；但目前背包圖鑑 一次全載 180 件、A/B 共 37 件與實用的 SS/S+/S 混在同一列表，增加查詢負擔與資訊干擾。
問題二：看不出合成階層，也無法按「強化/干擾」軸篩選
現有篩選只有「稀有度」「類型（基礎功能）」「裝備」三種。玩家看不出一個背包在合成樹的哪一階， 也無法把「強化包」與「干擾包」分開篩——而這正是 S+ 複合背包最主要的分類方式 （出力強化背包 vs 出力干擾背包）。
【實測】遊戲的背包合成階層（2026-07-24 live 盤點）：
// 製作台（遊戲內「背包製作」分頁） 基礎背包製作 → S 基礎功能背包 + 隨機S級強化/干擾背包 定向背包製作·強化 → S 強化背包·[變體] （首攻/追擊/警戒/反擊/彈道/協力/援護/再攻擊） 定向背包製作·干擾 → S 干擾背包·[變體] （攻擊/命中/迴避/暴擊/暴傷/護甲/增傷） 複合背包製作 → S+ 複合背包 = [基礎功能] + [強化|干擾] + [變體] 特種背包製作 → SS 特種背包 + 複合武器（裁決者等，見 PLAN-031）
Design
設計決策
決策一：合成階層完全由 rarity derive，零資料改動
實測 rarity 與合成階層一對一完美對應，不需新增任何欄位：
階層rarity數量內容
素材A + B37低階版本（同名背包在 B/A/S 都有，是升階材料）
基礎背包S23出力/移動/誘導/飛行… 基礎功能 + 強化背包·X + 干擾背包·X
複合背包S+98出力強化背包·首攻、移動干擾背包·攻擊…
特種背包SS22強襲者/征服者… + 複合武器投影（PLAN-031 已做）
合計 180。tier = tierFromRarity(rarity) 是純函式，不碰 Firestore。
決策二：A/B 命名用「素材」而非「耗材」
遊戲沒有明確區分，但語意上它們不是用掉就沒的消耗品，而是製作高階背包的材料 （強化背包·首攻 在 B→A→S 都有，是 出力強化背包·首攻(S+) 的升階前身）。 故四層命名定為：素材(A/B) · 基礎(S) · 複合(S+) · 特種(SS)。
決策三：預設隱藏 A/B 素材（背包頁預設篩選 SS/S+/S）
落地 /backpacks 時預設只顯示 SS/S+/S（167 件），A/B 素材需手動打開「素材」層才顯示。 減少查詢與資訊干擾；既有稀有度多選篩選仍可自由調整。
決策四：「強化/干擾」是第二條軸，現有 type 欄位沒有編碼它
關鍵陷阱【實測】type 欄位只編碼基礎功能軸 （PowerAdd/MovePointAdd/Interference/…），「強化 vs 干擾」只存在於名字字串：
出力強化背包·首攻 → type=PowerAdd（出力） 出力干擾背包·攻擊 → type=PowerAdd（出力） ← 同 type！強化/干擾差異只在名字 移動強化背包·追擊 → type=MovePointAdd（移動）
S+ 複合背包名字結構高度規律：[基礎功能][強化|干擾]背包·[變體]， 可乾淨拆出三軸。決策：先用 name 解析 derive，不加結構化欄位—— 驗證够用後若要做決策六的合成鏈才需要結構化。
決策五（邊界）：不是所有背包都落在「強化/干擾」軸上，篩選須優雅降級
純功能基礎背包（出力背包、移動背包）與 SS 特種背包（強襲者背包） 名字不含強化/干擾。強化/干擾子篩選只作用於含該軸的條目，其餘不因此被錯誤排除 （比照 PLAN-031 armor 篩選對投影武器的處理）。另注意 S/A/B 的 干擾背包·X(type=EMP)、強化背包·X(type=Enhance) 是基礎階的強化/干擾線。
決策六（延伸，本計畫先不做）：背包合成關係鏈
出力強化背包·首攻 = 出力背包 + 強化背包·首攻； SS 特種背包 = 特定 S+ 再進階。這根本是 PLAN-031 武器 upgrade 進階鏈的背包版， 可複用同套 { fromId, ... } 模型。但它需要結構化欄位與推導腳本，先列為可選延伸， 待決策四的 name-derive 上線、確認需求後再評估是否納入。
Scope
實作範圍與不在範圍內
在範圍內：
  • src/utils/backpackClassify.ts（新）：tierFromRarity、名字解析出 { baseFunction, line: '強化'|'干擾'|null, variant }、對應中文標籤

  • docs 資料模型同步（backpacks.html 補階層與軸的 derive 說明）+ siteChangelog

  • 背包合成關係鏈（決策六）——另評估；若做，複用 PLAN-031 upgrade 模型

  • 刪除 A/B 素材資料（只是預設隱藏，資料保留）
